4.8. 오류 로그 관리

오류 로그 관리 메커니즘은 문제의 원인을 설명하는 평이한 영어 형식으로 CUDA API 오류를 개발자에게 보고할 수 있게 해줍니다.

4.8.1. 배경#

전통적으로, 실패한 CUDA API 호출을 알리는 유일한 단서는 0이 아닌 코드가 반환되는 것입니다. CUDA Toolkit 12.9 기준으로 CUDA 런타임은 오류 조건에 대해 100개가 넘는 서로 다른 반환 코드를 정의하지만, 그중 많은 것들은 일반적(generic)이며 개발자에게 원인 디버깅에 대한 도움을 제공하지 않습니다.

4.8.2. 활성화#

CUDA_LOG_FILE 환경 변수를 설정하십시오. 허용되는 값은 stdout, stderr, 또는 파일을 쓰기 위한 시스템의 유효한 경로입니다. 로그 버퍼는 프로그램 실행 전에 CUDA_LOG_FILE이 설정되지 않았더라도 API를 통해 덤프할 수 있습니다. 참고: 오류 없이 실행되면 로그가 전혀 출력되지 않을 수 있습니다.

4.8.3. 출력#

로그는 다음 형식으로 출력됩니다:

[Time][TID][Source][Severity][API Entry Point] Message

다음 줄은 개발자가 할당되지 않은 버퍼에 오류 로그 관리 로그를 덤프하려고 할 때 생성되는 실제 오류 메시지입니다:

[22:21:32.099][25642][CUDA][E][cuLogsDumpToMemory] buffer cannot be NULL

이전에는, 개발자가 받는 것은 반환 코드의 CUDA_ERROR_INVALID_VALUE와, cuGetErrorString이 호출된 경우의 “invalid argument” 정도가 전부였습니다.

4.8.4. API 설명#

CUDA Driver는 오류 로그 관리 기능과 상호작용하기 위한 API를 두 가지 범주로 제공합니다.

이 기능은 오류 로그가 생성될 때마다 사용될 콜백 함수를 개발자가 등록할 수 있게 하며, 콜백 시그니처는 다음과 같습니다:

void callbackFunc(void *data, CUlogLevel logLevel, char *message, size_t length)

콜백은 다음 API로 등록됩니다:

CUresult cuLogsRegisterCallback(CUlogsCallback callbackFunc, void *userData, CUlogsCallbackHandle *callback_out)

여기서 userData는 수정 없이 콜백 함수로 전달됩니다. callback_out은 호출자가 cuLogsUnregisterCallback에서 사용하기 위해 저장해야 합니다.

CUresult cuLogsUnregisterCallback(CUlogsCallbackHandle callback)

다른 API 함수 집합은 로그의 출력을 관리하기 위한 것입니다. 중요한 개념은 로그 이터레이터(iterator)로, 버퍼의 현재 끝을 가리킵니다:

CUresult cuLogsCurrent(CUlogIterator *iterator_out, unsigned int flags)

전체 로그 버퍼의 덤프를 원하지 않는 상황에서는 호출 소프트웨어가 이터레이터 위치를 유지할 수 있습니다. 현재 flags 매개변수는 0이어야 하며, 추가 옵션은 향후 CUDA 릴리스용으로 예약되어 있습니다.

언제든지, 오류 로그 버퍼는 다음 함수들로 파일 또는 메모리로 덤프할 수 있습니다:

CUresult cuLogsDumpToFile(CUlogIterator *iterator, const char *pathToFile, unsigned int flags)
CUresult cuLogsDumpToMemory(CUlogIterator *iterator, char *buffer, size_t *size, unsigned int flags)

iterator가 NULL이면 최대 100개 항목까지 전체 버퍼가 덤프됩니다. iterator가 NULL이 아니면 해당 항목부터 시작하여 로그가 덤프되며, iterator의 값은 cuLogsCurrent가 호출된 것처럼 로그의 현재 끝으로 업데이트됩니다. 버퍼에 100개를 초과하는 로그 항목이 있었던 경우, 이를 알리는 메모가 덤프 시작 부분에 추가됩니다.

flags 매개변수는 0이어야 하며, 추가 옵션은 향후 CUDA 릴리스용으로 예약되어 있습니다.

cuLogsDumpToMemory 함수에는 추가 고려 사항이 있습니다:

  1. 버퍼 자체는 null 종료되지만, 각 개별 로그 항목은 개행(n) 문자로만 구분됩니다.

  2. 버퍼의 최대 크기는 25600바이트입니다.

  3. size에 제공된 값이 원하는 모든 로그를 저장하기에 충분하지 않으면, 첫 번째 항목으로 메모가 추가되며, 들어가지 못하는 가장 오래된 항목은 덤프되지 않습니다.

  4. 반환 후 size에는 제공된 버퍼에 실제로 기록된 바이트 수가 포함됩니다.

4.8.5. 제한 사항 및 알려진 문제#

  1. 로그 버퍼는 100개 항목으로 제한됩니다. 이 제한에 도달하면 가장 오래된 항목이 대체되며, 로그 덤프에는 롤오버를 알리는 줄이 포함됩니다.

  2. 아직 모든 CUDA API가 포함되어 있지는 않습니다. 이는 모든 API에 대해 더 나은 사용 오류 보고를 제공하기 위한 진행 중인 프로젝트입니다.

  3. 오류 로그 관리 로그 위치(제공된 경우)는 로그가 생성되기 전에는/생성되지 않는 한 유효성 테스트가 수행되지 않습니다.

  4. 오류 로그 관리 API는 현재 CUDA Driver를 통해서만 사용할 수 있습니다. 동등한 API는 향후 릴리스에서 CUDA 런타임에 추가될 예정입니다.

  5. 로그 메시지는 어떤 언어로도 현지화되어 있지 않으며, 제공되는 모든 로그는 미국식 영어(US English)로 되어 있습니다.
