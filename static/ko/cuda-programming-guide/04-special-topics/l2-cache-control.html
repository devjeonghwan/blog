4.13. L2 캐시 제어

CUDA 커널이 전역 메모리의 데이터 영역에 반복적으로 접근할 때, 이러한 데이터 접근은 지속적(persisting)이라고 간주할 수 있습니다. 반면 데이터가 한 번만 접근된다면, 이러한 데이터 접근은 스트리밍(streaming)이라고 간주할 수 있습니다.

컴퓨트 기능 8.0 이상의 디바이스는 L2 캐시에서 데이터의 지속성에 영향을 줄 수 있는 기능을 갖추고 있으며, 잠재적으로 전역 메모리에 대한 더 높은 대역폭과 더 낮은 지연 시간의 접근을 제공할 수 있습니다.

이 기능은 두 가지 주요 API를 통해 노출됩니다:

  • CUDA 런타임 API(CUDA 11.0부터)는 L2 캐시 지속성에 대한 프로그래밍 방식의 제어를 제공합니다.

  • 이 cuda::annotated_ptr API에서 libcu++ 라이브러리(CUDA 11.5부터)는 유사한 효과를 얻기 위해 CUDA 커널의 포인터에 메모리 접근 속성을 주석으로 표시합니다..

다음 섹션에서는 CUDA 런타임 API에 중점을 둡니다. 에 대한 자세한 정보는 cuda::annotated_ptr 접근 방식에 대해서는 다음을 참조하십시오 libcu++ 문서.

4.13.1. 지속적 접근을 위한 L2 캐시 예약#

L2 캐시의 일부를 전역 메모리에 대한 지속적 데이터 접근에 사용하도록 예약할 수 있습니다. 지속적 접근은 L2 캐시의 이 예약된 부분을 우선적으로 사용하며, 반면 전역 메모리에 대한 일반 또는 스트리밍 접근은 지속적 접근이 사용하지 않을 때에만 L2의 이 부분을 활용할 수 있습니다.

지속적 접근을 위한 L2 캐시 예약 크기는 제한 내에서 조정할 수 있습니다:

cudaGetDeviceProperties(&prop, device_id);
size_t size = min(int(prop.l2CacheSize * 0.75), prop.persistingL2CacheMaxSize);
cudaDeviceSetLimit(cudaLimitPersistingL2CacheSize, size); /* set-aside 3/4 of L2 cache for persisting accesses or the max allowed*/

GPU가 Multi-Instance GPU(MIG) 모드로 구성된 경우, L2 캐시 예약 기능이 비활성화됩니다.

Multi-Process Service(MPS)를 사용할 때는 L2 캐시 예약 크기를 cudaDeviceSetLimit로 변경할 수 없습니다. 대신 예약 크기는 환경 변수 CUDA_DEVICE_DEFAULT_PERSISTING_L2_CACHE_PERCENTAGE_LIMIT를 통해 MPS 서버 시작 시에만 지정할 수 있습니다.

4.13.2. 지속적 접근을 위한 L2 정책#

접근 정책 창(access policy window)은 전역 메모리의 연속적인 영역과, 해당 영역 내 접근에 대해 L2 캐시에서의 지속성 속성을 지정합니다.

아래 코드 예시는 CUDA Stream을 사용하여 L2 지속적 접근 창을 설정하는 방법을 보여줍니다.

CUDA Stream 예시

cudaStreamAttrValue stream_attribute;                                         // Stream level attributes data structure
stream_attribute.accessPolicyWindow.base_ptr  = reinterpret_cast<void*>(ptr); // Global Memory data pointer
stream_attribute.accessPolicyWindow.num_bytes = num_bytes;                    // Number of bytes for persistence access.
                                                                              // (Must be less than cudaDeviceProp::accessPolicyMaxWindowSize)
stream_attribute.accessPolicyWindow.hitRatio  = 0.6;                          // Hint for cache hit ratio
stream_attribute.accessPolicyWindow.hitProp   = cudaAccessPropertyPersisting; // Type of access property on cache hit
stream_attribute.accessPolicyWindow.missProp  = cudaAccessPropertyStreaming;  // Type of access property on cache miss.

//Set the attributes to a CUDA stream of type cudaStream_t
cudaStreamSetAttribute(stream, cudaStreamAttributeAccessPolicyWindow, &stream_attribute);

이후 커널이 CUDA stream에서 실행되면, 전역 메모리 범위 [ptr..ptr+num_bytes) 내의 메모리 접근은 다른 전역 메모리 위치에 대한 접근보다 L2 캐시에 지속될 가능성이 더 높습니다.

아래 예시에 보인 것처럼 CUDA Graph Kernel Node에 대해서도 L2 지속성을 설정할 수 있습니다:

CUDA GraphKernelNode 예시

cudaKernelNodeAttrValue node_attribute;                                     // Kernel level attributes data structure
node_attribute.accessPolicyWindow.base_ptr  = reinterpret_cast<void*>(ptr); // Global Memory data pointer
node_attribute.accessPolicyWindow.num_bytes = num_bytes;                    // Number of bytes for persistence access.
                                                                            // (Must be less than cudaDeviceProp::accessPolicyMaxWindowSize)
node_attribute.accessPolicyWindow.hitRatio  = 0.6;                          // Hint for cache hit ratio
node_attribute.accessPolicyWindow.hitProp   = cudaAccessPropertyPersisting; // Type of access property on cache hit
node_attribute.accessPolicyWindow.missProp  = cudaAccessPropertyStreaming;  // Type of access property on cache miss.

//Set the attributes to a CUDA Graph Kernel node of type cudaGraphNode_t
cudaGraphKernelNodeSetAttribute(node, cudaKernelNodeAttributeAccessPolicyWindow, &node_attribute);

hitRatio 매개변수는 hitProp 속성을 부여받는 접근의 비율을 지정하는 데 사용할 수 있습니다. 위의 두 예시 모두에서 전역 메모리 영역 [ptr..ptr+num_bytes) 내 메모리 접근의 60%는 지속적(persisting) 속성을 가지며, 메모리 접근의 40%는 스트리밍(streaming) 속성을 가집니다. 어떤 특정 메모리 접근이 지속적(즉, hitProp)으로 분류되는지는 약 hitRatio의 확률로 무작위이며, 확률 분포는 하드웨어 아키텍처와 메모리 범위에 따라 달라집니다.

예를 들어, L2 예약(set-aside) 캐시 크기가 16KB이고 num_bytes 에서 accessPolicyWindow 가 32KB인 경우:

  • a를 사용하여 hitRatio 0.5의 경우 하드웨어는 32KB 윈도우 중 16KB를 무작위로 선택하여 지속적(persisting)으로 지정하고, 예약된(set-aside) L2 캐시 영역에 캐시합니다.

  • With a hitRatio of 1.0이면 하드웨어는 예약된(set-aside) L2 캐시 영역에 전체 32KB 윈도우를 캐시하려고 시도합니다. 예약된 영역은 윈도우보다 작으므로, 캐시 라인은 축출되어 32KB 데이터 중 가장 최근에 사용된 16KB가 L2 캐시의 예약된 부분에 유지되도록 합니다.

따라서 hitRatio를 사용하면 캐시 라인의 스래싱(thrashing)을 방지하고, 전반적으로 L2 캐시로 들어오고 나가는 데이터 이동량을 줄일 수 있습니다.

1.0 미만의 hitRatio 값은 동시 CUDA 스트림의 서로 다른 accessPolicyWindow들이 L2에 캐시할 수 있는 데이터 양을 수동으로 제어하는 데 사용할 수 있습니다. 예를 들어, L2 예약(set-aside) 캐시 크기가 16KB라고 하고, 서로 다른 두 CUDA 스트림에서 실행되는 두 개의 동시 커널이 각각 16KB accessPolicyWindow를 가지며, 둘 다 hitRatio 값이 1.0이라면, 공유 L2 리소스를 두고 경쟁할 때 서로의 캐시 라인을 축출할 수 있습니다. 하지만 두 accessPolicyWindows 모두 hitRatio 값이 0.5라면, 자기 자신의 또는 서로의 지속적(persisting) 캐시 라인을 축출할 가능성이 더 낮아집니다.

4.13.3. L2 접근 속성#

서로 다른 전역 메모리 데이터 접근에 대해 세 가지 유형의 접근 속성이 정의됩니다:

  1. cudaAccessPropertyStreaming: 스트리밍(streaming) 속성으로 발생하는 메모리 접근은 우선적으로 축출되므로 L2 캐시에 유지될 가능성이 더 낮습니다.

  2. cudaAccessPropertyPersisting: 지속적(persisting) 속성으로 발생하는 메모리 접근은 L2 캐시에서 유지될 가능성이 더 높습니다. 이러한 접근은 L2 캐시의 예약된(set-aside) 부분에서 우선적으로 유지되기 때문입니다.

  3. cudaAccessPropertyNormal: 이 접근 속성은 이전에 적용된 지속적 접근 속성을 강제로 정상 상태로 재설정합니다. 이전 CUDA 커널의 지속적 속성을 가진 메모리 접근은 의도한 사용이 끝난 후에도 L2 캐시에 오랫동안 유지될 수 있습니다. 이러한 사용 후 지속(persistence-after-use)은 지속적 속성을 사용하지 않는 후속 커널이 사용할 수 있는 L2 캐시의 양을 줄입니다. cudaAccessPropertyNormal 속성으로 접근 속성 윈도우를 재설정하면, 이전 접근이 접근 속성 없이 수행된 것처럼, 이전 접근의 지속적(우선적 유지) 상태가 제거됩니다.

4.13.4. L2 지속성 예시#

다음 예시는 지속적 접근을 위해 L2 캐시를 예약(set-aside)하는 방법, CUDA Stream을 통해 CUDA 커널에서 예약된(set-aside) L2 캐시를 사용하는 방법, 그리고 이후 L2 캐시를 재설정하는 방법을 보여줍니다.

cudaStream_t stream;
cudaStreamCreate(&stream);                                                                  // Create CUDA stream

cudaDeviceProp prop;                                                                        // CUDA device properties variable
cudaGetDeviceProperties( &prop, device_id);                                                 // Query GPU properties
size_t size = min( int(prop.l2CacheSize * 0.75) , prop.persistingL2CacheMaxSize );
cudaDeviceSetLimit( cudaLimitPersistingL2CacheSize, size);                                  // set-aside 3/4 of L2 cache for persisting accesses or the max allowed

size_t window_size = min(prop.accessPolicyMaxWindowSize, num_bytes);                        // Select minimum of user defined num_bytes and max window size.

cudaStreamAttrValue stream_attribute;                                                       // Stream level attributes data structure
stream_attribute.accessPolicyWindow.base_ptr  = reinterpret_cast<void*>(data1);               // Global Memory data pointer
stream_attribute.accessPolicyWindow.num_bytes = window_size;                                // Number of bytes for persistence access
stream_attribute.accessPolicyWindow.hitRatio  = 0.6;                                        // Hint for cache hit ratio
stream_attribute.accessPolicyWindow.hitProp   = cudaAccessPropertyPersisting;               // Persistence Property
stream_attribute.accessPolicyWindow.missProp  = cudaAccessPropertyStreaming;                // Type of access property on cache miss

cudaStreamSetAttribute(stream, cudaStreamAttributeAccessPolicyWindow, &stream_attribute);   // Set the attributes to a CUDA Stream

for(int i = 0; i < 10; i++) {
    cuda_kernelA<<<grid_size,block_size,0,stream>>>(data1);                                 // This data1 is used by a kernel multiple times
}                                                                                           // [data1 + num_bytes) benefits from L2 persistence
cuda_kernelB<<<grid_size,block_size,0,stream>>>(data1);                                     // A different kernel in the same stream can also benefit
                                                                                            // from the persistence of data1

stream_attribute.accessPolicyWindow.num_bytes = 0;                                          // Setting the window size to 0 disable it
cudaStreamSetAttribute(stream, cudaStreamAttributeAccessPolicyWindow, &stream_attribute);   // Overwrite the access policy attribute to a CUDA Stream
cudaCtxResetPersistingL2Cache();                                                            // Remove any persistent lines in L2

cuda_kernelC<<<grid_size,block_size,0,stream>>>(data2);                                     // data2 can now benefit from full L2 in normal mode

4.13.5. L2 접근을 정상으로 재설정#

이전 CUDA 커널의 지속적 L2 캐시 라인은 사용된 후에도 L2에 오랫동안 유지될 수 있습니다. 따라서 스트리밍 또는 일반 메모리 접근이 정상 우선순위로 L2 캐시를 활용할 수 있도록 L2 캐시를 정상으로 재설정하는 것이 중요합니다. 지속적 접근을 정상 상태로 재설정하는 방법은 세 가지가 있습니다.

  1. 접근 속성 cudaAccessPropertyNormal를 사용하여 이전 지속적 메모리 영역을 재설정합니다.

  2. cudaCtxResetPersistingL2Cache()를 호출하여 모든 지속적 L2 캐시 라인을 정상으로 재설정합니다.

  3. 궁극적으로 건드리지 않은 라인은 자동으로 정상 상태로 재설정됩니다. 자동 재설정이 발생하는 데 필요한 시간이 정해져 있지 않으므로 자동 재설정에 의존하는 것은 강력히 권장되지 않습니다.

4.13.6. L2 예약(set-aside) 캐시 활용 관리#

서로 다른 CUDA 스트림에서 동시에 실행되는 여러 CUDA 커널에는 각 스트림에 서로 다른 접근 정책 윈도우가 할당될 수 있습니다. 하지만 L2 예약(set-aside) 캐시 부분은 이러한 모든 동시 CUDA 커널 간에 공유됩니다. 그 결과, 이 예약 캐시 부분의 순(총) 사용량은 모든 동시 커널의 개별 사용량의 합이 됩니다. 지속적(persisting)으로 메모리 접근을 지정하는 이점은 지속적 접근의 양이 예약된(set-aside) L2 캐시 용량을 초과할수록 감소합니다.

예약된(set-aside) L2 캐시 부분의 활용을 관리하기 위해 애플리케이션은 다음을 고려해야 합니다:

  • L2 예약(set-aside) 캐시의 크기.

  • 동시에 실행될 수 있는 CUDA 커널.

  • 동시에 실행될 수 있는 모든 CUDA 커널의 접근 정책 윈도우.

  • 정상 또는 스트리밍 접근이 이전에 예약된(set-aside) L2 캐시를 동일한 우선순위로 활용할 수 있도록 L2 재설정이 언제, 어떻게 필요한지.

4.13.7. L2 캐시 속성 조회#

L2 캐시와 관련된 속성은 cudaDeviceProp 구조체의 일부이며 CUDA 런타임 API cudaGetDeviceProperties를 사용하여 조회할 수 있습니다

CUDA 디바이스 속성에는 다음이 포함됩니다:

  • l2CacheSize: GPU에서 사용 가능한 L2 캐시의 양.

  • persistingL2CacheMaxSize: 지속적 메모리 접근을 위해 예약(set-aside)할 수 있는 L2 캐시의 최대량.

  • accessPolicyMaxWindowSize: 접근 정책 윈도우의 최대 크기.

4.13.8. 지속적 메모리 접근을 위한 L2 캐시 예약(set-aside) 크기 제어#

지속적 메모리 접근을 위한 L2 예약(set-aside) 캐시 크기는 CUDA 런타임 API cudaDeviceGetLimit를 사용하여 조회하며, CUDA 런타임 API cudaDeviceSetLimit를 사용하여 cudaLimit로 설정합니다. 이 제한을 설정할 때의 최대 값은 cudaDeviceProp::persistingL2CacheMaxSize입니다.

enum cudaLimit {
    /* other fields not shown */
    cudaLimitPersistingL2CacheSize
};
