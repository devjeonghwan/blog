4.12. 클러스터 런치 제어를 통한 워크 스틸링

가변적인 데이터 및 계산 크기 문제를 다루는 것은 CUDA 애플리케이션을 개발할 때 필수적입니다. 전통적으로 CUDA 개발자는 런치할 커널 스레드 블록의 수를 결정하기 위해 두 가지 주요 접근 방식을 사용해 왔습니다: 스레드 블록당 고정 작업량과 고정된 스레드 블록 수. 두 접근 방식 모두 장단점이 있습니다.

스레드 블록당 고정 작업량: 이 접근 방식에서는 스레드 블록의 수가 문제 크기에 의해 결정되며, 각 스레드 블록이 수행하는 작업량은 일정하게 유지됩니다.

이 접근 방식의 핵심 장점:

  • SM 간 로드 밸런싱

    스레드 블록 실행 시간이 가변적일 때 그리고/또는 스레드 블록 수가 GPU가 동시에 실행할 수 있는 수보다 훨씬 클 때(로우-테일 효과를 유발), 이 접근 방식은 GPU 스케줄러가 일부 SM에서는 다른 SM보다 더 많은 스레드 블록을 실행할 수 있게 합니다.

  • 선점(Preemption)

    GPU 스케줄러는 더 높은 우선순위의 커널을, 더 낮은 우선순위의 커널이 이미 실행을 시작한 뒤에 런치되었더라도, 더 낮은 우선순위 커널의 스레드 블록이 완료되는 대로 해당 스레드 블록을 스케줄링함으로써 실행을 시작할 수 있습니다. 그 후 더 높은 우선순위의 커널 실행이 끝나면 더 낮은 우선순위 커널의 실행을 재개할 수 있습니다.

고정된 스레드 블록 수: 이 접근 방식은 흔히 block-stride 또는 grid-stride 루프로 구현되며, 스레드 블록 수는 문제 크기에 의존하지 않습니다. 대신 각 스레드 블록이 수행하는 작업량은 문제 크기의 함수입니다. 일반적으로 스레드 블록 수는 커널이 실행되는 GPU의 SM 수와 원하는 점유율(occupancy)에 기반합니다.

이 접근 방식의 핵심 장점:

  • 스레드 블록 오버헤드 감소

    이 접근 방식은 스레드 블록 런치 지연 시간을 평균적으로 줄일 뿐만 아니라 모든 스레드 블록 전반에 걸친 공유 연산과 관련된 계산 오버헤드도 최소화합니다. 이러한 오버헤드는 런치 지연 오버헤드보다 훨씬 클 수 있습니다.

    예를 들어, 컨볼루션 커널에서는 컨볼루션 계수를 계산하기 위한 서두(prologue) — 스레드 블록 인덱스와 무관한 — 를 고정된 스레드 블록 수 덕분에 더 적은 횟수로 계산할 수 있어, 중복 계산을 줄일 수 있습니다.

클러스터 런치 제어(Cluster Launch Control)는 NVIDIA Blackwell GPU 아키텍처(컴퓨트 기능 10.0)에 도입된 기능으로, 앞의 두 접근 방식의 이점을 결합하는 것을 목표로 합니다. 개발자가 스레드 블록 또는 스레드 블록 클러스터를 취소할 수 있도록 하여 스레드 블록 스케줄링에 대해 더 많은 제어를 제공합니다. 이 메커니즘은 워크 스틸링을 가능하게 합니다. 워크 스틸링은 병렬 컴퓨팅에서의 동적 로드 밸런싱 기법으로, 유휴 프로세서가 작업이 할당되기를 기다리는 대신, 바쁜 프로세서의 작업 큐에서 작업을 적극적으로 “훔치는” 방식입니다.

클러스터 런치 제어를 사용하면, 스레드 블록은 아직 실행을 시작하지 않은 다른 스레드 블록의 런치를 취소하려고 시도합니다. 취소 요청이 성공하면, 해당 스레드 블록의 작업을 “훔쳐” 그 인덱스를 사용해 작업을 수행합니다. 취소는 더 이상 사용 가능한 스레드 블록 인덱스가 없거나, 더 높은 우선순위의 커널이 스케줄링되는 것과 같은 다른 이유로 실패할 수 있습니다. 후자의 경우, 스레드 블록이 취소 실패 후 종료하면, 스케줄러는 더 높은 우선순위의 커널 실행을 시작할 수 있으며, 그 후 현재 커널의 남은 스레드 블록을 계속 스케줄링하여 실행합니다. 위의 그림은 이 절차의 실행 흐름을 보여줍니다.

4.12.1. API 세부 정보#

클러스터 런치 제어 API를 통해 스레드 블록을 취소하는 작업은 비동기적으로 수행되며 공유 메모리 배리어를 사용해 동기화되고, 비동기 데이터 복사와 유사한 프로그래밍 패턴을 따릅니다.

libcu++를 통해 사용할 수 있는 이 API는 다음을 제공합니다:

  • 인코딩된 취소 결과를 __shared__ 변수에 기록하는 요청 명령.

  • 성공/실패 상태와 취소된 스레드 블록 인덱스를 추출하는 디코딩 명령.

클러스터 런치 제어 연산은 async proxy 연산으로 모델링된다는 점에 유의하십시오( Async Thread and Async Proxy 참고).

4.12.1.1. 스레드 블록 취소#

클러스터 런치 제어를 사용하는 바람직한 방법은 단일 스레드에서, 즉 한 번에 하나의 요청을 수행하는 것입니다.

취소 프로세스는 다섯 단계로 구성됩니다:

  • 설정 단계 (단계 1-2): 취소 결과 및 동기화 변수를 선언하고 초기화합니다.

  • 워크 스틸링 루프 (단계 3-5): 취소 결과를 요청, 동기화, 처리하기 위해 반복 실행합니다.

  1. 스레드 블록 취소를 위한 변수를 선언합니다:

    __shared__ uint4 result; // Request result.
__shared__ uint64_t bar; // Synchronization barrier.
int phase = 0;           // Synchronization barrier phase.

  2. 단일 도착 카운트로 공유 메모리 배리어를 초기화합니다:

    if (cg::thread_block::thread_rank() == 0)
    ptx::mbarrier_init(&bar, 1);
__syncthreads();

  3. 단일 스레드로 비동기 취소 요청을 제출하고 트랜잭션 카운트를 설정합니다:

    if (cg::thread_block::thread_rank() == 0) {
    cg::invoke_one(cg::coalesced_threads(), [&](){ptx::clusterlaunchcontrol_try_cancel(&result, &bar);});
    ptx::mbarrier_arrive_expect_tx(ptx::sem_relaxed, ptx::scope_cta, ptx::space_shared, &bar, sizeof(uint4));
}

    참고

    스레드 블록 취소는 균일(uniform) 명령이므로, invoke_one 스레드 선택기 내부에서 제출하는 것을 권장합니다. 이를 통해 컴파일러가 peeling 루프를 최적화로 제거할 수 있습니다.

  4. 비동기 취소 요청을 동기화(완료)합니다:

    while (!ptx::mbarrier_try_wait_parity(&bar, phase))
{}
phase ^= 1;

  5. 취소 상태와 취소된 스레드 블록 인덱스를 가져옵니다:

    bool success = ptx::clusterlaunchcontrol_query_cancel_is_canceled(result);
if (success) {
    // Don't need all three for 1D/2D thread blocks:
    int bx = ptx::clusterlaunchcontrol_query_cancel_get_first_ctaid_x(result);
    int by = ptx::clusterlaunchcontrol_query_cancel_get_first_ctaid_y(result);
    int bz = ptx::clusterlaunchcontrol_query_cancel_get_first_ctaid_z(result);
}

  6. async 및 generic proxies 간의 공유 메모리 연산 가시성을 보장하고, 워크 스틸링 루프 반복 간 데이터 레이스를 방지합니다.

4.12.1.2. 스레드 블록 취소에 대한 제약#

제약은 실패한 취소 요청과 관련이 있습니다:

  • 이전에 실패한 요청을 관찰(observing)한 후 다른 취소 요청을 제출하는 것은 정의되지 않은 동작(undefined behavior)입니다.

    아래 두 코드 예제에서 첫 번째 취소 요청이 실패한다고 가정하면, 첫 번째 예제만 정의되지 않은 동작을 보입니다. 두 번째 예제는 취소 요청들 사이에 관찰이 없으므로 올바릅니다:

    잘못된 코드:

    // First request:
ptx::clusterlaunchcontrol_try_cancel(&result0, &bar0);

// First request query:
[Synchronize bar0 code here.]
bool success0 = ptx::clusterlaunchcontrol_query_cancel_is_canceled(result0);
assert(!success0); // Observed failure; second cancellation will be invalid.

// Second request - next line is Undefined Behavior:
ptx::clusterlaunchcontrol_try_cancel(&result1, &bar1);

    올바른 코드:

    // First request:
ptx::clusterlaunchcontrol_try_cancel(&result0, &bar0);

// Second request:
ptx::clusterlaunchcontrol_try_cancel(&result1, &bar1);

// First request query:
[Synchronize bar0 code here.]
bool success0 = ptx::clusterlaunchcontrol_query_cancel_is_canceled(result0);
assert(!success0); // Observed failure; second cancellation was valid.

  • 실패한 취소 요청의 스레드 블록 인덱스를 가져오는 것은 정의되지 않은 동작(Undefined Behavior)입니다.

  • 여러 스레드에서 취소 요청을 제출하는 것은 권장되지 않습니다. 이는 여러 스레드 블록의 취소를 초래하며 신중한 처리가 필요합니다. 예를 들어:

    • 제출하는 각 스레드는 데이터 레이스를 피하기 위해 고유한 __shared__ 결과 포인터를 제공해야 합니다.

    • 동기화에 동일한 배리어를 사용하는 경우, 도착 및 트랜잭션 카운트를 그에 맞게 조정해야 합니다.

4.12.2. 예: 벡터-스칼라 곱셈#

다음 하위 섹션에서는 벡터-스칼라 곱셈 커널을 통해 클러스터 런치 제어를 사용한 워크 스틸링을 시연합니다. 동일한 문제의 두 가지 변형을 보여줍니다. 하나는 스레드 블록을 사용하고, 다른 하나는 스레드 블록 클러스터를 사용합니다.

4.12.2.1. 사용 사례: 스레드 블록#

아래의 세 개 커널은 다음을 시연합니다 스레드 블록당 고정 작업량, 고정된 스레드 블록 수, 그리고 클러스터 런치 제어 접근 방식 벡터-스칼라 곱셈을 위한 \(\overline{v} := \alpha \overline{v}\).

  • 스레드 블록당 고정 작업량:

    __global__
void kernel_fixed_work (float* data, int n)
{
    // Prologue:
    float alpha = compute_scalar();

    // Computation:
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n)
        data[i] *= alpha;
}

// Launch: kernel_fixed_work<<<1024, (n + 1023) / 1024>>>(data, n);

  • 고정된 스레드 블록 수:

    __global__
void kernel_fixed_blocks (float* data, int n)
{
    // Prologue:
    float alpha = compute_scalar();

    // Computation:
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    while (i < n) {
        data[i] *= alpha;
        i += gridDim.x * blockDim.x;
    }
}

// Launch: kernel_fixed_blocks<<<1024, SM_COUNT>>>(data, n);

  • 클러스터 런치 제어:

    #include <cooperative_groups.h>
#include <cuda/ptx>

namespace cg = cooperative_groups;
namespace ptx = cuda::ptx;

__global__
void kernel_cluster_launch_control (float* data, int n)
{
    // Cluster launch control initialization:
    __shared__ uint4 result;
    __shared__ uint64_t bar;
    int phase = 0;

    if (cg::thread_block::thread_rank() == 0)
        ptx::mbarrier_init(&bar, 1);

    // Prologue:
    float alpha = compute_scalar(); // Device function not shown in this code snippet.

    // Work-stealing loop:
    int bx = blockIdx.x; // Assuming 1D x-axis thread blocks.

    while (true) {
        // Protect result from overwrite in the next iteration,
        // (also ensure barrier initialization at 1st iteration):
        __syncthreads();

        // Cancellation request:
        if (cg::thread_block::thread_rank() == 0) {
            // Acquire write of result in the async proxy:
            ptx::fence_proxy_async_generic_sync_restrict(ptx::sem_acquire, ptx::space_cluster, ptx::scope_cluster);

            cg::invoke_one(cg::coalesced_threads(), [&](){ptx::clusterlaunchcontrol_try_cancel(&result, &bar);});
            ptx::mbarrier_arrive_expect_tx(ptx::sem_relaxed, ptx::scope_cta, ptx::space_shared, &bar, sizeof(uint4));
        }

        // Computation:
        int i = bx * blockDim.x + threadIdx.x;
        if (i < n)
            data[i] *= alpha;

        // Cancellation request synchronization:
        while (!ptx::mbarrier_try_wait_parity(ptx::sem_acquire, ptx::scope_cta, &bar, phase))
        {}
        phase ^= 1;

        // Cancellation request decoding:
        bool success = ptx::clusterlaunchcontrol_query_cancel_is_canceled(result);
        if (!success)
            break;

        bx = ptx::clusterlaunchcontrol_query_cancel_get_first_ctaid_x<int>(result);

        // Release read of result to the async proxy:
        ptx::fence_proxy_async_generic_sync_restrict(ptx::sem_release, ptx::space_shared, ptx::scope_cluster);
    }
}

// Launch: kernel_cluster_launch_control<<<1024, (n + 1023) / 1024>>>(data, n);

4.12.2.2. 사용 사례: 스레드 블록 클러스터#

thread block clusters의 경우, 스레드 블록 취소 단계는 비클러스터(non-cluster) 설정에서와 동일하며, 약간의 조정만 있습니다. 비클러스터 경우와 마찬가지로, 클러스터 내 여러 스레드에서 취소 요청을 제출하는 것은 권장되지 않는데, 이는 여러 클러스터를 취소하려고 시도하게 되기 때문입니다.

  • 취소는 단일 클러스터 스레드가 제출합니다.

  • 각 클러스터의 스레드 블록에 대한 shared memory 결과는 취소된 스레드 블록 인덱스의 동일한(인코딩된) 값을 받게 됩니다 (즉, 결과 값이 멀티캐스트됩니다). 모든 스레드 블록이 받는 결과는 클러스터 내 로컬 블록 인덱스 {0, 0, 0}에 해당합니다. 따라서 클러스터 내 스레드 블록은 로컬 블록 인덱스를 더해야 합니다.

  • 동기화는 각 클러스터의 스레드 블록이 로컬을 사용하여 수행됩니다 __shared__ 메모리 배리어. 배리어 연산은 수행되어야 합니다 with the ptx::scope_cluster 스코프.

  • 클러스터 경우에서의 취소는 모든 스레드 블록이 존재해야 합니다. 사용자는 다음을 사용하여 모든 스레드 블록이 실행 중임을 보장할 수 있습니다. cg::cluster_group::sync() 에서 동기화 API.

아래 커널은 스레드 블록 클러스터를 사용한 클러스터 런치 제어 접근 방식을 보여줍니다.

#include <cooperative_groups.h>
#include <cuda/ptx>

namespace cg = cooperative_groups;
namespace ptx = cuda::ptx;

__global__ __cluster_dims__(2, 1, 1)
void kernel_cluster_launch_control (float* data, int n)
{
    // Cluster launch control initialization:
    __shared__ uint4 result;
    __shared__ uint64_t bar;
    int phase = 0;

    if (cg::thread_block::thread_rank() == 0) {
        ptx::mbarrier_init(&bar, 1);
        ptx::fence_mbarrier_init(ptx::sem_release, ptx::scope_cluster); // CGA-level fence.
    }

    // Prologue:
    float alpha = compute_scalar(); // Device function not shown in this code snippet.

    // Work-stealing loop:
    int bx = blockIdx.x; // Assuming 1D x-axis thread blocks.

    while (true) {
        // Protect result from overwrite in the next iteration,
        // (also ensure all thread blocks have started at 1st iteration):
        cg::cluster_group::sync();

        // Cancellation request by a single cluster thread:
        if (cg::cluster_group::thread_rank() == 0) {
            // Acquire write of result in the async proxy:
            ptx::fence_proxy_async_generic_sync_restrict(ptx::sem_acquire, ptx::space_cluster, ptx::scope_cluster);

            cg::invoke_one(cg::coalesced_threads(), [&](){ptx::clusterlaunchcontrol_try_cancel_multicast(&result, &bar);});
        }

        // Cancellation completion tracked by each thread block:
        if (cg::thread_block::thread_rank() == 0)
            ptx::mbarrier_arrive_expect_tx(ptx::sem_relaxed, ptx::scope_cluster, ptx::space_shared, &bar, sizeof(uint4));

        // Computation:
        int i = bx * blockDim.x + threadIdx.x;
        if (i < n)
            data[i] *= alpha;

        // Cancellation request synchronization:
        while (!ptx::mbarrier_try_wait_parity(ptx::sem_acquire, ptx::scope_cluster, &bar, phase))
        {}
        phase ^= 1;

        // Cancellation request decoding:
        bool success = ptx::clusterlaunchcontrol_query_cancel_is_canceled(result);
        if (!success)
            break;

        bx = ptx::clusterlaunchcontrol_query_cancel_get_first_ctaid_x<int>(result);
        bx += cg::cluster_group::block_index().x; // Add local offset.

        // Release read of result to the async proxy:
        ptx::fence_proxy_async_generic_sync_restrict(ptx::sem_release, ptx::space_shared, ptx::scope_cluster);
    }
}

// Launch: kernel_cluster_launch_control<<<1024, (n + 1023) / 1024>>>(data, n);
