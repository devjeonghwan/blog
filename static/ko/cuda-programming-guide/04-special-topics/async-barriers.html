4.9. 비동기 배리어

고급 동기화 프리미티브에서 소개된 비동기 배리어는 CUDA 동기화를 __syncthreads() 및 __syncwarp()를 넘어 확장하여, 세밀한 제어의 비차단 조정과 통신 및 연산의 더 나은 오버랩을 가능하게 합니다.

이 섹션에서는 주로 cuda::barrier API를 통해 비동기 배리어를 사용하는 방법에 대한 세부 정보를 제공하며(해당되는 경우 cuda::ptx 및 프리미티브에 대한 포인터도 포함합니다).

4.9.1. 초기화#

초기화는 어떤 스레드든 배리어에 참여하기 시작하기 전에 이루어져야 합니다.

#include <cuda/barrier>
#include <cooperative_groups.h>

__global__ void init_barrier()
{
  __shared__ cuda::barrier<cuda::thread_scope_block> bar;
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    // A single thread initializes the total expected arrival count.
    init(&bar, block.size());
  }
  block.sync();
}

#include <cuda/ptx>
#include <cooperative_groups.h>

__global__ void init_barrier()
{
  __shared__ uint64_t bar;
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    // A single thread initializes the total expected arrival count.
    cuda::ptx::mbarrier_init(&bar, block.size());
  }
  block.sync();
}

#include <cuda_awbarrier_primitives.h>
#include <cooperative_groups.h>

__global__ void init_barrier()
{
  __shared__ uint64_t bar;
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    // A single thread initializes the total expected arrival count.
    __mbarrier_init(&bar, block.size());
  }
  block.sync();
}

어떤 스레드든 배리어에 참여하기 전에, 배리어는 cuda::barrier::init() friend 함수로 초기화되어야 합니다. 이는 어떤 스레드가 배리어에 도착(arrive)하기 전에 이루어져야 합니다. 이는 스레드가 배리어에 참여하기 전에 동기화해야 하지만, 스레드가 동기화하기 위해 배리어를 생성하고 있다는 점에서 부트스트래핑 문제를 야기합니다. 이 예제에서는 참여할 스레드가 협력 그룹(cooperative group)의 일부이며, block.sync()를 사용해 초기화를 부트스트랩합니다. 전체 스레드 블록이 배리어에 참여하므로, __syncthreads()도 사용할 수 있습니다.

init()의 두 번째 매개변수는 예상 도착 횟수로, 즉 참여하는 스레드가 bar.arrive()를 몇 번 호출해야 참여 스레드가 bar.wait(std::move(token)) 호출에서 언블록(unblock)되는지를 의미합니다. 이 예제와 이전 예제에서는 배리어가 스레드 블록의 스레드 수, 즉 cooperative_groups::this_thread_block().size()로 초기화되어, 스레드 블록 내의 모든 스레드가 배리어에 참여할 수 있습니다.

비동기 배리어는 스레드가 어떻게 참여하는지(도착/대기 분리)와 어떤 스레드가 참여하는지를 지정하는 데 유연합니다. 반면, this_thread_block.sync() 또는 __syncthreads()는 전체 스레드 블록에 적용되며, __syncwarp(mask)는 워프의 지정된 부분집합에 적용됩니다. 그럼에도 사용자의 의도가 전체 스레드 블록 또는 전체 워프를 동기화하는 것이라면, 더 나은 성능을 위해 각각 __syncthreads() 및 __syncwarp()를 사용할 것을 권장합니다.

4.9.2. 배리어의 페이즈: 도착, 카운트다운, 완료 및 리셋#

비동기 배리어는 참여 스레드가 bar.arrive()를 호출함에 따라 예상 도착 카운트에서 0까지 카운트다운합니다. 카운트다운이 0에 도달하면, 배리어는 현재 페이즈에 대해 완료됩니다. bar.arrive()에 대한 마지막 호출로 인해 카운트다운이 0에 도달하면, 카운트다운은 자동으로 그리고 원자적으로 리셋됩니다. 리셋은 카운트다운을 예상 도착 카운트로 설정하고, 배리어를 다음 페이즈로 이동시킵니다.

token 클래스의 cuda::barrier::arrival_token 객체는 token=bar.arrive()에서 반환되는 것처럼, 배리어의 현재 페이즈와 연관됩니다. bar.wait(std::move(token))에 대한 호출은 배리어가 현재 페이즈에 있는 동안, 즉 토큰과 연관된 페이즈가 배리어의 페이즈와 일치하는 동안 호출한 스레드를 블록합니다. bar.wait(std::move(token))에 대한 호출 이전에 페이즈가 (카운트다운이 0에 도달하여) 진행되면 스레드는 블록되지 않습니다. 스레드가 bar.wait(std::move(token))에서 블록되어 있는 동안 페이즈가 진행되면 스레드는 언블록(unblock)됩니다.

리셋이 발생할 수 있는 경우와 발생할 수 없는 경우를 아는 것은 특히 복잡하지 않은 도착/대기 동기화 패턴에서 필수적입니다.

  • 스레드가 token=bar.arrive() 및 bar.wait(std::move(token))를 호출하는 순서는, token=bar.arrive()가 배리어의 현재 페이즈 동안 발생하고, bar.wait(std::move(token))는 동일한 페이즈 또는 다음 페이즈 동안 발생하도록 시퀀싱되어야 합니다.

  • 스레드의 호출은 bar.arrive() 배리어의 카운터가 0이 아닐 때 발생해야 합니다. 배리어 초기화 후, 스레드가 bar.arrive() 가 카운트다운이 0에 도달하게 하면, 에 대한 호출은 bar.wait(std::move(token)) 배리어를 후속 호출에 다시 사용하려면 먼저 발생해야 합니다 bar.arrive().

  • bar.wait() 반드시 오직 a를 사용하여 호출되어야 합니다 token 현재 페이즈 또는 바로 이전 페이즈의 object를 사용해서만 호출되어야 합니다. 그 외의 모든 값에 대해서는 token object에 대해서는 동작이 정의되지 않습니다.

단순한 도착/대기 동기화 패턴의 경우, 이러한 사용 규칙을 준수하는 것은 간단합니다.

4.9.2.1. 워프 얽힘#

워프 다이버전스(warp-divergence)는 arrive-on 연산이 배리어를 업데이트하는 횟수에 영향을 미칩니다. 호출하는 워프가 완전히 컨버지드(converged)된 경우, 배리어는 한 번 업데이트됩니다. 호출하는 워프가 완전히 다이버지드(diverged)된 경우, 32개의 개별 업데이트가 배리어에 적용됩니다.

참고

배리어 객체에 대한 업데이트를 최소화하기 위해, arrive-on(bar) 호출은 컨버지드된 스레드에서 사용하는 것을 권장합니다. 이러한 연산에 앞선 코드가 스레드를 다이버지시키는 경우, arrive-on 연산을 호출하기 전에 __syncwarp를 통해 워프를 다시 컨버지드되도록 해야 합니다.

4.9.3. 명시적 페이즈 추적#

비동기 배리어는 스레드 및 메모리 연산을 동기화하는 데 몇 번 사용되는지에 따라 여러 페이즈를 가질 수 있습니다. 토큰을 사용하여 배리어 페이즈 플립을 추적하는 대신, 다음을 사용하여 페이즈를 직접 추적할 수 있습니다. mbarrier_try_wait_parity() 다음을 통해 사용할 수 있는 함수 패밀리 cuda::ptx 및 프리미티브 API.

가장 단순한 형태로, cuda::ptx::mbarrier_try_wait_parity(uint64_t* bar, const uint32_t& phaseParity) 함수는 특정 패리티를 가진 페이즈를 기다립니다. phaseParity 피연산자는 배리어 객체의 현재 페이즈 또는 바로 이전 페이즈의 정수 패리티입니다. 짝수 페이즈의 정수 패리티는 0이고 홀수 페이즈의 정수 패리티는 1입니다. 배리어를 초기화하면 해당 페이즈의 패리티는 0입니다. 따라서 phaseParity의 유효한 값은 0과 1입니다. 명시적 페이즈 추적은 비동기 메모리 연산을 추적할 때 유용할 수 있는데, 이는 단 하나의 스레드만 배리어에 도착하여 트랜잭션 카운트를 설정하고, 다른 스레드들은 패리티 기반 페이즈 플립만 기다리도록 허용하기 때문입니다. 이는 모든 스레드가 배리어에 도착하고 토큰을 사용하는 것보다 더 효율적일 수 있습니다. 이 기능은 스레드 블록 및 클러스터 스코프에서의 공유 메모리 배리어에 대해서만 사용할 수 있습니다.

#include <cuda/ptx>
#include <cooperative_groups.h>

__device__ void compute(float *data, int iteration);

__global__ void split_arrive_wait(int iteration_count, float *data)
{
  using barrier_t = cuda::barrier<cuda::thread_scope_block>;
  __shared__ barrier_t bar;
  int parity = 0; // Initial phase parity is 0.
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    // Initialize barrier with expected arrival count.
    init(&bar, block.size());
  }
  block.sync();

  for (int i = 0; i < iteration_count; ++i)
  {
    /* code before arrive */

    // This thread arrives. Arrival does not block a thread.
    // Get a handle to the native barrier to use with cuda::ptx API.
    (void)cuda::ptx::mbarrier_arrive(cuda::device::barrier_native_handle(bar));

    compute(data, i);

    // Wait for all threads participating in the barrier to complete mbarrier_arrive().
    // Get a handle to the native barrier to use with cuda::ptx API.
    while (!cuda::ptx::mbarrier_try_wait_parity(cuda::device::barrier_native_handle(bar), parity)) {}
    // Flip parity.
    parity ^= 1;

    /* code after wait */
  }
}

#include <cuda/ptx>
#include <cooperative_groups.h>

__device__ void compute(float *data, int iteration);

__global__ void split_arrive_wait(int iteration_count, float *data)
{
  __shared__ uint64_t bar;
  int parity = 0; // Initial phase parity is 0.
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    // Initialize barrier with expected arrival count.
    cuda::ptx::mbarrier_init(&bar, block.size());
  }
  block.sync();

  for (int i = 0; i < iteration_count; ++i)
  {
    /* code before arrive */

    // This thread arrives. Arrival does not block a thread.
    (void)cuda::ptx::mbarrier_arrive(&bar);

    compute(data, i);

    // Wait for all threads participating in the barrier to complete mbarrier_arrive().
    while (!cuda::ptx::mbarrier_try_wait_parity(&bar, parity)) {}
    // Flip parity.
    parity ^= 1;

    /* code after wait */
  }
}

#include <cuda_awbarrier_primitives.h>
#include <cooperative_groups.h>

__device__ void compute(float *data, int iteration);

__global__ void split_arrive_wait(int iteration_count, float *data)
{
  __shared__ __mbarrier_t bar;
  bool parity = false; // Initial phase parity is false.
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    // Initialize barrier with expected arrival count.
    __mbarrier_init(&bar, block.size());
  }
  block.sync();

  for (int i = 0; i < iteration_count; ++i)
  {
    /* code before arrive */

    // This thread arrives. Arrival does not block a thread.
    (void)__mbarrier_arrive(&bar);

    compute(data, i);

    // Wait for all threads participating in the barrier to complete __mbarrier_arrive().
    while(!__mbarrier_try_wait_parity(&bar, parity, 1000)) {}
    parity ^= 1;

    /* code after wait */
  }
}

4.9.4. 조기 종료#

일련의 동기화 시퀀스에 참여 중인 스레드가 해당 시퀀스에서 조기에 종료해야 하는 경우, 해당 스레드는 종료하기 전에 참여에서 명시적으로 빠져나와야 합니다. 남아 있는 참여 스레드들은 이후의 arrive 및 wait 연산을 정상적으로 진행할 수 있습니다.

#include <cuda/barrier>
#include <cooperative_groups.h>

__device__ bool condition_check();

__global__ void early_exit_kernel(int N)
{
  __shared__ cuda::barrier<cuda::thread_scope_block> bar;
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    init(&bar, block.size());
  }
  block.sync();

  for (int i = 0; i < N; ++i)
  {
    if (condition_check())
    {
      bar.arrive_and_drop();
      return;
    }
    // Other threads can proceed normally.
    auto token = bar.arrive();

    /* code between arrive and wait */

    // Wait for all threads to arrive.
    bar.wait(std::move(token));

    /* code after wait */
  }
}

#include <cuda_awbarrier_primitives.h>
#include <cooperative_groups.h>

__device__ bool condition_check();

__global__ void early_exit_kernel(int N)
{
  __shared__ __mbarrier_t bar;
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    __mbarrier_init(&bar, block.size());
  }
  block.sync();

  for (int i = 0; i < N; ++i)
  {
    if (condition_check())
    {
      __mbarrier_token_t token = __mbarrier_arrive_and_drop(&bar);
      return;
    }
    // Other threads can proceed normally.
    __mbarrier_token_t token = __mbarrier_arrive(&bar);

    /* code between arrive and wait */

    // Wait for all threads to arrive.
    while (!__mbarrier_try_wait(&bar, token, 1000)) {}

    /* code after wait */
  }
}

bar.arrive_and_drop() 연산은 현재 페이즈에서 참여 스레드가 도착해야 하는 의무를 이행하기 위해 배리어에 도착한 다음, 다음 페이즈에서 기대되는 도착 카운트를 감소시켜 이 스레드가 더 이상 배리어에 도착할 것으로 기대되지 않도록 합니다.

4.9.5. 완료 함수#

The cuda::barrier API는 선택적 완료 함수를 지원합니다. A CompletionFunction 의 cuda::barrier<Scope, CompletionFunction> 는 마지막 스레드 이후 각 페이즈당 한 번 실행됩니다. 도착합니다 그리고 어떤 스레드도 다음으로부터 언블록(unblock)되기 전에 wait. 배리어에 도착한 스레드가 수행한 메모리 연산은 barrier 페이즈 동안은 다음을 실행하는 스레드에 보입니다 CompletionFunction, 그리고 다음 범위 내에서 수행된 모든 메모리 연산은 CompletionFunction 배리어에서 대기 중인 모든 스레드에 보입니다 barrier 배리어에서 언블록(unblock)되면 wait.

#include <cuda/barrier>
#include <cooperative_groups.h>
#include <functional>
namespace cg = cooperative_groups;

__device__ int divergent_compute(int *, int);
__device__ int independent_computation(int *, int);

__global__ void psum(int *data, int n, int *acc)
{
  auto block = cg::this_thread_block();

  constexpr int BlockSize = 128;
  __shared__ int smem[BlockSize];
  assert(BlockSize == block.size());
  assert(n % BlockSize == 0);

  auto completion_fn = [&]
  {
    int sum = 0;
    for (int i = 0; i < BlockSize; ++i)
    {
      sum += smem[i];
    }
    *acc += sum;
  };

  /* Barrier storage.
     Note: the barrier is not default-constructible because
           completion_fn is not default-constructible due
           to the capture. */
  using completion_fn_t = decltype(completion_fn);
  using barrier_t = cuda::barrier<cuda::thread_scope_block,
                                  completion_fn_t>;
  __shared__ std::aligned_storage<sizeof(barrier_t),
                                  alignof(barrier_t)>
      bar_storage;

  // Initialize barrier.
  barrier_t *bar = (barrier_t *)&bar_storage;
  if (block.thread_rank() == 0)
  {
    assert(*acc == 0);
    assert(blockDim.x == blockDim.y == blockDim.y == 1);
    new (bar) barrier_t{block.size(), completion_fn};
    /* equivalent to: init(bar, block.size(), completion_fn); */
  }
  block.sync();

  // Main loop.
  for (int i = 0; i < n; i += block.size())
  {
    smem[block.thread_rank()] = data[i] + *acc;
    auto token = bar->arrive();
    // We can do independent computation here.
    bar->wait(std::move(token));
    // Shared-memory is safe to re-use in the next iteration
    // since all threads are done with it, including the one
    // that did the reduction.
  }
}

4.9.6. 비동기 메모리 연산 추적#

비동기 배리어는 비동기 메모리 복사를 추적하는 데 사용할 수 있습니다. 비동기 복사 연산이 배리어에 바인딩되면, 복사 연산은 시작 시 현재 배리어 페이즈의 기대 카운트를 자동으로 증가시키고 완료 시 감소시킵니다. 이 메커니즘은 배리어의 wait() 연산이 연결된 모든 비동기 메모리 복사가 완료될 때까지 블록되도록 보장하여, 여러 개의 동시 메모리 연산을 동기화하는 편리한 방법을 제공합니다.

컴퓨트 커패빌리티 9.0부터, 스레드 블록 또는 클러스터 스코프를 갖는 공유 메모리의 비동기 배리어는 비동기 메모리 연산을 명시적으로 추적할 수 있습니다. 우리는 이러한 배리어를 비동기 트랜잭션 배리어라고 부릅니다. 기대 도착 카운트 외에도, 배리어 object는 트랜잭션 카운트를 받을 수 있으며, 이는 비동기 트랜잭션의 완료를 추적하는 데 사용할 수 있습니다. 트랜잭션 카운트는 비동기 트랜잭션 중 아직 완료되지 않은 미완료(outstanding) 트랜잭션의 수를, 비동기 메모리 연산에서 지정한 단위(일반적으로 바이트)로 추적합니다. 현재 페이즈에서 추적할 트랜잭션 카운트는 cuda::device::barrier_arrive_tx()로 도착(arrival) 시 설정하거나, cuda::device::barrier_expect_tx()로 직접 설정할 수 있습니다. 배리어가 트랜잭션 카운트를 사용할 때에는, 모든 생산자 스레드가 arrive 및 모든 트랜잭션 카운트의 합이 기대 값에 도달할 때까지 대기(wait) 연산에서 스레드를 블록합니다.

#include <cuda/barrier>
#include <cooperative_groups.h>

__global__ void track_kernel()
{
  __shared__ cuda::barrier<cuda::thread_scope_block> bar;
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    init(&bar, block.size());
  }
  block.sync();

  auto token = cuda::device::barrier_arrive_tx(bar, 1, 0);

  bar.wait(cuda::std::move(token));
}

#include <cuda/ptx>
#include <cooperative_groups.h>

__global__ void track_kernel()
{
  __shared__ uint64_t bar;
  auto block = cooperative_groups::this_thread_block();

  if (block.thread_rank() == 0)
  {
    cuda::ptx::mbarrier_init(&bar, block.size());
  }
  block.sync();

  uint64_t token = cuda::ptx::mbarrier_arrive_expect_tx(cuda::ptx::sem_release, cuda::ptx::scope_cluster, cuda::ptx::space_shared, &bar, 1, 0);

  while (!cuda::ptx::mbarrier_try_wait(&bar, token)) {}
}

이 예제에서, cuda::device::barrier_arrive_tx() 연산은 현재 페이즈의 페이즈 동기화 지점과 연관된 도착 토큰 object를 구성합니다. 그런 다음 도착 카운트를 1 감소시키고 기대 트랜잭션 카운트를 0 증가시킵니다. 트랜잭션 카운트 업데이트가 0이므로, 배리어는 어떤 트랜잭션도 추적하고 있지 않습니다. 이어지는 텐서 메모리 가속기(TMA) 사용 섹션에는 비동기 메모리 연산을 추적하는 예제가 포함되어 있습니다.

4.9.7. 배리어를 사용하는 프로듀서-컨슈머 패턴#

스레드 블록은 서로 다른 스레드가 독립적인 연산을 수행할 수 있도록 공간적으로 파티셔닝할 수 있습니다. 이는 가장 일반적으로 스레드 블록 내의 서로 다른 워프에 속한 스레드를 특정 작업에 할당함으로써 수행됩니다. 이 기법을 워프 특화(warp specialization)라고 합니다.

이 섹션은 프로듀서-컨슈머 패턴에서의 공간적 파티셔닝 예제를 보여주며, 여기서 한 스레드 부분집합이 데이터를 생성하고, 다른(서로 겹치지 않는) 스레드 부분집합이 이를 동시에 소비합니다. 프로듀서-컨슈머 공간 파티셔닝 패턴은 프로듀서와 컨슈머 사이의 데이터 버퍼를 관리하기 위해 두 개의 일방향 동기화가 필요합니다.

프로듀서

컨슈머

버퍼가 채워질 준비가 될 때까지 대기

버퍼가 채워질 준비가 되었음을 신호

데이터를 생성하고 버퍼를 채움

버퍼가 채워졌음을 신호

버퍼가 채워질 때까지 대기

채워진 버퍼의 데이터를 소비

프로듀서 스레드는 컨슈머 스레드가 버퍼가 채워질 준비가 되었음을 신호할 때까지 대기하지만, 컨슈머 스레드는 이 신호를 기다리지 않습니다. 컨슈머 스레드는 프로듀서 스레드가 버퍼가 채워졌음을 신호할 때까지 대기하지만, 프로듀서 스레드는 이 신호를 기다리지 않습니다. 프로듀서/컨슈머의 완전한 동시성을 위해 이 패턴은 (최소한) 더블 버퍼링을 가지며, 각 버퍼에는 두 개의 배리어가 필요합니다.

#include <cuda/barrier>

using barrier_t = cuda::barrier<cuda::thread_scope_block>;

__device__ void produce(barrier_t ready[], barrier_t filled[], float *buffer, int buffer_len, float *in, int N)
{
  for (int i = 0; i < N / buffer_len; ++i)
  {
    ready[i % 2].arrive_and_wait(); /* wait for buffer_(i%2) to be ready to be filled */
    /* produce, i.e., fill in, buffer_(i%2)  */
    barrier_t::arrival_token token = filled[i % 2].arrive(); /* buffer_(i%2) is filled */
  }
}

__device__ void consume(barrier_t ready[], barrier_t filled[], float *buffer, int buffer_len, float *out, int N)
{
  barrier_t::arrival_token token1 = ready[0].arrive(); /* buffer_0 is ready for initial fill */
  barrier_t::arrival_token token2 = ready[1].arrive(); /* buffer_1 is ready for initial fill */
  for (int i = 0; i < N / buffer_len; ++i)
  {
    filled[i % 2].arrive_and_wait(); /* wait for buffer_(i%2) to be filled */
    /* consume buffer_(i%2) */
    barrier_t::arrival_token token3 = ready[i % 2].arrive(); /* buffer_(i%2) is ready to be re-filled */
  }
}

__global__ void producer_consumer_pattern(int N, float *in, float *out, int buffer_len)
{
  constexpr int warpSize = 32;

  /* Shared memory buffer declared below is of size 2 * buffer_len
     so that we can alternatively work between two buffers.
     buffer_0 = buffer and buffer_1 = buffer + buffer_len */
  __shared__ extern float buffer[];

  /* bar[0] and bar[1] track if buffers buffer_0 and buffer_1 are ready to be filled,
     while bar[2] and bar[3] track if buffers buffer_0 and buffer_1 are filled-in respectively */
  #pragma nv_diag_suppress static_var_with_dynamic_init
  __shared__ barrier_t bar[4];

  if (threadIdx.x < 4)
  {
    init(bar + threadIdx.x, blockDim.x);
  }
  __syncthreads();

  if (threadIdx.x < warpSize)
  { produce(bar, bar + 2, buffer, buffer_len, in, N); }
  else
  { consume(bar, bar + 2, buffer, buffer_len, out, N); }
}

#include <cuda/ptx>

__device__ void produce(barrier ready[], barrier filled[], float *buffer, int buffer_len, float *in, int N)
{
  for (int i = 0; i < N / buffer_len; ++i)
  {
    uint64_t token1 = cuda::ptx::mbarrier_arrive(ready[i % 2]);
    while(!cuda::ptx::mbarrier_try_wait(&ready[i % 2], token1)) {} /* wait for buffer_(i%2) to be ready to be filled */
    /* produce, i.e., fill in, buffer_(i%2)  */
    uint64_t token2 = cuda::ptx::mbarrier_arrive(&filled[i % 2]); /* buffer_(i%2) is filled */
  }
}

__device__ void consume(barrier ready[], barrier filled[], float *buffer, buffer_len, float *out, int N)
{
  uint64_t token1 = cuda::ptx::mbarrier_arrive(&ready[0]); /* buffer_0 is ready for initial fill */
  uint64_t token2 = cuda::ptx::mbarrier_arrive(&ready[1]); /* buffer_1 is ready for initial fill */
  for (int i = 0; i < N / buffer_len; ++i)
  {
    uint64_t token3 = cuda::ptx::mbarrier_arrive(&filled[i % 2]);
    while(!cuda::ptx::mbarrier_try_wait(&filled[i % 2], token3x)) {} /* wait for buffer_(i%2) to be filled */
    /* consume buffer_(i%2) */
    uint64_t token4 = cuda::ptx::mbarrier_arrive(&ready[i % 2]); /* buffer_(i%2) is ready to be re-filled */
  }
}

__global__ void producer_consumer_pattern(int N, float *in, float *out, int buffer_len)
{
  constexpr int warpSize = 32;

  /* Shared memory buffer declared below is of size 2 * buffer_len
     so that we can alternatively work between two buffers.
     buffer_0 = buffer and buffer_1 = buffer + buffer_len */
  __shared__ extern float buffer[];

  /* bar[0] and bar[1] track if buffers buffer_0 and buffer_1 are ready to be filled,
     while bar[2] and bar[3] track if buffers buffer_0 and buffer_1 are filled-in respectively */
  #pragma nv_diag_suppress static_var_with_dynamic_init
  __shared__ uint64_t bar[4];

  if (threadIdx.x < 4)
  {
    cuda::ptx::mbarrier_init(bar + block.thread_rank(), block.size());
  }
  __syncthreads();

  if (threadIdx.x < warpSize)
  {  produce(bar, bar + 2, buffer, buffer_len, in, N); }
  else

#include <cuda_awbarrier_primitives.h>

__device__ void produce(__mbarrier_t ready[], __mbarrier_t filled[], float *buffer, int buffer_len, float *in, int N)
{
  for (int i = 0; i < N / buffer_len; ++i)
  {
    __mbarrier_token_t token1 = __mbarrier_arrive(&ready[i % 2]); /* wait for buffer_(i%2) to be ready to be filled */
    while(!__mbarrier_try_wait(&ready[i % 2], token1, 1000)) {}
    /* produce, i.e., fill in, buffer_(i%2)  */
    __mbarrier_token_t token2 = __mbarrier_arrive(filled[i % 2]);  /* buffer_(i%2) is filled */
  }
}

__device__ void consume(__mbarrier_t ready[], __mbarrier_t filled[], float *buffer, int buffer_len, float *out, int N)
{
  __mbarrier_token_t token1 = __mbarrier_arrive(&ready[0]); /* buffer_0 is ready for initial fill */
  __mbarrier_token_t token2 = __mbarrier_arrive(&ready[1]); /* buffer_1 is ready for initial fill */
  for (int i = 0; i < N / buffer_len; ++i)
  {
    __mbarrier_token_t token3 = __mbarrier_arrive(&filled[i % 2]);
    while(!__mbarrier_try_wait(&filled[i % 2], token3, 1000)) {}
    /* consume buffer_(i%2) */
    __mbarrier_token_t token4 = __mbarrier_arrive(&ready[i % 2]); /* buffer_(i%2) is ready to be re-filled */
  }
}

__global__ void producer_consumer_pattern(int N, float *in, float *out, int buffer_len)
{
  constexpr int warpSize = 32;

  /* Shared memory buffer declared below is of size 2 * buffer_len
     so that we can alternatively work between two buffers.
     buffer_0 = buffer and buffer_1 = buffer + buffer_len */
  __shared__ extern float buffer[];

  /* bar[0] and bar[1] track if buffers buffer_0 and buffer_1 are ready to be filled,
     while bar[2] and bar[3] track if buffers buffer_0 and buffer_1 are filled-in respectively */
  #pragma nv_diag_suppress static_var_with_dynamic_init
  __shared__ __mbarrier_t bar[4];

  if (threadIdx.x < 4)
  {
    __mbarrier_init(bar + threadIdx.x, blockDim.x);
  }
  __syncthreads();

  if (threadIdx.x < warpSize)
  { produce(bar, bar + 2, buffer, buffer_len, in, N); }
  else
  { consume(bar, bar + 2, buffer, buffer_len, out, N); }
}

이 예제에서 첫 번째 워프는 프로듀서로 특화되고 나머지 워프들은 컨슈머로 특화됩니다. 모든 프로듀서 및 컨슈머 스레드는 네 개의 배리어 각각에 참여( bar.arrive() 또는 bar.arrive_and_wait() 호출)하므로 기대 도착 카운트는 block.size()와 같습니다.

프로듀서 스레드는 컨슈머 스레드가 공유 메모리 버퍼를 채울 수 있음을 신호할 때까지 기다립니다. 배리어에서 대기하려면, 프로듀서 스레드는 먼저 해당 ready[i%2].arrive()에서 도착하여 토큰을 얻고, 그 다음 그 토큰으로 ready[i%2].wait(token)를 수행해야 합니다. 단순화를 위해 ready[i%2].arrive_and_wait()는 이러한 연산을 결합합니다.

bar.arrive_and_wait();
/* is equivalent to */
bar.wait(bar.arrive());

프로듀서 스레드는 준비된 버퍼를 계산하고 채운 다음, 채워짐(filled) 배리어인 filled[i%2].arrive()에서 도착함으로써 버퍼가 채워졌음을 신호합니다. 프로듀서 스레드는 이 시점에서는 대기하지 않으며, 대신 다음 반복의 버퍼(더블 버퍼링)가 채워질 준비가 될 때까지 기다립니다.

컨슈머 스레드는 두 버퍼 모두가 채워질 준비가 되었음을 신호하는 것으로 시작합니다. 컨슈머 스레드는 이 시점에서는 대기하지 않으며, 대신 이번 반복의 버퍼가 채워질 때까지 filled[i%2].arrive_and_wait()에서 기다립니다. 컨슈머 스레드가 버퍼를 소비한 뒤에는, 버퍼가 다시 채워질 준비가 되었음을 ready[i%2].arrive()로 신호하고, 그 다음 다음 반복의 버퍼가 채워질 때까지 기다립니다.
