4.7. 지연 로딩

4.7.1. 소개#

지연 로딩은 CUDA 모듈을 필요할 때까지 로드를 기다림으로써 프로그램 초기화 시간을 줄입니다. 지연 로딩은 라이브러리를 사용할 때 흔히 그렇듯, 포함된 커널 중 소수만 사용하는 프로그램에 특히 효과적입니다. 지연 로딩은 CUDA 프로그래밍 모델을 따르면 사용자에게 보이지 않도록 설계되었습니다. 잠재적 위험에서 이를 자세히 설명합니다. CUDA 12.3부터 지연 로딩은 모든 플랫폼에서 기본적으로 활성화되어 있지만, CUDA_MODULE_LOADING 환경 변수를 통해 제어할 수 있습니다.

4.7.3. 지연 로딩을 위한 요구 사항#

지연 로딩은 CUDA 런타임과 드라이버의 공동 기능입니다. 지연 로딩은 런타임 및 드라이버 버전 요구 사항이 충족될 때만 사용할 수 있습니다.

4.7.3.1. CUDA 런타임 버전 요구 사항#

지연 로딩은 CUDA 런타임 버전 11.7부터 사용할 수 있습니다. CUDA 런타임은 일반적으로 프로그램과 라이브러리에 정적으로 링크되므로, CUDA 11.7+ 툴킷으로 제공되거나 컴파일된 프로그램과 라이브러리만 지연 로딩의 이점을 누릴 수 있습니다. 더 오래된 CUDA 런타임 버전을 사용해 컴파일된 라이브러리는 모든 모듈을 즉시(eagerly) 로드합니다.

4.7.3.2. CUDA 드라이버 버전 요구 사항#

지연 로딩에는 드라이버 버전 515 이상이 필요합니다. CUDA 툴킷 11.7 이상을 사용하더라도, 515보다 오래된 드라이버 버전에서는 지연 로딩을 사용할 수 없습니다.

4.7.3.3. 컴파일러 요구 사항#

지연 로딩에는 컴파일러 지원이 필요하지 않습니다. 11.7 이전 컴파일러로 컴파일된 SASS와 PTX 모두 지연 로딩이 활성화된 상태에서 로드될 수 있으며, 해당 기능의 모든 이점을 누릴 수 있습니다. 그러나 위에서 설명한 대로 11.7+ CUDA 런타임 버전은 여전히 필요합니다.

4.7.3.4. 커널 요구 사항#

지연 로딩은 관리 변수를 포함하는 모듈에는 영향을 주지 않으며, 이러한 모듈은 여전히 즉시(eagerly) 로드됩니다.

4.7.4. 사용법#

4.7.4.1. 활성화 및 비활성화#

지연 로딩은 CUDA_MODULE_LOADING 환경 변수를 LAZY로 설정하여 활성화됩니다. 지연 로딩은 CUDA_MODULE_LOADING 환경 변수를 EAGER로 설정하여 비활성화할 수 있습니다. CUDA 12.3부터 지연 로딩은 모든 플랫폼에서 기본적으로 활성화되어 있습니다.

4.7.4.2. 런타임에서 지연 로딩이 활성화되어 있는지 확인#

CUDA 드라이버 API의 cuModuleGetLoadingMode API를 사용하여 지연 로딩이 활성화되어 있는지 확인할 수 있습니다. 이 함수를 실행하기 전에 CUDA를 초기화해야 한다는 점에 유의하십시오. 예시 사용법은 아래 스니펫에 나와 있습니다.

#include "<cuda.h>"
#include "<assert.h>"
#include "<iostream>"

int main() {
        CUmoduleLoadingMode mode;

        assert(CUDA_SUCCESS == cuInit(0));
        assert(CUDA_SUCCESS == cuModuleGetLoadingMode(&mode));

        std::cout << "CUDA Module Loading Mode is " << ((mode == CU_MODULE_LAZY_LOADING) ? "lazy" : "eager") << std::endl;

        return 0;
}

4.7.4.3. 런타임에서 모듈을 즉시(eagerly) 로드하도록 강제#

커널과 변수의 로딩은 명시적 로딩이 전혀 필요 없이 자동으로 수행됩니다. 커널은 다음을 수행하여 실행하지 않고도 명시적으로 로드할 수 있습니다:

  • cuModuleGetFunction() 함수는 모듈이 디바이스 메모리에 로드되도록 합니다

  • cudaFuncGetAttributes() 함수는 커널이 디바이스 메모리에 로드되도록 합니다

참고

cuModuleLoad()는 모듈이 즉시 로드된다는 것을 보장하지 않습니다.

4.7.5. 잠재적 위험 요소#

지연 로딩은 이를 사용하기 위해 애플리케이션에 어떤 수정도 필요하지 않도록 설계되었습니다. 그렇지만 아래에 설명된 것처럼, 특히 애플리케이션이 CUDA 프로그래밍 모델을 완전히 준수하지 않는 경우 몇 가지 주의사항이 있습니다.

4.7.5.1. 동시 커널 실행에 미치는 영향#

일부 프로그램은 동시 커널 실행이 보장된다고 잘못 가정합니다. 커널 간 동기화가 필요하지만 커널 실행이 직렬화된 경우 데드락이 발생할 수 있습니다. 지연 로딩이 동시 커널 실행에 미치는 영향을 최소화하려면 다음을 수행하십시오:

  • 동시에 실행하기를 기대하는 모든 커널을 실행(launch)하기 전에 미리 로드하거나

  • 애플리케이션을 CUDA_MODULE_LOADING = EAGER와 함께 실행하여 각 함수가 즉시 로드되도록 강제하지 않으면서 데이터를 즉시(eagerly) 로드하도록 강제

4.7.5.2. 대규모 메모리 할당#

지연 로딩은 CUDA 모듈에 대한 메모리 할당을 프로그램 초기화 시점에서 실행 시점에 더 가까운 시점으로 지연시킵니다. 애플리케이션이 시작 시 전체 VRAM을 할당하면, CUDA가 런타임에 모듈을 위한 메모리 할당에 실패할 수 있습니다. 가능한 해결 방법:

  • 시작 시 전체 VRAM을 할당하는 할당자 대신 cudaMallocAsync()를 사용

  • 커널의 지연 로딩을 보상하기 위해 일부 버퍼를 추가

  • 할당자를 초기화하려고 시도하기 전에 프로그램에서 사용할 모든 커널을 미리 로드

4.7.5.3. 성능 측정에 미치는 영향#

지연 로딩은 CUDA 모듈 초기화를 측정된 실행 구간으로 이동시켜 성능 측정을 왜곡할 수 있습니다. 이를 피하려면:

  • 측정 전에 최소 한 번의 워밍업 반복을 수행

  • 벤치마크 대상 커널을 실행(launch)하기 전에 미리 로드
