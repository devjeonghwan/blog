4.4. 코오퍼러티브 그룹(Cooperative Groups)

4.4.1. 소개#

코오퍼러티브 그룹은 협업하는 스레드 그룹을 구성하기 위한 CUDA 프로그래밍 모델의 확장입니다. 코오퍼러티브 그룹은 스레드가 협업하는 세분성을 개발자가 제어할 수 있게 하여, 더 풍부하고 더 효율적인 병렬 분해를 표현하도록 돕습니다. 코오퍼러티브 그룹은 또한 스캔 및 병렬 리듀스 같은 일반적인 병렬 프리미티브의 구현을 제공합니다.

역사적으로 CUDA 프로그래밍 모델은 협업하는 스레드를 동기화하기 위한 단 하나의 간단한 구성을 제공해 왔습니다. 즉, __syncthreads() 인트린식 함수로 구현되는, 스레드 블록의 모든 스레드에 걸친 배리어입니다. 더 폭넓은 병렬 상호작용 패턴을 표현하려는 노력의 일환으로, 성능 지향 프로그래머들은 단일 워프 내에서, 또는 단일 GPU에서 실행되는 스레드 블록 집합 전반에서 스레드를 동기화하기 위해 자신만의 임시방편적이고 안전하지 않은 프리미티브를 작성하는 데 의존해 왔습니다. 달성된 성능 향상은 종종 가치가 있었지만, 그 결과 GPU 세대가 바뀌는 동안 시간이 지남에 따라 작성, 튜닝, 유지보수 비용이 많이 드는 취약한 코드의 컬렉션이 계속 늘어났습니다. 코오퍼러티브 그룹(Cooperative Groups)은 고성능 코드를 작성하기 위한 안전하고 미래 지향적인 메커니즘을 제공합니다.

전체 코오퍼러티브 그룹(Cooperative Groups) API는 코오퍼러티브 그룹(Cooperative Groups) API에서 확인할 수 있습니다.

4.4.2. 코오퍼러티브 그룹 핸들 및 멤버 함수#

코오퍼러티브 그룹(Cooperative Groups)은 코오퍼러티브 그룹 핸들을 통해 관리됩니다. 코오퍼러티브 그룹 핸들을 통해 참여 스레드는 그룹 내에서 자신의 위치, 그룹 크기 및 기타 그룹 정보를 알 수 있습니다. 선택된 그룹 멤버 함수는 다음 표에 나와 있습니다.

표 10 선택된 멤버 함수#

액세서

반환

thread_rank()

호출한 스레드의 랭크.

num_threads()

그룹 내 총 스레드 수 .

thread_index()

실행된 블록 내에서 스레드의 3차원 인덱스.

멤버 함수의 전체 목록은 코오퍼러티브 그룹(Cooperative Groups) API에서 확인할 수 있습니다.

4.4.3. 기본 동작 / 그룹 없는 실행#

그리드와 스레드 블록을 나타내는 그룹은 커널 실행 구성에 따라 암묵적으로 생성됩니다. 이러한 “암묵적” 그룹은 개발자가 더 세분화된 그룹으로 명시적으로 분해할 수 있는 출발점을 제공합니다. 암묵적 그룹은 다음 메서드를 사용하여 접근할 수 있습니다:

Table 11 CUDA 런타임에 의해 암묵적으로 생성되는 코오퍼러티브 그룹#

접근자

그룹 범위

this_thread_block()

현재 스레드 블록의 모든 스레드를 포함하는 그룹에 대한 핸들을 반환합니다.

this_grid()

그리드의 모든 스레드를 포함하는 그룹에 대한 핸들을 반환합니다.

워프(warp)에서 현재 활성인 스레드들의 그룹에 대한 핸들을 반환합니다.

현재 클러스터의 스레드 그룹에 대한 핸들을 반환합니다.

[2]

this_cluster()은 비클러스터 그리드가 실행될 때 1x1x1 클러스터를 가정합니다. Compute Capability 9.0 이상이 필요합니다.

추가 정보는 코오퍼러티브 그룹(Cooperative Groups) API에서 확인할 수 있습니다.

4.4.3.1. 암묵적 그룹 핸들을 가능한 한 빨리 생성#

최상의 성능을 위해, 암묵적 그룹에 대한 핸들을 사전에(가능한 한 이르게, 어떤 분기(branching)도 발생하기 전에) 생성하고 커널 전체에서 해당 핸들을 사용하기를 권장합니다.

4.4.3.2. 그룹 핸들은 참조로만 전달#

그룹 핸들을 함수에 전달할 때는, 함수에 그룹 핸들을 넘기는 경우 참조로 전달할 것을 권장합니다. 그룹 핸들은 기본 생성자가 없으므로 선언 시점에 초기화되어야 합니다. 그룹 핸들을 복사 생성(copy-construct)하는 것은 권장되지 않습니다.

4.4.4. 코오퍼러티브 그룹(Cooperative Groups) 생성#

그룹은 상위 그룹을 하위 그룹으로 분할하여 생성됩니다. 그룹이 분할되면, 결과로 생성된 하위 그룹을 관리하기 위한 그룹 핸들이 생성됩니다. 개발자가 사용할 수 있는 분할 연산은 다음과 같습니다:

Table 12 Cooperative Group 분할 연산#

분할 유형

설명

tiled_partition

상위 그룹을 1차원 행 우선(row-major) 형식으로 배치된 일련의 고정 크기 하위 그룹으로 분할합니다.

stride_partition

상위 그룹을 동일한 크기의 하위 그룹으로 분할하며, 스레드는 라운드 로빈 방식으로 하위 그룹에 할당됩니다.

labeled_partition

어떤 정수형도 될 수 있는 조건부 레이블을 기반으로 상위 그룹을 1차원 하위 그룹으로 분할합니다.

binary_partition

레이블이 “0” 또는 “1”만 될 수 있는 labeled partitioning의 특수한 형태입니다.

다음 예제는 타일 분할이 어떻게 생성되는지 보여줍니다:

namespace cg = cooperative_groups;
// Obtain the current thread's cooperative group
cg::thread_block my_group = cg::this_thread_block();

// Partition the cooperative group into tiles of size 8
cg::thread_block_tile<8> my_subgroup = cg::tiled_partition<8>(cta);

// do work as my_subgroup

사용하기에 가장 좋은 분할 전략은 문맥에 따라 달라집니다. 추가 정보는 코오퍼러티브 그룹(Cooperative Groups) API에서 확인할 수 있습니다.

4.4.4.1. 그룹 생성 시 위험 요소 방지#

그룹을 분할하는 것은 집합적 연산이며, 그룹 내의 모든 스레드가 참여해야 합니다. 모든 스레드가 도달하지 않는 조건 분기에서 그룹이 생성되었다면, 이는 데드록 또는 데이터 손상으로 이어질 수 있습니다.

4.4.5. 동기화#

코오퍼러티브 그룹이 도입되기 전에는 CUDA 프로그래밍 모델이 커널 완료 경계에서만 스레드 블록 간 동기화를 허용했습니다. 코오퍼러티브 그룹을 사용하면 개발자는 서로 협력하는 스레드 그룹을 다양한 세분성으로 동기화할 수 있습니다.

4.4.5.1. 동기화(Sync)#

집합적(collective)을 호출하여 그룹을 동기화할 수 있습니다. sync() 함수. 예를 들어 __syncthreads(), 그 sync() function은 다음을 보장합니다: - 동기화 지점 이전에 그룹 내 스레드가 수행한 모든 메모리 접근(예: 읽기 및 쓰기)은 동기화 지점 이후에 그룹 내 모든 스레드에서 볼 수 있습니다. - 어떤 스레드도 그 지점을 넘어 진행할 수 있기 전에, 그룹 내 모든 스레드가 동기화 지점에 도달합니다.

다음 예제는 cooperative_groups::sync() 와 동등한 __syncthreads().

namespace cg = cooperative_groups;

cg::thread_block my_group = cg::this_thread_block();

// Synchronize threads in the block
cg::sync(my_group);

코오퍼러티브 그룹은 전체 그리드를 동기화하는 데 사용할 수 있습니다. CUDA 13부터 코오퍼러티브 그룹은 더 이상 멀티 디바이스 동기화에 사용할 수 없습니다. 자세한 내용은 대규모 그룹 섹션을 참조하세요.

동기화에 대한 추가 정보는 코오퍼러티브 그룹(Cooperative Groups) API에서 확인할 수 있습니다.

4.4.5.2. 배리어(Barrier)#

코오퍼러티브 그룹은 보다 고급 동기화에 사용할 수 있는 cuda::barrier와 유사한 배리어 API를 제공합니다. 코오퍼러티브 그룹 배리어 API는 몇 가지 핵심적인 측면에서 cuda::barrier와 다릅니다: - 코오퍼러티브 그룹 배리어는 자동으로 초기화됩니다 - 그룹의 모든 스레드는 단계(phase)당 한 번, 배리어에 도달하고(arrive) 배리어에서 대기(wait)해야 합니다. - barrier_arrive는 arrival_token 객체를 반환하며, 이는 해당하는 barrier_wait에 전달되어야 합니다. 여기에서 객체는 소모(consumed)되며 다시 사용할 수 없습니다.

프로그래머는 코오퍼러티브 그룹 배리어를 사용할 때 위험 요소를 피하도록 주의해야 합니다: - barrier_arrive를 호출한 이후부터 barrier_wait를 호출하기 전까지, 그룹은 어떤 집합적 연산도 사용할 수 없습니다. - barrier_wait는 그룹의 모든 스레드가 barrier_arrive를 호출했음을 보장할 뿐입니다. barrier_wait는 모든 스레드가 barrier_wait를 호출했음을 보장하지 않습니다.

namespace cg = cooperative_groups;

cg::thread_block my_group = this_block();

auto token = cluster.barrier_arrive();

// Optional: Do some local processing to hide the synchronization latency
local_processing(block);

// Make sure all other blocks in the cluster are running and initialized shared data before accessing dsmem
cluster.barrier_wait(std::move(token));

4.4.6. 집합적 연산#

코오퍼러티브 그룹에는 스레드 그룹이 수행할 수 있는 집합적 연산(collective operations) 집합이 포함되어 있습니다. 이러한 연산은 연산을 완료하기 위해 지정된 그룹의 모든 스레드가 참여해야 합니다.

코오퍼러티브 그룹(Cooperative Groups) API에서 서로 다른 값이 명시적으로 허용되는 경우를 제외하면, 그룹의 모든 스레드는 각 집합적 호출에 대해 해당 인자에 동일한 값을 전달해야 합니다. 그렇지 않으면 호출의 동작은 정의되지 않습니다.

4.4.6.1. 리듀스(Reduce)#

The reduce 함수는 지정된 그룹의 각 스레드가 제공하는 데이터에 대해 병렬 리듀션을 수행하는 데 사용됩니다. 리듀션의 유형은 다음 표에 표시된 연산자 중 하나를 제공하여 지정해야 합니다.

Table 13 코오퍼러티브 그룹 리덕션 연산자#

연산자

반환값

plus

그룹 내 모든 값의 합

less

최소값

greater

최대값

bit_and

비트 AND 리덕션

bit_or

비트 OR 리덕션

bit_xor

비트 XOR 리덕션

가능한 경우 리덕션에 하드웨어 가속이 사용됩니다(Compute Capability 8.0 이상 필요). 하드웨어 가속을 사용할 수 없는 구형 하드웨어를 위한 소프트웨어 폴백이 제공됩니다. 하드웨어로 가속되는 것은 4B 타입만입니다.

리덕션에 대한 추가 정보는 코오퍼러티브 그룹(Cooperative Groups) API에서 확인할 수 있습니다.

다음 예제는 스레드 블록 전체 합 리덕션을 수행하기 위해 cooperative_groups::reduce()를 사용하는 방법을 보여줍니다.

namespace cg = cooperative_groups;

cg::thread_block my_group = cg::this_thread_block();

int val = data[threadIdx.x];

int sum = cg::reduce(cta, val, cg::plus<int>());

// Store the result from the reduction
if (my_group.thread_rank() == 0) {
   result[blockIdx.x] = sum;
}

4.4.6.2. 스캔(Scans)#

코오퍼러티브 그룹에는 임의의 그룹 크기에서 사용할 수 있는 inclusive_scan 및 exclusive_scan 구현이 포함되어 있습니다. 이 function들은 지정된 그룹에서 이름이 지정된 각 스레드가 제공한 데이터에 대해 스캔 연산을 수행합니다.

프로그래머는 선택적으로, 위의 Reduction Operators Table에 나열된 리덕션 연산자를 지정할 수 있습니다.

namespace cg = cooperative_groups;

cg::thread_block my_group = cg::this_thread_block();

int val = data[my_group.thread_rank()];

int exclusive_sum = cg::exclusive_scan(my_group, val, cg::plus<int>());

result[my_group.thread_rank()] = exclusive_sum;

스캔에 대한 추가 정보는 코오퍼러티브 그룹 스캔 API에서 확인할 수 있습니다.

4.4.6.3. Invoke One#

코오퍼러티브 그룹은 그룹을 대신해 단일 스레드가 작업의 직렬 부분을 수행해야 할 때 사용할 수 있는 invoke_one 함수를 제공합니다. - invoke_one는 호출 그룹에서 임의의 단일 스레드를 선택하고, 제공된 인자를 사용하여 제공된 invocable function을 호출하는 데 해당 스레드를 사용합니다. - invoke_one_broadcast는 호출 결과가 그룹 내 모든 스레드로 브로드캐스트된다는 점을 제외하면 invoke_one와 동일합니다.

스레드 선택 메커니즘은 결정적(deterministic)임이 보장되지 않습니다.

다음 예제는 invoke_one의 기본 사용법을 보여줍니다.

namespace cg = cooperative_groups;
cg::thread_block my_group = cg::this_thread_block();

// Ensure only one thread in the thread block prints the message
cg::invoke_one(my_group, []() {
   printf("Hello from one thread in the block!");
});

// Synchronize to make sure all threads wait until the message is printed
cg::sync(my_group);

invocable function 내부에서는 호출 그룹 내에서의 통신 또는 동기화가 허용되지 않습니다. 호출 그룹 밖의 스레드와의 통신은 허용됩니다.

4.4.7. 비동기 데이터 이동#

CUDA의 코오퍼러티브 그룹 memcpy_async 기능은 전역 메모리와 공유 메모리 사이에서 비동기 메모리 복사를 수행하는 방법을 제공합니다. memcpy_async는 특히 메모리 전송을 최적화하고, 성능을 개선하기 위해 데이터 전송과 연산을 오버랩하는 데 유용합니다.

memcpy_async function은 전역 메모리에서 공유 메모리로의 비동기 로드를 시작하는 데 사용됩니다. memcpy_async는 데이터가 필요해지기 전에 로드하는 “프리페치(prefetch)”처럼 사용되도록 의도되었습니다.

wait function은 그룹의 모든 스레드가 비동기 메모리 전송이 완료될 때까지 기다리도록 강제합니다. 공유 메모리에서 데이터에 접근하기 전에 그룹의 모든 스레드가 wait를 호출해야 합니다.

다음 예제는 데이터를 프리페치하기 위해 memcpy_async 및 wait를 사용하는 방법을 보여줍니다.

namespace cg = cooperative_groups;

cg::thread_group my_group = cg::this_thread_block();

__shared__ int shared_data[];

// Perform an asynchronous copy from global memory to shared memory
cg::memcpy_async(my_group, shared_data + my_group.rank(), input + my_group.rank(), sizeof(int));

// Hide latency by doing work here. Cannot use shared_data

// Wait for the asynchronous copy to complete
cg::wait(my_group);

// Prefetched data is now available

자세한 내용은 코오퍼러티브 그룹(Cooperative Groups) API를 참조하세요.

4.4.7.1. Memcpy Async 정렬 요구 사항#

memcpy_async는 소스가 전역 메모리이고 대상이 공유 메모리이며, 둘 다 최소 4바이트 정렬인 경우에만 비동기입니다. 최상의 성능을 얻기 위해: 공유 메모리와 전역 메모리 모두에 대해 16바이트 정렬을 권장합니다.

4.4.8. 대규모 그룹#

코오퍼러티브 그룹은 전체 그리드에 걸치는 대규모 그룹을 허용합니다. 이전에 설명한 모든 코오퍼러티브 그룹 기능을 이러한 대규모 그룹에서 사용할 수 있으며, 한 가지 주목할 만한 예외가 있습니다: 전체 그리드를 동기화하려면 cudaLaunchCooperativeKernel 런타임 실행 API를 사용해야 합니다.

코오퍼러티브 그룹을 위한 멀티 디바이스 실행 API 및 관련 참조는 CUDA 13부터 제거되었습니다.

4.4.8.1. cudaLaunchCooperativeKernel를 사용해야 하는 경우#

cudaLaunchCooperativeKernel는 cooperative groups를 사용하는 단일 디바이스 커널을 실행하는 데 사용되는 CUDA 런타임 API function이며, 특히 블록 간 동기화가 필요한 커널을 실행하도록 설계되었습니다. 이 function은 커널의 모든 스레드가 전체 그리드에 걸쳐 동기화하고 협력할 수 있도록 보장하는데, 이는 개별 스레드 블록 내에서만 동기화를 허용하는 기존 CUDA 커널로는 불가능합니다. cudaLaunchCooperativeKernel는 커널 실행이 아토믹(atomic)임을 보장합니다. 즉, API 호출이 성공하면 제공된 스레드 블록 수가 지정된 디바이스에서 실행됩니다.

먼저 디바이스 속성 cudaDevAttrCooperativeLaunch를 쿼리하여 디바이스가 cooperative launch를 지원하는지 확인하는 것이 좋은 관행입니다:

int dev = 0;
int supportsCoopLaunch = 0;
cudaDeviceGetAttribute(&supportsCoopLaunch, cudaDevAttrCooperativeLaunch, dev);

이는 디바이스 0에서 해당 속성이 지원되는 경우 supportsCoopLaunch를 1로 설정합니다. Compute Capability 6.0 이상을 가진 디바이스만 지원됩니다. 또한 다음 중 하나에서 실행 중이어야 합니다:

  • MPS가 없는 Linux 플랫폼

  • MPS가 있는 Linux 플랫폼이며 Compute Capability 7.0 이상인 디바이스

  • 최신 Windows 플랫폼
