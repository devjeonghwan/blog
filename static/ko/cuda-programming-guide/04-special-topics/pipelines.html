4.10. 파이프라인

고급 동기화 프리미티브에서 소개된 파이프라인은 작업을 스테이징하고 다중 버퍼 생산자–소비자 패턴을 조정하기 위한 메커니즘으로, 일반적으로 비동기 데이터 복사와 연산을 오버랩하는 데 사용됩니다.

이 섹션에서는 주로 cuda::pipeline API를 통해 파이프라인을 사용하는 방법에 대한 세부 사항을 제공합니다(해당되는 경우 프리미티브에 대한 안내 포함).

4.10.1. 초기화#

cuda::pipeline는 서로 다른 스레드 범위에서 생성할 수 있습니다. cuda::thread_scope_thread 이외의 범위에서는, 참여하는 스레드들을 조정하기 위해 cuda::pipeline_shared_state<scope, count> 객체가 필요합니다. 이 상태는 파이프라인이 최대 count개의 동시 스테이지를 처리할 수 있게 하는 유한한 리소스를 캡슐화합니다.

// Create a pipeline at thread scope
constexpr auto scope = cuda::thread_scope_thread;
cuda::pipeline<scope> pipeline = cuda::make_pipeline();

// Create a pipeline at block scope
constexpr auto scope = cuda::thread_scope_block;
constexpr auto stages_count = 2;
__shared__ cuda::pipeline_shared_state<scope, stages_count> shared_state;
auto pipeline = cuda::make_pipeline(group, &shared_state);

파이프라인은 통합(unified) 또는 분할(partitioned)일 수 있습니다. 통합 파이프라인에서는 참여하는 모든 스레드가 생산자이자 소비자입니다. 분할 파이프라인에서는 각 참여 스레드가 생산자 또는 소비자 중 하나이며, 그 역할은 파이프라인 객체의 생애 동안 변경될 수 없습니다. 스레드-로컬 파이프라인은 분할될 수 없습니다. 분할 파이프라인을 생성하려면, cuda::make_pipeline()에 생산자 수 또는 스레드의 역할 중 하나를 제공해야 합니다.

// Create a partitioned pipeline at block scope where only thread 0 is a producer
constexpr auto scope = cuda::thread_scope_block;
constexpr auto stages_count = 2;
__shared__ cuda::pipeline_shared_state<scope, stages_count> shared_state;
auto thread_role = (group.thread_rank() == 0) ? cuda::pipeline_role::producer : cuda::pipeline_role::consumer;
auto pipeline = cuda::make_pipeline(group, &shared_state, thread_role);

분할을 지원하기 위해, 공유 cuda::pipeline 추가 오버헤드가 발생하며, 여기에는 동기화를 위해 단계(stage)당 공유 메모리 배리어(barrier) 세트를 사용하는 것이 포함됩니다. 이는 파이프라인이 통합(unified)되어 있고 사용할 수 있는 경우에도 사용됩니다. __syncthreads() 대신. 따라서 가능하다면 이러한 오버헤드를 피할 수 있는 스레드-로컬 파이프라인을 사용하는 것이 바람직합니다.

4.10.2. 작업 제출#

파이프라인 단계에 작업을 커밋하는 데에는 다음이 포함됩니다:

  • 집합적으로 획득 파이프라인 헤드 생산자 스레드 집합에서 다음을 사용하여 pipeline.producer_acquire().

  • 비동기 작업을 제출하는 것(예: memcpy_async, 파이프라인 헤드에.

  • 집합적으로 커밋 (전진시키며) 다음을 사용하여 파이프라인 헤드를 pipeline.producer_commit().

모든 리소스가 사용 중이면, pipeline.producer_acquire() 소비자 스레드가 다음 파이프라인 단계의 리소스를 해제할 때까지 생산자 스레드를 블록합니다.

4.10.3. 작업 소비#

이전에 커밋된 단계(stage)에서 작업을 소비하는 데에는 다음이 포함됩니다:

  • 집합적으로 단계(stage)가 완료될 때까지 대기하는 것(예: 다음을 사용하는 경우) pipeline.consumer_wait() 소비자 스레드 집합에서 테일(가장 오래된) 단계에서 대기하기 위해.

  • 집합적으로 해제 다음을 사용하여 단계를 pipeline.consumer_release().

cuda::pipeline<cuda:thread_scope_thread>를 사용하면 cuda::pipeline_consumer_wait_prior<N>() friend 함수도 사용하여 마지막 N개 단계를 제외한 모든 단계가 완료될 때까지 대기할 수 있으며, 이는 프리미티브 API의 __pipeline_wait_prior(N)과 유사합니다.

4.10.4. 워프 얽힘#

파이프라인 메커니즘은 동일한 워프 내의 CUDA 스레드들 사이에서 공유됩니다. 이러한 공유로 인해 제출된 작업 시퀀스가 워프 내부에서 얽히게 되며, 특정 상황에서는 성능에 영향을 미칠 수 있습니다.

커밋. 커밋 작업은 병합(coalesced)되어, 커밋 작업을 호출하는 모든 수렴(converged)된 스레드에 대해 파이프라인의 시퀀스가 한 번만 증가하고, 이들이 제출한 작업들이 함께 배치됩니다. 워프가 완전히 수렴되어 있다면 시퀀스는 1만큼 증가하고 제출된 모든 작업은 파이프라인의 동일한 스테이지에 배치됩니다. 워프가 완전히 발산(diverged)되어 있다면 시퀀스는 32만큼 증가하고 제출된 모든 작업은 서로 다른 스테이지로 분산됩니다.

  • PB를 워프 공유 파이프라인의 실제 작업 시퀀스라고 하겠습니다.

    PB = {BP0, BP1, BP2, …, BPL}

  • TB를 스레드의 인지된 작업 시퀀스라고 하겠습니다. 이는 시퀀스가 이 스레드의 커밋 작업 호출에 의해서만 증가하는 것처럼 간주한 것입니다.

    TB = {BT0, BT1, BT2, …, BTL}

pipeline::producer_commit()의 반환 값은 스레드의 인지된 배치 시퀀스에서 가져온 것입니다.

  • 스레드의 인지된 시퀀스에서의 인덱스는 항상 실제 워프 공유 시퀀스에서의 동일하거나 더 큰 인덱스에 정렬됩니다. 시퀀스가 동일해지는 경우는 모든 커밋 작업이 완전히 수렴된 스레드들에서 호출될 때뿐입니다.

    BTn ≡ BPm 여기서 n <= m

예를 들어, 워프가 완전히 발산되어 있을 때:

  • 워프 공유 파이프라인의 실제 시퀀스는 다음과 같습니다: PB = {0, 1, 2, 3, ..., 31} (PL=31).

  • 이 워프의 각 스레드에 대한 인지된 시퀀스는 다음과 같습니다:

    • 스레드 0: TB = {0} (TL=0)

    • 스레드 1: TB = {0} (TL=0)

    • …

    • 스레드 31: TB = {0} (TL=0)

대기. CUDA 스레드가 호출합니다 pipeline::consumer_wait() 또는 pipeline_consumer_wait_prior<N>() 배치들이 다음에서 대기하도록 인지된 시퀀스 TB 완료될 때까지. 유의하십시오 pipeline::consumer_wait() 와 동등합니다 pipeline_consumer_wait_prior<N>(), 여기서 N = PL.

wait prior 변형은 실제 시퀀스에서 최소한 PL-N까지(이를 포함하여) 배치들을 기다립니다. TL <= PL이므로, PL-N까지(이를 포함하여) 배치를 기다리는 것은 배치 TL-N을 기다리는 것까지 포함합니다. 따라서 TL < PL일 때, 스레드는 의도치 않게 추가적인, 더 최근의 배치들을 기다리게 됩니다. 위의 극단적인 완전 발산 워프 예시에서는, 각 스레드가 32개 배치 전체를 기다릴 수 있습니다.

참고

실제 시퀀스와 스레드들이 인지하는 배치 시퀀스를 정렬된 상태로 유지하여 과도하게 기다리지 않도록, 커밋 호출은 수렴(converged)된 스레드들에 의해 이루어지는 것이 권장됩니다.

이러한 작업에 앞선 코드가 스레드들을 발산(diverge)시키는 경우, 커밋 작업을 호출하기 전에 __syncwarp를 통해 워프를 다시 수렴(re-converge)시켜야 합니다.

4.10.5. 조기 종료#

파이프라인에 참여하는 스레드가 조기에 종료해야 하는 경우, 해당 스레드는 cuda::pipeline::quit()를 사용하여 종료하기 전에 참여를 명시적으로 중단(drop out)해야 합니다. 남아 있는 참여 스레드들은 이후 작업을 정상적으로 진행할 수 있습니다.

4.10.6. 비동기 메모리 작업 추적#

다음 예제는 복사 작업을 추적하기 위해 파이프라인을 사용하여 비동기 메모리 복사를 통해 전역 메모리에서 공유 메모리로 데이터를 집합적으로 복사하는 방법을 보여줍니다. 각 스레드는 자체 파이프라인을 사용하여 메모리 복사를 독립적으로 제출한 다음, 완료될 때까지 대기하고 데이터를 소비합니다. 비동기 데이터 복사에 대한 자세한 내용은 섹션 3.2.5를 참조하십시오.

#include <cuda/pipeline>

__global__ void example_kernel(const float *in)
{
    constexpr int block_size = 128;
    __shared__ __align__(sizeof(float)) float buffer[4 * block_size];

    // Create a unified pipeline per thread
    cuda::pipeline<cuda::thread_scope_thread> pipeline = cuda::make_pipeline();

    // First stage of memory copies
    pipeline.producer_acquire();
    // Every thread fetches one element of the first block
    cuda::memcpy_async(buffer, in, sizeof(float), pipeline);
    pipeline.producer_commit();

    // Second stage of memory copies
    pipeline.producer_acquire();
    // Every thread fetches one element of the second and third block
    cuda::memcpy_async(buffer + block_size, in + block_size, sizeof(float), pipeline);
    cuda::memcpy_async(buffer + 2 * block_size, in + 2 * block_size, sizeof(float), pipeline);
    pipeline.producer_commit();

    // Third stage of memory copies
    pipeline.producer_acquire();
    // Every thread fetches one element of the last block
    cuda::memcpy_async(buffer + 3 * block_size, in + 3 * block_size, sizeof(float), pipeline);
    pipeline.producer_commit();

    // Wait for the oldest stage (waits for first stage)
    pipeline.consumer_wait();
    pipeline.consumer_release();

    // __syncthreads();
    // Use data from the first stage

    // Wait for the oldest stage (waits for second stage)
    pipeline.consumer_wait();
    pipeline.consumer_release();

    // __syncthreads();
    // Use data from the second stage

    // Wait for the oldest stage (waits for third stage)
    pipeline.consumer_wait();
    pipeline.consumer_release();

    // __syncthreads();
    // Use data from the third stage
}

#include <cuda_pipeline.h>

__global__ void example_kernel(const float *in)
{
    constexpr int block_size = 128;
    __shared__ __align__(sizeof(float)) float buffer[4 * block_size];

    // First batch of memory copies
    // Every thread fetches one element of the first block
    __pipeline_memcpy_async(buffer, in, sizeof(float));
    __pipeline_commit();

    // Second batch of memory copies
    // Every thread fetches one element of the second and third block
    __pipeline_memcpy_async(buffer + block_size, in + block_size, sizeof(float));
    __pipeline_memcpy_async(buffer + 2 * block_size, in + 2 * block_size, sizeof(float));
    __pipeline_commit();

    // Third batch of memory copies
    // Every thread fetches one element of the last block
    __pipeline_memcpy_async(buffer + 3 * block_size, in + 3 * block_size, sizeof(float));
    __pipeline_commit();

    // Wait for all except the last two batches of memory copies (waits for first batch)
    __pipeline_wait_prior(2);

    // __syncthreads();
    // Use data from the first batch

    // Wait for all except the last batch of memory copies (waits for second batch)
    __pipeline_wait_prior(1);

    // __syncthreads();
    // Use data from the second batch

    // Wait for all batches of memory copies (waits for third batch)
    __pipeline_wait_prior(0);

    // __syncthreads();
    // Use data from the last batch
}

4.10.7. 파이프라인을 사용한 프로듀서-컨슈머 패턴#

섹션 4.9.7에서는 비동기 배리어를 사용하여 프로듀서-컨슈머 패턴을 구현할 수 있도록 스레드 블록을 공간적으로 분할하는 방법을 보여주었습니다. cuda::pipeline를 사용하면, 버퍼당 두 개의 비동기 배리어 대신 데이터 버퍼당 하나의 스테이지를 갖는 단일 분할(partitioned) 파이프라인을 사용하여 이를 단순화할 수 있습니다.

#include <cuda/pipeline>
#include <cooperative_groups.h>

#pragma nv_diag_suppress static_var_with_dynamic_init

using pipeline = cuda::pipeline<cuda::thread_scope_block>;

__device__ void produce(pipeline &pipe, int num_stages, int stage, int num_batches, int batch, float *buffer, int buffer_len, float *in, int N)
{
  if (batch < num_batches)
  {
    pipe.producer_acquire();
    /* copy data from in(batch) to buffer(stage) using asynchronous memory copies */
    pipe.producer_commit();
  }
}

__device__ void consume(pipeline &pipe, int num_stages, int stage, int num_batches, int batch, float *buffer, int buffer_len, float *out, int N)
{
  pipe.consumer_wait();
  /* consume buffer(stage) and update out(batch) */
  pipe.consumer_release();
}

__global__ void producer_consumer_pattern(float *in, float *out, int N, int buffer_len)
{
  auto block = cooperative_groups::this_thread_block();

  /* Shared memory buffer declared below is of size 2 * buffer_len
     so that we can alternatively work between two buffers.
     buffer_0 = buffer and buffer_1 = buffer + buffer_len */
  __shared__ extern float buffer[];

  const int num_batches = N / buffer_len;

  // Create a partitioned pipeline with 2 stages where half the threads are producers and the other half are consumers.
  constexpr auto scope = cuda::thread_scope_block;
  constexpr int num_stages = 2;
  cuda::std::size_t producer_count = block.size() / 2;
  __shared__ cuda::pipeline_shared_state<scope, num_stages> shared_state;
  pipeline pipe = cuda::make_pipeline(block, &shared_state, producer_count);

  // Fill the pipeline
  if (block.thread_rank() < producer_count)
  {
    for (int s = 0; s < num_stages; ++s)
    {
      produce(pipe, num_stages, s, num_batches, s, buffer, buffer_len, in, N);
    }
  }

  // Process the batches
  int stage = 0;
  for (size_t b = 0; b < num_batches; ++b)
  {
    if (block.thread_rank() < producer_count)
    {
      // Prefetch the next batch
      produce(pipe, num_stages, stage, num_batches, b + num_stages, buffer, buffer_len, in, N);
    }
    else
    {
      // Consume the oldest batch
      consume(pipe, num_stages, stage, num_batches, b, buffer, buffer_len, out, N);
    }
    stage = (stage + 1) % num_stages;
  }
}

이 예제에서는 스레드 블록 내 스레드의 절반을 프로듀서로, 나머지 절반을 컨슈머로 사용합니다. 첫 번째 단계로, 우리는 생성해야 합니다 cuda::pipeline 객체를 생성해야 합니다. 일부 스레드를 프로듀서로, 일부 스레드를 컨슈머로 사용하려고 하므로, 우리는 사용해야 합니다 분할(partitioned) 파이프라인을 사용하여 cuda::thread_scope_block. 분할(partitioned) 파이프라인에는 cuda::pipeline_shared_state 참여 스레드들을 조정하기 위해. 스레드 블록 범위에서 2-스테이지 파이프라인의 상태를 초기화한 다음 호출합니다 cuda::make_pipeline(). 다음으로, 프로듀서 스레드들은 다음으로부터의 비동기 복사를 제출하여 파이프라인을 채웁니다 in 로 buffer. 이 시점에서 모든 데이터 복사 작업이 진행 중입니다. 마지막으로, 메인 루프에서 모든 데이터 배치를 순회하며, 스레드가 프로듀서인지 컨슈머인지에 따라 미래 배치를 위한 또 다른 비동기 복사를 제출하거나 현재 배치를 소비합니다.
