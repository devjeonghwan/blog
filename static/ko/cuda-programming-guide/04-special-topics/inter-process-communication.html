4.15. 프로세스 간 통신

서로 다른 호스트 프로세스가 관리하는 여러 GPU 간 통신은 프로세스 간 통신(IPC) API 및 IPC 공유 가능 메모리 버퍼를 사용하고, 이후 피어 GPU의 디바이스 메모리에 대한 프로세스 로컬 디바이스 포인터를 얻는 데 사용되는 프로세스 이식 가능 핸들을 생성함으로써 지원됩니다.

호스트 스레드가 생성한 모든 디바이스 메모리 포인터 또는 이벤트 핸들은 동일한 프로세스 내의 다른 어떤 스레드에서도 직접 참조할 수 있습니다. 하지만 디바이스 포인터 또는 이벤트 핸들은 이를 생성한 프로세스 밖에서는 유효하지 않으므로, 다른 프로세스에 속한 스레드가 직접 참조할 수는 없습니다. 프로세스 간에 디바이스 메모리와 CUDA 이벤트에 액세스하려면, 애플리케이션은 표준 호스트 운영체제 IPC 메커니즘(예: 프로세스 간 공유 메모리 또는 파일)을 사용해 다른 프로세스와 공유할 수 있는 프로세스 이식 가능 핸들을 생성하기 위해 CUDA 프로세스 간 통신(IPC) 또는 가상 메모리 관리 API를 사용해야 합니다. 프로세스들 간에 프로세스 이식 가능 핸들이 교환되면, CUDA IPC 또는 VMM API를 사용하여 해당 핸들로부터 프로세스 로컬 디바이스 포인터를 얻어야 합니다. 그런 다음 프로세스 로컬 디바이스 포인터는 단일 프로세스 내에서와 동일하게 사용할 수 있습니다.

단일 노드 및 단일 운영체제 인스턴스 내 IPC에 사용되는 것과 같은 유형의 이식 가능 핸들 접근 방식은 멀티 노드 NVLink로 연결된 클러스터에서 GPU 간 피어 투 피어 통신에도 사용됩니다. 멀티 노드의 경우, 통신하는 GPU는 각 클러스터 노드의 독립적인 운영체제 인스턴스 내에서 실행되는 프로세스에 의해 관리되므로, 운영체제 인스턴스 수준보다 한 단계 높은 추가 추상화가 필요합니다. 멀티 노드 피어 통신은 멀티 노드 GPU 피어 간에 소위 “패브릭(fabric)” 핸들을 생성하고 교환한 다음, 멀티 노드 랭크에 해당하는 참여 프로세스 및 운영체제 인스턴스 내에서 프로세스 로컬 디바이스 포인터를 얻는 방식으로 달성됩니다.

GPU 통신을 위한 프로세스 로컬 디바이스 포인터를 얻는 데 사용되는 프로세스 이식 가능 핸들 및 노드 및 운영체제 인스턴스 이식 가능 핸들을 설정하고 교환하는 데 사용되는 구체적인 API는 아래(단일 노드 CUDA IPC) 및 ref::virtual-memory-management를 참조하십시오.

참고

IPC에 사용할 때 CUDA IPC API와 가상 메모리 관리(VMM) API를 사용하는 것에는 각각의 장점과 제한 사항이 있습니다.

CUDA IPC API는 현재 Linux 플랫폼에서만 지원됩니다.

CUDA 가상 메모리 관리 API는 메모리 할당 시점에 피어 접근성 및 공유에 대해 할당 단위(per-allocation) 제어를 허용하지만, CUDA 드라이버 API를 사용해야 합니다.

4.15.1. 레거시 프로세스 간 통신 API를 사용한 IPC#

프로세스 간에 디바이스 메모리 포인터와 이벤트를 공유하려면, 애플리케이션은 참조 매뉴얼에 자세히 설명된 CUDA 프로세스 간 통신 API를 사용해야 합니다. IPC API를 사용하면 애플리케이션이 cudaIpcGetMemHandle()을 사용하여 주어진 디바이스 메모리 포인터에 대한 IPC 핸들을 얻을 수 있습니다. CUDA IPC 핸들은 표준 호스트 운영체제 IPC 메커니즘(예: 프로세스 간 공유 메모리 또는 파일)을 사용해 다른 프로세스로 전달할 수 있습니다. cudaIpcOpenMemHandle()은 IPC 핸들을 사용하여 다른 프로세스 내에서 사용할 수 있는 유효한 디바이스 포인터를 검색합니다. 이벤트 핸들은 유사한 엔트리 포인트를 사용하여 공유할 수 있습니다.

IPC API 사용 예시는 단일 주 프로세스가 입력 데이터 배치를 생성하고, 재생성이나 복사 없이 그 데이터를 여러 보조 프로세스에서 사용할 수 있도록 만드는 경우입니다.

참고

IPC API는 Linux에서만 지원됩니다.

IPC API는 cudaMallocManaged 할당에 대해서는 지원되지 않습니다.

서로 통신하기 위해 CUDA IPC를 사용하는 애플리케이션은 동일한 CUDA 드라이버 및 런타임으로 컴파일, 링크 및 실행해야 합니다.

cudaMalloc()에 의해 수행된 할당은 성능상의 이유로 더 큰 메모리 블록에서 서브 할당될 수 있습니다. 이 경우 CUDA IPC API는 기반이 되는 전체 메모리 블록을 공유하게 되며, 그 결과 다른 서브 할당도 공유될 수 있어 프로세스 간 정보 노출로 이어질 가능성이 있습니다. 이 동작을 방지하기 위해 2MiB 정렬 크기를 갖는 할당만 공유할 것을 권장합니다.

L4T 및 컴퓨트 기능 7.x 이상을 갖는 임베디드 Linux Tegra 디바이스에서는 IPC 이벤트 공유 API만 지원됩니다. IPC 메모리 공유 API는 Tegra 플랫폼에서 지원되지 않습니다.

4.15.2. Virtual Memory Management API를 사용한 IPC#

CUDA Virtual Memory Management API를 사용하면 IPC 공유 가능한 메모리 할당을 생성할 수 있으며, 운영체제별 IPC 핸들 데이터 구조를 통해 여러 운영체제를 지원합니다.
