4.19. API와의 CUDA 상호운용성

CUDA에서 API를 통해 GPU 데이터에 직접 접근하면 CUDA 커널로 해당 데이터를 읽고 쓸 수 있으며, 이를 통해 다른 API에서 이를 소비하면서도 CUDA 기능을 제공할 수 있습니다. 두 가지 주요 개념이 있습니다. 하나는 직접 접근 방식으로, openGL 및 Direct3D[9-11]와의 Graphics Interoperability이며, 이를 통해 OpenGL과 Direct3D의 리소스를 CUDA 주소 공간으로 매핑할 수 있습니다. 다른 하나는 더 유연한 External resource interoperability로, OS 수준 핸들을 통해 가져오기 및 내보내기를 수행하여 메모리 및 동기화 객체에 접근할 수 있습니다. 이는 Direct3D[11-12], Vulkan 및 NVIDIA Software Communication Interface Interoperability에 대해 지원됩니다.

4.19.1. Graphics Interoperability#

Direct3D 또는 openGL 리소스(예: VBO(vertex buffer object))에 CUDA로 접근하기 전에, 해당 리소스는 등록되고 매핑되어야 합니다. 아래 예시를 참고하면, 해당 CUDA 함수로 등록하면 struct cudaGraphicsResource 유형의 CUDA 그래픽스 리소스가 반환되며, 이는 CUDA 디바이스 포인터 또는 배열을 보유합니다. 커널에서 디바이스 데이터에 접근하려면 리소스를 매핑해야 합니다. 리소스가 등록되어 있는 동안에는 필요할 때마다 원하는 횟수만큼 매핑/언매핑할 수 있습니다. 매핑된 리소스는 버퍼의 경우 cudaGraphicsResourceGetMappedPointer(), CUDA 배열의 경우 cudaGraphicsSubResourceGetMappedArray()에서 반환되는 디바이스 메모리 주소를 사용하여 커널에서 접근합니다. CUDA에서 더 이상 리소스가 필요하지 않으면 등록을 해제할 수 있습니다. 주요 단계는 다음과 같습니다: 1. 그래픽스 버퍼를 CUDA에 등록 2. 리소스 매핑 3. 매핑된 리소스의 디바이스 포인터 또는 배열에 접근 4. CUDA 커널에서 디바이스 포인터 또는 배열 사용 4. 리소스 언매핑 5. 리소스 등록 해제

리소스 등록은 비용이 크므로, 이상적으로는 리소스당 한 번만 호출하는 것이 좋습니다. 그러나 리소스를 사용하려는 각 CUDA 컨텍스트마다 리소스를 별도로 등록해야 합니다. cudaGraphicsResourceSetMapFlags()는 CUDA 드라이버가 리소스 관리를 최적화하는 데 사용할 수 있는 사용 힌트(쓰기 전용, 읽기 전용)를 지정하기 위해 호출할 수 있습니다. 또한 리소스가 매핑되어 있는 동안 OpenGL, Direct3D 또는 다른 CUDA 컨텍스트를 통해 리소스에 접근하면 정의되지 않은 결과가 발생한다는 점에 유의하십시오.

4.19.1.1. OpenGL Interoperability#

CUDA의 주소 공간으로 매핑될 수 있는 OpenGL 리소스는 OpenGL 버퍼, 텍스처, 렌더버퍼 객체입니다. 버퍼 객체는 cudaGraphicsGLRegisterBuffer()를 사용해 등록하며, CUDA에서는 일반 디바이스 포인터로 나타납니다. 텍스처 또는 렌더버퍼 객체는 cudaGraphicsGLRegisterImage()를 사용해 등록하며, CUDA에서는 CUDA 배열로 나타납니다.

텍스처 또는 렌더 버퍼 객체가 cudaGraphicsRegisterFlagsSurfaceLoadStore 플래그로 등록된 경우, 해당 객체에 쓸 수 있습니다. cudaGraphicsGLRegisterImage()는 구성 요소가 1, 2 또는 4개이고 내부 타입이 float(예: GL_RGBA_FLOAT32), 정규화된 정수(예: GL_RGBA8, GL_INTENSITY16), 비정규화 정수(예: GL_RGBA8UI)인 모든 텍스처 포맷을 지원합니다.

__global__ void simple_vbo_kernel(float4 *pos, unsigned int width, unsigned int height, float time)
{
    unsigned int x = blockIdx.x * blockDim.x + threadIdx.x;
    unsigned int y = blockIdx.y * blockDim.y + threadIdx.y;

    // calculate uv coordinates
    float u = x / (float)width;
    float v = y / (float)height;
    u = u * 2.0f - 1.0f;
    v = v * 2.0f - 1.0f;

    // calculate simple sine wave pattern
    float freq = 4.0f;
    float w = sinf(u * freq + time) * cosf(v * freq + time) * 0.5f;

    // write output vertex
    pos[y * width + x] = make_float4(u, w, v, 1.0f);
}

void createVBO(GLuint *vbo, struct cudaGraphicsResource **vbo_res, unsigned int vbo_res_flags)
{
    assert(vbo);

    // create buffer object
    glGenBuffers(1, vbo);
    glBindBuffer(GL_ARRAY_BUFFER, *vbo);

    // initialize buffer object
    unsigned int size = mesh_width * mesh_height * 4 * sizeof(float);
    glBufferData(GL_ARRAY_BUFFER, size, 0, GL_DYNAMIC_DRAW);

    glBindBuffer(GL_ARRAY_BUFFER, 0);

    // register this buffer object with CUDA
    checkCudaErrors(cudaGraphicsGLRegisterBuffer(vbo_res, *vbo, vbo_res_flags));

    SDK_CHECK_ERROR_GL();
}

    glMatrixMode(GL_MODELVIEW);

}

void deleteVBO(GLuint *vbo, struct cudaGraphicsResource *vbo_res)
{
    // 6. Unregister and delete VBO
    checkCudaErrors(cudaGraphicsUnregisterResource(vbo_res));

    glBindBuffer(1, *vbo);
    glDeleteBuffers(1, vbo);

    *vbo = 0;
}

void cleanup()
{

    if (vbo) {
        deleteVBO(&vbo, cuda_vbo_resource);
    }
}

4.19.1.2. Direct3D 상호운용성#

Direct3D 상호운용성은 Direct3D9, Direct3D10, Direct3D11에 대해 지원되지만 Direct3D12는 지원되지 않습니다. 여기서는 Direct3D11에 중점을 두며, Direct3D9 및 Direct3D10에 대해서는 CUDA programming guide 12.9를 참조하십시오. CUDA의 주소 공간으로 매핑될 수 있는 Direct3D 리소스는 Direct3D 버퍼, 텍스처 및 서피스입니다. 이러한 리소스는 cudaGraphicsD3D11RegisterResource()를 사용하여 등록됩니다.

CUDA 컨텍스트는 DriverType가 D3D_DRIVER_TYPE_HARDWARE로 설정되어 생성된 Direct3D11 디바이스와만 상호운용할 수 있습니다.

예: 2D 텍스처 Direct3D11 상호운용성

다음 코드 스니펫은 simpleD3D11Texture 예제에서 가져온 것으로, NVIDIA/cuda-samples에 있습니다. 전체 예제에는 많은 보일러플레이트 DX11 코드가 포함되어 있으며, 여기서는 CUDA 측에 중점을 둡니다.

CUDA 커널 cuda_kernel_texture_2d는 파란색 스트로브 배경 위에 움직이는 빨강/초록 해치 패턴으로 2D 텍스처를 칠하며, 이전 텍스처 값에 의존합니다. 기본 데이터는 2D CUDA 배열이며, 행 오프셋은 pitch로 정의됩니다.

/*
 * Paint a 2D texture with a moving red/green hatch pattern on a
 * strobing blue background.  Note that this kernel reads to and
 * writes from the texture, hence why this texture was not mapped
 * as WriteDiscard.
 */
__global__ void cuda_kernel_texture_2d(unsigned char *surface, int width,
                                       int height, size_t pitch, float t) {
  int x = blockIdx.x * blockDim.x + threadIdx.x;
  int y = blockIdx.y * blockDim.y + threadIdx.y;
  float *pixel;

  // in the case where, due to quantization into grids, we have
  // more threads than pixels, skip the threads which don't
  // correspond to valid pixels
  if (x >= width || y >= height) return;

  // get a pointer to the pixel at (x,y)
  pixel = (float *)(surface + y * pitch) + 4 * x;

  // populate it
  float value_x = 0.5f + 0.5f * cos(t + 10.0f * ((2.0f * x) / width - 1.0f));
  float value_y = 0.5f + 0.5f * cos(t + 10.0f * ((2.0f * y) / height - 1.0f));
  pixel[0] = 0.5 * pixel[0] + 0.5 * pow(value_x, 3.0f);  // red
  pixel[1] = 0.5 * pixel[1] + 0.5 * pow(value_y, 3.0f);  // green
  pixel[2] = 0.5f + 0.5f * cos(t);                       // blue
  pixel[3] = 1;                                          // alpha
}

extern "C" void cuda_texture_2d(void *surface, int width, int height,
                                size_t pitch, float t) {
  cudaError_t error = cudaSuccess;

  dim3 Db = dim3(16, 16);  // block dimensions are fixed to be 256 threads
  dim3 Dg = dim3((width + Db.x - 1) / Db.x, (height + Db.y - 1) / Db.y);

  cuda_kernel_texture_2d<<<Dg, Db>>>((unsigned char *)surface, width, height,
                                     pitch, t);

  error = cudaGetLastError();

  if (error != cudaSuccess) {
    printf("cuda_kernel_texture_2d() failed to launch error = %d\n", error);
  }
}

포인터와 데이터 버퍼가 함께 속하도록 하기 위해 다음 데이터 구조를 사용합니다:

// Data structure for 2D texture shared between DX11 and CUDA
struct {
  ID3D11Texture2D *pTexture;
  ID3D11ShaderResourceView *pSRView;
  cudaGraphicsResource *cudaResource;
  void *cudaLinearMemory;
  size_t pitch;
  int width;
  int height;
  int offsetInShader;

Direct3D 디바이스와 텍스처를 초기화한 후, 리소스는 한 번만 CUDA에 등록됩니다. Direct3D 픽셀 포맷에 맞추기 위해 CUDA 배열은 동일한 너비와 높이로 할당되며, Direct3D 텍스처 행 pitch와 일치하는 pitch를 갖습니다.

    // register the Direct3D resources that are used in the CUDA kernel
    // we'll read to and write from g_texture_2d, so don't set any special map flags for it
    cudaGraphicsD3D11RegisterResource(&g_texture_2d.cudaResource,
                                      g_texture_2d.pTexture,
                                      cudaGraphicsRegisterFlagsNone);
    getLastCudaError("cudaGraphicsD3D11RegisterResource (g_texture_2d) failed");
    // CUDA cannot write into the texture directly : the texture is seen as a
    // cudaArray and can only be mapped as a texture
    // Create a buffer so that CUDA can write into it
    // the pixel fmt is DXGI_FORMAT_R32G32B32A32_FLOAT
    cudaMallocPitch(&g_texture_2d.cudaLinearMemory, &g_texture_2d.pitch,
                    g_texture_2d.width * sizeof(float) * 4,
                    g_texture_2d.height);
    getLastCudaError("cudaMallocPitch (g_texture_2d) failed");
    cudaMemset(g_texture_2d.cudaLinearMemory, 1,
               g_texture_2d.pitch * g_texture_2d.height);

렌더링 루프에서는 리소스를 매핑하고, CUDA 커널을 실행하여 텍스처 데이터를 업데이트한 다음, 리소스를 언매핑합니다. 이 단계 이후 Direct3D 디바이스를 사용하여 업데이트된 텍스처를 화면에 그립니다.

    cudaGraphicsResource *ppResources[nbResources] = {

    cudaGraphicsMapResources(nbResources, ppResources, stream);

  cudaGraphicsUnregisterResource(g_texture_2d.cudaResource);
  getLastCudaError("cudaGraphicsUnregisterResource (g_texture_2d) failed");
  cudaFree(g_texture_2d.cudaLinearMemory);
  getLastCudaError("cudaFree (g_texture_2d) failed");

4.19.1.3. Scalable Link Interface (SLI) 구성에서의 상호운용성#

여러 GPU가 있는 시스템에서는, 모든 CUDA 지원 GPU가 CUDA 드라이버와 런타임을 통해 별도의 디바이스로서 액세스 가능합니다. 시스템이 SLI 모드일 때는 이와 다릅니다. SLI는 여러 GPU에 걸쳐 작업 부하를 분할함으로써 렌더링 성능을 향상시키는, 하드웨어로 구성되는 멀티 GPU 구성입니다. 드라이버가 가정을 하는 암시적(Implicit) SLI 모드는 더 이상 지원되지 않지만, 명시적(Explicit) SLI는 여전히 지원됩니다. 명시적 SLI란 애플리케이션이 SLI 그룹의 모든 디바이스에 대해 API(예: Vulkan, DirectX, GL)를 통해 SLI 상태를 알고 관리한다는 것을 의미합니다.

시스템이 SLI 모드일 때는 다음과 같은 특별한 고려 사항이 있습니다:

  • 한 GPU의 하나의 CUDA 디바이스에서의 할당은, Direct3D 또는 OpenGL 디바이스의 SLI 구성에 포함된 다른 GPU에서의 메모리도 소비하게 됩니다. 이 때문에, 할당이 예상보다 더 일찍 실패할 수 있습니다.

  • 애플리케이션은 SLI 구성에 포함된 각 GPU마다 하나씩, 여러 CUDA 컨텍스트를 생성해야 합니다. 이는 엄격한 요구 사항은 아니지만, 디바이스 간 불필요한 데이터 전송을 피할 수 있습니다. 애플리케이션은 다음을 사용할 수 있습니다. cudaD3D[9|10|11]GetDevices() Direct3D 및 cudaGLGetDevices() OpenGL에 대해서는, 현재 프레임과 다음 프레임에서 렌더링을 수행하는 디바이스들의 CUDA 디바이스 핸들을 식별하기 위한 호출 집합을 사용합니다. 이 정보가 주어지면, 애플리케이션은 일반적으로 적절한 디바이스를 선택하고 Direct3D 또는 OpenGL 리소스를, 다음에서 반환된 CUDA 디바이스에 매핑합니다. cudaD3D[9|10|11]GetDevices() 또는 cudaGLGetDevices() 때 deviceList 매개변수가 다음으로 설정되면 cudaD3D[9|10|11]DeviceListCurrentFrame 또는 cudaGLDeviceListCurrentFrame.

  • cudaGraphicsD3D[9|10|11]RegisterResource 및 cudaGraphicsGLRegister[Buffer|Image]에서 반환된 리소스는 등록이 발생한 디바이스에서만 사용되어야 합니다. 따라서 SLI 구성에서 서로 다른 프레임의 데이터가 서로 다른 CUDA 디바이스에서 계산되는 경우, 각 리소스를 별도로 등록해야 합니다.

4.19.2. 외부 리소스 상호운용성#

외부 리소스 상호운용성을 통해 CUDA는 API에 의해 명시적으로 내보내진 특정 리소스를 가져올 수 있습니다. 이러한 객체는 일반적으로 Linux의 파일 디스크립터나 Windows의 NT 핸들처럼, 운영 체제에 네이티브한 핸들을 사용하여 내보내집니다. 이를 통해 중간에서 복사하거나 중복할 필요 없이, 다른 API와 CUDA 간에 리소스를 효율적으로 공유할 수 있습니다. 이는 다음 API에 대해 지원됩니다: Direct3D[11-12], Vulkan 및 NVIDIA Software Communication Interface Interoperability. 가져올 수 있는 리소스에는 두 가지 유형이 있습니다:

  • 메모리 객체

    는 cudaImportExternalMemory()을 사용하여 CUDA로 가져올 수 있습니다. 가져온 메모리 객체는 cudaExternalMemoryGetMappedBuffer()로 메모리 객체에 매핑된 디바이스 포인터 또는 cudaExternalMemoryGetMappedMipmappedArray()로 매핑된 CUDA mipmapped 배열을 사용하여, 커널 내부에서 액세스할 수 있습니다. 메모리 객체의 유형에 따라 하나의 메모리 객체에 대해 둘 이상의 매핑을 설정할 수 있을 수도 있습니다. 매핑은 내보내는 API에서 설정한 매핑과 일치해야 합니다. 일치하지 않는 매핑은 모두 정의되지 않은 동작을 초래합니다. 가져온 메모리 객체는 cudaDestroyExternalMemory()을 사용하여 해제해야 합니다. 메모리 객체를 해제하더라도 해당 객체에 대한 어떤 매핑도 해제되지 않습니다. 따라서 해당 객체에 매핑된 모든 디바이스 포인터는 cudaFree()를 사용하여 명시적으로 해제해야 하며, 해당 객체에 매핑된 모든 CUDA mipmapped 배열은 cudaFreeMipmappedArray()을 사용하여 명시적으로 해제해야 합니다. 객체가 파괴된 후에는 해당 객체에 대한 매핑에 액세스하는 것은 불법입니다.

  • 동기화 객체

    cudaImportExternalSemaphore()를 사용하여 CUDA로 가져올 수 있습니다. 가져온 동기화 객체는 이후 cudaSignalExternalSemaphoresAsync()를 사용하여 시그널을 보낼 수 있으며, cudaWaitExternalSemaphoresAsync()를 사용하여 대기할 수 있습니다. 해당하는 시그널이 발행되기 전에 대기를 발행하는 것은 불법입니다. 또한 가져온 동기화 객체의 유형에 따라, 이후 섹션에서 설명하듯 시그널을 보내고 대기할 수 있는 방식에 추가 제약이 부과될 수 있습니다. 가져온 세마포어 객체는 cudaDestroyExternalSemaphore()를 사용하여 해제해야 합니다. 세마포어 객체가 파괴되기 전에, 미완료된 모든 시그널 및 대기가 완료되어야 합니다.

4.19.2.1.2. 일치하는 디바이스 UUID로 CUDA 초기화#

Vulkan이 내보낸 메모리 및 동기화 객체를 가져올 때는, 생성된 것과 동일한 디바이스에서 가져오고 매핑해야 합니다. 객체가 생성된 Vulkan 물리 디바이스에 대응하는 CUDA 디바이스는 CUDA 디바이스의 UUID와 Vulkan 물리 디바이스의 UUID를 비교하여 결정할 수 있으며, 다음은 simpleVulkan 예제의 코드 스니펫에 표시된 방식입니다. 여기서 vkDeviceUUID은 Vulkan API 구조체 vkPhysicalDeviceIDProperties.deviceUUID의 멤버이며, 현재 Vulkan 인스턴스의 물리 디바이스 id를 정의합니다.

// from the CUDA example `simpleVulkan`
int SineWaveSimulation::initCuda(uint8_t *vkDeviceUUID, size_t UUID_SIZE) {
  int current_device = 0;
  int device_count = 0;
  int devices_prohibited = 0;

  cudaDeviceProp deviceProp;
  checkCudaErrors(cudaGetDeviceCount(&device_count));

  if (device_count == 0) {
    fprintf(stderr, "CUDA error: no devices supporting CUDA.\n");
    exit(EXIT_FAILURE);
  }

  // Find the GPU which is selected by Vulkan
  while (current_device < device_count) {
    cudaGetDeviceProperties(&deviceProp, current_device);

    if ((deviceProp.computeMode != cudaComputeModeProhibited)) {
      // Compare the cuda device UUID with vulkan UUID
      int ret = memcmp((void *)&deviceProp.uuid, vkDeviceUUID, UUID_SIZE);
      if (ret == 0) {
        checkCudaErrors(cudaSetDevice(current_device));
        checkCudaErrors(cudaGetDeviceProperties(&deviceProp, current_device));
        printf("GPU Device %d: \"%s\" with compute capability %d.%d\n\n",
               current_device, deviceProp.name, deviceProp.major,
               deviceProp.minor);

        return current_device;
      }

    } else {
      devices_prohibited++;
    }

    current_device++;
  }

  if (devices_prohibited == device_count) {
    fprintf(stderr,
            "CUDA error:"
            " No Vulkan-CUDA Interop capable GPU found.\n");
    exit(EXIT_FAILURE);
  }

  return -1;
}

Vulkan 물리 디바이스는 둘 이상의 Vulkan 물리 디바이스를 포함하는 디바이스 그룹의 일부가 아니어야 합니다. 즉, 주어진 Vulkan 물리 디바이스를 포함하는, vkEnumeratePhysicalDeviceGroups가 반환하는 디바이스 그룹은 물리 디바이스 개수가 1이어야 합니다.

4.19.2.1.3. Vulkan 메모리 객체 내보내기#

Vulkan 메모리 객체를 내보내려면, 해당 내보내기 플래그를 가진 버퍼를 생성해야 합니다. 핸들 타입에 대한 enum은 플랫폼별임에 유의하세요.

void VulkanBaseApp::createExternalBuffer(
    VkDeviceSize size, VkBufferUsageFlags usage,
    VkMemoryPropertyFlags properties,
    VkExternalMemoryHandleTypeFlagsKHR extMemHandleType, VkBuffer &buffer,
    VkDeviceMemory &bufferMemory) {
  VkBufferCreateInfo bufferInfo = {};
  bufferInfo.sType = VK_STRUCTURE_TYPE_BUFFER_CREATE_INFO;
  bufferInfo.size = size;
  bufferInfo.usage = usage;
  bufferInfo.sharingMode = VK_SHARING_MODE_EXCLUSIVE;

  VkExternalMemoryBufferCreateInfo externalMemoryBufferInfo = {};
  externalMemoryBufferInfo.sType =
      VK_STRUCTURE_TYPE_EXTERNAL_MEMORY_BUFFER_CREATE_INFO;
  externalMemoryBufferInfo.handleTypes = extMemHandleType;
  bufferInfo.pNext = &externalMemoryBufferInfo;

  if (vkCreateBuffer(m_device, &bufferInfo, nullptr, &buffer) != VK_SUCCESS) {
    throw std::runtime_error("failed to create buffer!");
  }

  VkMemoryRequirements memRequirements;
  vkGetBufferMemoryRequirements(m_device, buffer, &memRequirements);

#ifdef _WIN64
  WindowsSecurityAttributes winSecurityAttributes;

  VkExportMemoryWin32HandleInfoKHR vulkanExportMemoryWin32HandleInfoKHR = {};
  vulkanExportMemoryWin32HandleInfoKHR.sType =
      VK_STRUCTURE_TYPE_EXPORT_MEMORY_WIN32_HANDLE_INFO_KHR;
  vulkanExportMemoryWin32HandleInfoKHR.pNext = NULL;
  vulkanExportMemoryWin32HandleInfoKHR.pAttributes = &winSecurityAttributes;
  vulkanExportMemoryWin32HandleInfoKHR.dwAccess =
      DXGI_SHARED_RESOURCE_READ | DXGI_SHARED_RESOURCE_WRITE;
  vulkanExportMemoryWin32HandleInfoKHR.name = (LPCWSTR)NULL;
#endif /* _WIN64 */
  VkExportMemoryAllocateInfoKHR vulkanExportMemoryAllocateInfoKHR = {};
  vulkanExportMemoryAllocateInfoKHR.sType =
      VK_STRUCTURE_TYPE_EXPORT_MEMORY_ALLOCATE_INFO_KHR;
#ifdef _WIN64
  vulkanExportMemoryAllocateInfoKHR.pNext =
      extMemHandleType & VK_EXTERNAL_MEMORY_HANDLE_TYPE_OPAQUE_WIN32_BIT_KHR
          ? &vulkanExportMemoryWin32HandleInfoKHR
          : NULL;
  vulkanExportMemoryAllocateInfoKHR.handleTypes = extMemHandleType;
#else
  vulkanExportMemoryAllocateInfoKHR.pNext = NULL;
  vulkanExportMemoryAllocateInfoKHR.handleTypes =
      VK_EXTERNAL_MEMORY_HANDLE_TYPE_OPAQUE_FD_BIT;
#endif /* _WIN64 */
  VkMemoryAllocateInfo allocInfo = {};
  allocInfo.sType = VK_STRUCTURE_TYPE_MEMORY_ALLOCATE_INFO;
  allocInfo.pNext = &vulkanExportMemoryAllocateInfoKHR;
  allocInfo.allocationSize = memRequirements.size;
  allocInfo.memoryTypeIndex = findMemoryType(
      m_physicalDevice, memRequirements.memoryTypeBits, properties);

  if (vkAllocateMemory(m_device, &allocInfo, nullptr, &bufferMemory) !=
      VK_SUCCESS) {
    throw std::runtime_error("failed to allocate external buffer memory!");
  }

  vkBindBufferMemory(m_device, buffer, bufferMemory, 0);
}

4.19.2.1.4. Vulkan 동기화 객체 내보내기#

GPU에서 실행되는 Vulkan API 호출은 비동기식입니다. 실행 순서를 정의하기 위해 Vulkan에는 CUDA와 공유할 수 있는 세마포어와 펜스가 있습니다. 메모리 객체와 마찬가지로 세마포어는 Vulkan에서 내보낼 수 있으며, 세마포어 타입에 따라 내보내기 플래그를 사용하여 생성되어야 합니다. 세마포어에는 바이너리 세마포어와 타임라인 세마포어가 있습니다. 바이너리 세마포어는 1비트 카운터만 가지며, 시그널되었거나 그렇지 않거나 둘 중 하나입니다. 타임라인 세마포어는 64비트 카운터를 가지며, 동일한 세마포어로 실행 순서를 정의하는 데 사용할 수 있습니다. simpleVulkan 예제에는 타임라인 세마포어와 바이너리 세마포어 모두에 대한 코드 경로가 있습니다.

void VulkanBaseApp::createExternalSemaphore(
    VkSemaphore &semaphore, VkExternalSemaphoreHandleTypeFlagBits handleType) {
  VkSemaphoreCreateInfo semaphoreInfo = {};
  semaphoreInfo.sType = VK_STRUCTURE_TYPE_SEMAPHORE_CREATE_INFO;
  VkExportSemaphoreCreateInfoKHR exportSemaphoreCreateInfo = {};
  exportSemaphoreCreateInfo.sType =

4.19.2.1.5. 메모리 객체 가져오기#

Vulkan에서 내보낸 dedicated 및 non-dedicated 메모리 객체 모두 CUDA로 가져올 수 있습니다. Vulkan dedicated 메모리 객체를 가져올 때는 플래그 cudaExternalMemoryDedicated를 설정해야 합니다.

Windows에서는, VK_EXTERNAL_MEMORY_HANDLE_TYPE_OPAQUE_WIN32_BIT을 사용해 내보낸 Vulkan 메모리 객체를 아래와 같이 해당 객체와 연관된 NT handle을 사용하여 CUDA로 가져올 수 있습니다. CUDA는 NT handle의 소유권을 가정하지 않으며, 더 이상 필요하지 않을 때 handle을 닫는 것은 애플리케이션의 책임임에 유의하세요. NT handle은 리소스에 대한 참조를 보유하므로, 기반 메모리를 해제하기 전에 이를 명시적으로 해제해야 합니다.

Linux에서는, VK_EXTERNAL_MEMORY_HANDLE_TYPE_OPAQUE_FD_BIT을 사용해 내보낸 Vulkan 메모리 객체를 아래와 같이 해당 객체와 연관된 file descriptor를 사용하여 CUDA로 가져올 수 있습니다. CUDA는 가져오기가 완료되면 file descriptor의 소유권을 가정합니다. 성공적으로 가져온 후 file descriptor를 사용하면 정의되지 않은 동작이 발생합니다.

                                VkDeviceMemory &vkMem, VkDeviceSize size,
                                VkExternalMemoryHandleTypeFlagBits handleType) {

          cudaExternalMemoryHandleTypeOpaqueWin32Kmt;

4.19.2.1.9. 가져온 동기화 객체에 대한 시그널/대기#

가져온 Vulkan 세마포어는 아래와 같이 시그널 및 대기할 수 있습니다. 세마포어에 시그널을 보내면 세마포어가 시그널 상태로 설정되며, 타임라인 세마포어의 경우 시그널 호출에서 지정한 값으로 카운터를 설정합니다. 이 시그널을 대기하는 해당 wait는 Vulkan에서 발행되어야 합니다. 또한 바이너리 세마포어의 경우, 이 시그널을 대기하는 wait는 이 시그널이 발행된 이후에 발행되어야 합니다.

세마포어에 대한 대기는 세마포어가 시그널 상태에 도달하거나 지정된 대기 값에 도달할 때까지 기다립니다. 이후 시그널된 바이너리 세마포어는 다시 unsignaled 상태로 리셋됩니다. 이 wait가 대기하고 있는 해당 시그널은 Vulkan에서 발행되어야 합니다. 또한 바이너리 세마포어의 경우, 이 wait를 발행하기 전에 시그널이 발행되어야 합니다.

simpleVulkan 예제의 다음 코드 발췌에서는, 버텍스 버퍼 주변의 세마포어가 Vulkan에 의해 시그널된 이후에만 시뮬레이션 단계 / CUDA 커널이 호출됩니다. 시뮬레이션 단계 이후에는 또 다른 세마포어에 시그널을 보내거나, 타임라인 세마포어의 경우 CUDA가 동일한 세마포어 값을 증가시켜, 이 세마포어를 대기하고 있는 Vulkan 부분이 업데이트된 버텍스 버퍼로 렌더링을 계속할 수 있도록 합니다.

4.19.2.1.10. OpenGL 상호운용성#

OpenGL 상호운용성에 설명된 전통적인 OpenGL-CUDA interop은, OpenGL에서 생성된 핸들을 CUDA가 직접 소비하는 방식으로 동작합니다. 하지만 OpenGL은 Vulkan에서 생성된 메모리 및 동기화 객체도 소비할 수 있으므로, OpenGL-CUDA interop을 수행하는 대체 접근 방식이 존재합니다. 본질적으로, Vulkan이 내보낸 메모리 및 동기화 객체를 OpenGL과 CUDA 양쪽으로 가져온(import) 다음, 이를 사용하여 OpenGL과 CUDA 간의 메모리 액세스를 조정할 수 있습니다. Vulkan에서 내보낸 메모리 및 동기화 객체를 가져오는 방법에 대한 자세한 내용은 다음 OpenGL 확장을 참조하십시오:

  • GL_EXT_memory_object

  • GL_EXT_memory_object_fd

  • GL_EXT_memory_object_win32

  • GL_EXT_semaphore

  • GL_EXT_semaphore_fd

  • GL_EXT_semaphore_win32

4.19.2.2. Direct3D 상호운용성#

Direct3D[11|12] 리소스를 CUDA로 가져오는 기능은 Direct3D11 및 Direct3D12에서 지원됩니다. 여기서는 Direct3D12만 다루며, Direct3D11에 대해서는 CUDA 프로그래밍 가이드 12.9를 참조하십시오.

4.19.2.2.1. 디바이스 LUID 매칭#

Direct3D12가 내보낸 메모리 및 동기화 객체를 가져오는 경우, 해당 객체가 생성된 것과 동일한 디바이스에서 가져오고 매핑해야 합니다. 객체가 생성된 Direct3D12 디바이스에 대응하는 CUDA 디바이스는, 다음 코드 샘플에 표시된 것처럼 CUDA 디바이스의 LUID와 Direct3D12 디바이스의 LUID를 비교하여 결정할 수 있습니다. Direct3D12 디바이스는 linked node adapter에서 생성되면 안 되며, 즉 ID3D12Device::GetNodeCount가 반환하는 노드 개수는 1이어야 합니다.

int getCudaDeviceForD3D12Device(ID3D12Device *d3d12Device) {
    LUID d3d12Luid = d3d12Device->GetAdapterLuid();

    int cudaDeviceCount;
    cudaGetDeviceCount(&cudaDeviceCount);

    for (int cudaDevice = 0; cudaDevice < cudaDeviceCount; cudaDevice++) {
        cudaDeviceProp deviceProp;
        cudaGetDeviceProperties(&deviceProp, cudaDevice);
        char *cudaLuid = deviceProp.luid;

        if (!memcmp(&d3d12Luid.LowPart, cudaLuid, sizeof(d3d12Luid.LowPart)) &&
            !memcmp(&d3d12Luid.HighPart, cudaLuid + sizeof(d3d12Luid.LowPart), sizeof(d3d12Luid.HighPart))) {
            return cudaDevice;
        }
    }
    return cudaInvalidDeviceId;
}

4.19.2.2.2. 메모리 객체 가져오기#

NT 핸들에서 메모리 객체를 가져오는 방법에는 여러 가지가 있습니다. 더 이상 필요하지 않을 때 NT 핸들을 닫는 것은 애플리케이션의 책임이라는 점에 유의하세요. NT 핸들은 리소스에 대한 참조를 보유하므로, 기본 메모리를 해제할 수 있기 전에 명시적으로 해제되어야 합니다. Direct3D 리소스를 가져올 때는 아래의 스니펫에 나와 있는 것처럼 플래그 cudaExternalMemoryDedicated를 설정해야 합니다.

플래그를 설정하여 생성된, 공유 가능한 Direct3D12 힙 메모리 객체 D3D12_HEAP_FLAG_SHARED 호출에서 ID3D12Device::CreateHeap, 아래에 표시된 것처럼 해당 객체와 연관된 NT 핸들을 사용하여 CUDA로 가져올 수 있습니다.

cudaExternalMemory_t importD3D12HeapFromNTHandle(HANDLE handle, unsigned long long size) {
    cudaExternalMemory_t extMem = NULL;
    cudaExternalMemoryHandleDesc desc = {};

    memset(&desc, 0, sizeof(desc));

    desc.type = cudaExternalMemoryHandleTypeD3D12Heap;
    desc.handle.win32.handle = (void *)handle;
    desc.size = size;

    cudaImportExternalMemory(&extMem, &desc);

    // Input parameter 'handle' should be closed if it's not needed anymore
    CloseHandle(handle);

    return extMem;
}

공유 가능한 Direct3D12 힙 메모리 객체는 존재하는 경우 named handle을 사용해서도 가져올 수 있습니다:

    cudaExternalMemory_t extMem = NULL;
    cudaExternalMemoryHandleDesc desc = {};

    memset(&desc, 0, sizeof(desc));

    desc.type = cudaExternalMemoryHandleTypeD3D12Heap;
    desc.handle.win32.name = (void *)name;
    desc.size = size;

    cudaImportExternalMemory(&extMem, &desc);

    return extMem;
}

플래그를 설정하여 생성된, 공유 가능한 Direct3D12 committed 리소스, D3D12_HEAP_FLAG_SHARED 호출에서 D3D12Device::CreateCommittedResource, 아래에 표시된 것처럼 해당 객체와 연관된 NT 핸들을 사용하여 CUDA로 가져올 수 있습니다. Direct3D12 committed 리소스를 가져올 때는 플래그 cudaExternalMemoryDedicated 를 설정해야 합니다.

cudaExternalMemory_t importD3D12CommittedResourceFromNTHandle(HANDLE handle, unsigned long long size) {
    cudaExternalMemory_t extMem = NULL;

4.19.2.2.3. 가져온 메모리 객체에 버퍼 매핑#

디바이스 포인터는 아래에 표시된 것처럼 가져온 메모리 객체에 매핑할 수 있습니다. 매핑의 오프셋과 크기는 해당 Direct3D12 API를 사용하여 매핑을 생성할 때 지정한 것과 일치해야 합니다. 매핑된 모든 디바이스 포인터는 cudaFree()를 사용하여 해제해야 합니다.

void * mapBufferOntoExternalMemory(cudaExternalMemory_t extMem, unsigned long long offset, unsigned long long size) {
    void *ptr = NULL;
    cudaExternalMemoryBufferDesc desc = {};

    memset(&desc, 0, sizeof(desc));

    desc.size = size;

    cudaExternalMemoryGetMappedBuffer(&ptr, extMem, &desc);

    // Note: 'ptr' must eventually be freed using cudaFree()
    return ptr;
}

4.19.2.2.6. 가져온 동기화 객체에 대한 시그널/대기#

Direct3D12에서 fence가 포함된 세마포어를 가져오면 시그널하고 대기할 수 있습니다.

fence 객체에 시그널을 보내면 해당 값이 설정됩니다. 이 시그널을 대기하는 해당 대기 작업은 Direct3D12에서 발행되어야 합니다. 이 시그널을 대기하는 대기 작업은 이 시그널이 발행된 이후에 발행되어야 한다는 점에 유의하세요.

void signalExternalSemaphore(cudaExternalSemaphore_t extSem, unsigned long long value, cudaStream_t stream) {
    cudaExternalSemaphoreSignalParams params = {};

    memset(&params, 0, sizeof(params));

    params.params.fence.value = value;

    cudaSignalExternalSemaphoresAsync(&extSem, &params, 1, stream);
}

fence 객체는 그 값이 지정된 값과 같거나 더 커질 때까지 대기합니다. fence 객체가 대기하고 있는 해당 시그널은 Direct3D12에서 발행되어야 합니다. 이 대기 작업이 발행되기 전에 시그널이 발행되어야 한다는 점에 유의하세요.

void waitExternalSemaphore(cudaExternalSemaphore_t extSem, unsigned long long value, cudaStream_t stream) {
    cudaExternalSemaphoreWaitParams params = {};

    memset(&params, 0, sizeof(params));

    params.params.fence.value = value;

    cudaWaitExternalSemaphoresAsync(&extSem, &params, 1, stream);
}

4.19.2.3. NVIDIA Software Communication Interface 상호운용성 (NVSCI)#

NvSciBuf 및 NvSciSync는 다음 목적을 제공하기 위해 개발된 인터페이스입니다:

  • NvSciBuf: 애플리케이션이 메모리에서 버퍼를 할당하고 교환할 수 있도록 합니다

4.19.2.3.1. 메모리 객체 가져오기#

지정된 CUDA 디바이스와 호환되는 NvSciBuf 객체를 할당하려면, 아래에 표시된 것처럼 NvSciBuf 속성 목록에서 NvSciBufGeneralAttrKey_GpuId로 해당 GPU id를 설정해야 합니다. 선택적으로, 애플리케이션은 다음 속성을 지정할 수 있습니다 -

  • NvSciBufGeneralAttrKey_NeedCpuAccess: 버퍼에 CPU 액세스가 필요한지 지정합니다

  • NvSciBufRawBufferAttrKey_Align: NvSciBufType_RawBuffer의 정렬 요구 사항을 지정합니다

  • NvSciBufGeneralAttrKey_RequiredPerm: 서로 다른 UMD에 대해, NvSciBuf 메모리 객체 인스턴스별로 서로 다른 액세스 권한을 구성할 수 있습니다. 예를 들어 GPU에 버퍼에 대한 읽기 전용 액세스 권한을 제공하려면, 다음을 사용하여 중복 NvSciBuf 객체를 생성합니다 NvSciBufObjDupWithReducePerm() 를 사용하여 NvSciBufAccessPerm_Readonly 입력 매개변수로 사용합니다. 그런 다음 아래에 표시된 것처럼, 권한이 축소된 이 새로 생성된 중복 객체를 CUDA로 가져옵니다

  • NvSciBufGeneralAttrKey_EnableGpuCache: GPU L2 캐시 가능성을 제어하기 위해

  • NvSciBufGeneralAttrKey_EnableGpuCompression: GPU 압축을 지정하기 위해

참고

이러한 속성과 유효한 입력 옵션에 대한 자세한 내용은 NvSciBuf Documentation를 참조하세요.

다음 코드 스니펫은 이들의 샘플 사용법을 보여줍니다.

NvSciBufObj createNvSciBufObject() {
   // Raw Buffer Attributes for CUDA
    NvSciBufType bufType = NvSciBufType_RawBuffer;
    uint64_t rawsize = SIZE;
    uint64_t align = 0;
    bool cpuaccess_flag = true;
    NvSciBufAttrValAccessPerm perm = NvSciBufAccessPerm_ReadWrite;

    NvSciRmGpuId gpuid[] ={};
    CUuuid uuid;
    cuDeviceGetUuid(&uuid, dev));

    memcpy(&gpuid[0].bytes, &uuid.bytes, sizeof(uuid.bytes));
    // Disable cache on dev
    NvSciBufAttrValGpuCache gpuCache[] = {{gpuid[0], false}};
    NvSciBufAttrValGpuCompression gpuCompression[] = {{gpuid[0], NvSciBufCompressionType_GenericCompressible}};
    // Fill in values
    NvSciBufAttrKeyValuePair rawbuffattrs[] = {
         { NvSciBufGeneralAttrKey_Types, &bufType, sizeof(bufType) },
         { NvSciBufRawBufferAttrKey_Size, &rawsize, sizeof(rawsize) },
         { NvSciBufRawBufferAttrKey_Align, &align, sizeof(align) },
         { NvSciBufGeneralAttrKey_NeedCpuAccess, &cpuaccess_flag, sizeof(cpuaccess_flag) },
         { NvSciBufGeneralAttrKey_RequiredPerm, &perm, sizeof(perm) },
         { NvSciBufGeneralAttrKey_GpuId, &gpuid, sizeof(gpuid) },
         { NvSciBufGeneralAttrKey_EnableGpuCache &gpuCache, sizeof(gpuCache) },
         { NvSciBufGeneralAttrKey_EnableGpuCompression &gpuCompression, sizeof(gpuCompression) }
    };

    // Create list by setting attributes
    err = NvSciBufAttrListSetAttrs(attrListBuffer, rawbuffattrs,
            sizeof(rawbuffattrs)/sizeof(NvSciBufAttrKeyValuePair));

    NvSciBufAttrListCreate(NvSciBufModule, &attrListBuffer);

    // Reconcile And Allocate
    NvSciBufAttrListReconcile(&attrListBuffer, 1, &attrListReconciledBuffer,
                       &attrListConflictBuffer)
    NvSciBufObjAlloc(attrListReconciledBuffer, &bufferObjRaw);
    return bufferObjRaw;
}

NvSciBufObj bufferObjRo; // Readonly NvSciBuf memory obj
// Create a duplicate handle to the same memory buffer with reduced permissions
NvSciBufObjDupWithReducePerm(bufferObjRaw, NvSciBufAccessPerm_Readonly, &bufferObjRo);
return bufferObjRo;

할당된 NvSciBuf 메모리 객체는 아래에 보인 것처럼 NvSciBufObj 핸들을 사용하여 CUDA로 가져올 수 있습니다. 애플리케이션은 CUDA External Memory Descriptor를 채우는 데 필요한 속성들을 위해 할당된 NvSciBufObj를 쿼리해야 합니다. 속성 리스트와 NvSciBuf 객체는 애플리케이션이 유지해야 한다는 점에 유의하십시오. CUDA로 가져온 NvSciBuf 객체가 다른 드라이버에서도 매핑되어 있다면, NvSciBufGeneralAttrKey_GpuSwNeedCacheCoherency 출력 속성 값에 따라 애플리케이션은 CUDA와 다른 드라이버 간의 일관성을 유지하기 위한 적절한 배리어로 NvSciSync 객체(동기화 객체 가져오기 참조)를 사용해야 합니다.

참고

NvSciBuf 객체를 할당하고 유지하는 방법에 대한 자세한 내용은 NvSciBuf API Documentation.을 참조하십시오.

cudaExternalMemory_t importNvSciBufObject (NvSciBufObj bufferObjRaw) {

    NvSciBufAttrKeyValuePair bufattrs[] = {
                { NvSciBufRawBufferAttrKey_Size, NULL, 0 },
                { NvSciBufGeneralAttrKey_GpuSwNeedCacheCoherency, NULL, 0 },
                { NvSciBufGeneralAttrKey_EnableGpuCompression, NULL, 0 }
    };
    NvSciBufAttrListGetAttrs(retList, bufattrs,
        sizeof(bufattrs)/sizeof(NvSciBufAttrKeyValuePair)));
                ret_size = *(static_cast<const uint64_t*>(bufattrs[0].value));

    // Note cache and compression are per GPU attributes, so read values for specific gpu by comparing UUID
    // Read cacheability granted by NvSciBuf
    int numGpus = bufattrs[1].len / sizeof(NvSciBufAttrValGpuCache);
    NvSciBufAttrValGpuCache[] cacheVal = (NvSciBufAttrValGpuCache *)bufattrs[1].value;
    bool ret_cacheVal;
    for (int i = 0; i < numGpus; i++) {
        if (memcmp(gpuid[0].bytes, cacheVal[i].gpuId.bytes, sizeof(CUuuid)) == 0) {
            ret_cacheVal = cacheVal[i].cacheability);
        }
    }

    // Read compression granted by NvSciBuf
    numGpus = bufattrs[2].len / sizeof(NvSciBufAttrValGpuCompression);
    NvSciBufAttrValGpuCompression[] compVal = (NvSciBufAttrValGpuCompression *)bufattrs[2].value;
    NvSciBufCompressionType ret_compVal;
    for (int i = 0; i < numGpus; i++) {
        if (memcmp(gpuid[0].bytes, compVal[i].gpuId.bytes, sizeof(CUuuid)) == 0) {
            ret_compVal = compVal[i].compressionType);
        }
    }

    /*************** NvSciBuf Registration With CUDA **************/

    // Fill up CUDA_EXTERNAL_MEMORY_HANDLE_DESC
    cudaExternalMemoryHandleDesc memHandleDesc;
    memset(&memHandleDesc, 0, sizeof(memHandleDesc));
    memHandleDesc.type = cudaExternalMemoryHandleTypeNvSciBuf;
    memHandleDesc.handle.nvSciBufObject = bufferObjRaw;
    // Set the NvSciBuf object with required access permissions in this step
    memHandleDesc.handle.nvSciBufObject = bufferObjRo;
    memHandleDesc.size = ret_size;
    cudaImportExternalMemory(&extMemBuffer, &memHandleDesc);
    return extMemBuffer;
 }

4.19.2.3.2. 가져온 메모리 객체에 버퍼 매핑#

아래에 보인 것처럼 디바이스 포인터를 가져온 메모리 객체에 매핑할 수 있습니다. 매핑의 오프셋과 크기는 할당된 NvSciBufObj의 속성에 따라 채울 수 있습니다. 매핑된 모든 디바이스 포인터는 cudaFree()를 사용하여 해제해야 합니다.

void * mapBufferOntoExternalMemory(cudaExternalMemory_t extMem, unsigned long long offset, unsigned long long size) {
    void *ptr = NULL;
    cudaExternalMemoryBufferDesc desc = {};

    memset(&desc, 0, sizeof(desc));

    desc.offset = offset;
    desc.size = size;

    cudaExternalMemoryGetMappedBuffer(&ptr, extMem, &desc);

    // Note: 'ptr' must eventually be freed using cudaFree()
    return ptr;
}

4.19.2.3.4. 동기화 객체 가져오기#

주어진 CUDA 디바이스와 호환되는 NvSciSync 속성은 cudaDeviceGetNvSciSyncAttributes()를 사용하여 생성할 수 있습니다. 반환된 속성 리스트는 주어진 CUDA 디바이스와의 호환성이 보장되는 NvSciSyncObj를 생성하는 데 사용할 수 있습니다.

NvSciSyncObj createNvSciSyncObject() {
    NvSciSyncObj nvSciSyncObj
    int cudaDev0 = 0;
    int cudaDev1 = 1;
    NvSciSyncAttrList signalerAttrList = NULL;
    NvSciSyncAttrList waiterAttrList = NULL;
    NvSciSyncAttrList reconciledList = NULL;
    NvSciSyncAttrList newConflictList = NULL;

    NvSciSyncAttrListCreate(module, &signalerAttrList);
    NvSciSyncAttrListCreate(module, &waiterAttrList);
    NvSciSyncAttrList unreconciledList[2] = {NULL, NULL};
    unreconciledList[0] = signalerAttrList;
    unreconciledList[1] = waiterAttrList;

    cudaDeviceGetNvSciSyncAttributes(signalerAttrList, cudaDev0, CUDA_NVSCISYNC_ATTR_SIGNAL);
    cudaDeviceGetNvSciSyncAttributes(waiterAttrList, cudaDev1, CUDA_NVSCISYNC_ATTR_WAIT);

    NvSciSyncAttrListReconcile(unreconciledList, 2, &reconciledList, &newConflictList);

    NvSciSyncObjAlloc(reconciledList, &nvSciSyncObj);

    return nvSciSyncObj;
}

위와 같이 생성된 NvSciSync 객체는 아래에 보인 것처럼 NvSciSyncObj 핸들을 사용하여 CUDA로 가져올 수 있습니다. 가져온 후에도 NvSciSyncObj 핸들의 소유권은 계속 애플리케이션에 있다는 점에 유의하십시오.

cudaExternalSemaphore_t importNvSciSyncObject(void* nvSciSyncObj) {
    cudaExternalSemaphore_t extSem = NULL;
    cudaExternalSemaphoreHandleDesc desc = {};

    memset(&desc, 0, sizeof(desc));

    desc.type = cudaExternalSemaphoreHandleTypeNvSciSync;
    desc.handle.nvSciSyncObj = nvSciSyncObj;

    cudaImportExternalSemaphore(&extSem, &desc);

    // Deleting/Freeing the nvSciSyncObj beyond this point will lead to undefined behavior in CUDA

    return extSem;
}

4.19.2.3.5. 가져온 동기화 객체에 시그널/대기#

가져온 NvSciSyncObj 객체는 아래에 설명된 대로 시그널할 수 있습니다. NvSciSync 기반 세마포어 객체를 시그널하면 입력으로 전달되는 fence 파라미터가 초기화됩니다. 이 fence 파라미터는 앞서 언급한 시그널에 대응하는 대기(wait) 작업에서 대기 대상이 됩니다. 또한, 이 시그널을 대기하는 wait는 이 시그널이 발행된 이후에 발행되어야 합니다. 플래그가 cudaExternalSemaphoreSignalSkipNvSciBufMemSync로 설정되면, 기본적으로 시그널 작업의 일부로 실행되는 메모리 동기화 작업(이 프로세스에서 가져온 모든 NvSciBuf에 대해)은 건너뜁니다. NvsciBufGeneralAttrKey_GpuSwNeedCacheCoherency가 FALSE일 때 이 플래그를 설정해야 합니다.

void signalExternalSemaphore(cudaExternalSemaphore_t extSem, cudaStream_t stream, void *fence) {
    cudaExternalSemaphoreSignalParams signalParams = {};

    memset(&signalParams, 0, sizeof(signalParams));

    signalParams.params.nvSciSync.fence = (void*)fence;
    signalParams.flags = 0; //OR cudaExternalSemaphoreSignalSkipNvSciBufMemSync

    cudaSignalExternalSemaphoresAsync(&extSem, &signalParams, 1, stream);

}

가져온 NvSciSyncObj 객체는 아래에 설명된 대로 대기할 수 있습니다. NvSciSync 기반 세마포어 객체에 대한 대기는, 해당 시그널러가 입력 fence 파라미터를 시그널할 때까지 대기합니다. 또한, wait를 발행하기 전에 signal이 발행되어야 합니다. 플래그가 cudaExternalSemaphoreWaitSkipNvSciBufMemSync로 설정되면, 기본적으로 시그널 작업의 일부로 실행되는 메모리 동기화 작업(이 프로세스에서 가져온 모든 NvSciBuf에 대해)은 건너뜁니다. NvsciBufGeneralAttrKey_GpuSwNeedCacheCoherency이 FALSE일 때 이 플래그를 설정해야 합니다.

void waitExternalSemaphore(cudaExternalSemaphore_t extSem, cudaStream_t stream, void *fence) {
     cudaExternalSemaphoreWaitParams waitParams = {};

    memset(&waitParams, 0, sizeof(waitParams));

    waitParams.params.nvSciSync.fence = (void*)fence;
    waitParams.flags = 0; //OR cudaExternalSemaphoreWaitSkipNvSciBufMemSync

    cudaWaitExternalSemaphoresAsync(&extSem, &waitParams, 1, stream);
}
