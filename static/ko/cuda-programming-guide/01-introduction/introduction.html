1.1. 소개

1.1.1. 그래픽 처리 장치#

3D 그래픽을 위한 특수 목적 프로세서로 탄생한 그래픽 처리 장치(GPU)는 실시간 3D 렌더링에서 병렬 연산을 가속하기 위한 고정 기능 하드웨어로 시작했습니다. 세대를 거치며 GPU는 더 프로그래머블해졌습니다. 2003년까지 그래픽 파이프라인의 일부 단계는 완전히 프로그래머블해져, 3D 장면이나 이미지의 각 구성 요소에 대해 사용자 정의 코드를 병렬로 실행할 수 있게 되었습니다.

2006년 NVIDIA는 그래픽 API와 무관하게 모든 계산 워크로드가 GPU의 처리량 능력을 활용할 수 있도록 컴퓨트 통합 디바이스 아키텍처(CUDA)를 도입했습니다.

그 이후 CUDA와 GPU 컴퓨팅은 유체 역학이나 에너지 전달과 같은 과학 시뮬레이션부터 데이터베이스 및 분석과 같은 비즈니스 애플리케이션에 이르기까지 거의 모든 유형의 계산 워크로드를 가속하는 데 사용되어 왔습니다. 또한 GPU의 성능과 프로그래머빌리티는 이미지 분류에서 확산(Diffusion) 또는 대규모 언어 모델과 같은 생성형 인공지능에 이르기까지 새로운 알고리즘과 기술의 발전을 뒷받침하는 기반이 되어 왔습니다.

1.1.2. GPU 사용의 이점#

GPU는 비슷한 가격 및 전력 범위 내에서 CPU보다 훨씬 더 높은 명령 처리량과 메모리 대역폭을 제공합니다. 많은 애플리케이션이 이러한 기능을 활용하여 CPU에서보다 GPU에서 훨씬 더 빠르게 실행됩니다(참조: GPU 애플리케이션). FPGA와 같은 다른 컴퓨팅 장치도 에너지 효율이 매우 높지만, GPU에 비해 프로그래밍 유연성이 훨씬 낮습니다.

GPU와 CPU는 서로 다른 목표를 염두에 두고 설계되었습니다. CPU는 연산의 직렬 시퀀스(스레드라고 함)를 가능한 한 빠르게 실행하는 데 탁월하도록 설계되었으며, 이러한 스레드 수십 개를 병렬로 실행할 수 있습니다. 반면 GPU는 수천 개의 스레드를 병렬로 실행하는 데 탁월하도록 설계되었고, 단일 스레드 성능을 낮추는 대신 훨씬 더 큰 총 처리량을 달성합니다.

GPU는 고도로 병렬적인 계산에 특화되어 데이터 처리 유닛에 더 많은 트랜지스터를 할당하는 반면, CPU는 데이터 캐싱과 흐름 제어에 더 많은 트랜지스터를 할당합니다. 그림 1은 CPU와 GPU의 칩 리소스 분포 예를 보여줍니다.

1.1.3. 빠르게 시작하기#

GPU가 제공하는 컴퓨팅 성능을 활용하는 방법은 다양합니다. 이 가이드는 C++와 같은 고수준 언어로 CUDA GPU 플랫폼을 프로그래밍하는 방법을 다룹니다. 하지만 GPU 코드를 직접 작성할 필요가 없는 애플리케이션에서도 GPU를 활용하는 방법은 많습니다.

다양한 도메인의 알고리즘과 루틴으로 구성된 계속 확장되는 컬렉션을 특화 라이브러리를 통해 사용할 수 있습니다. 라이브러리가 이미 구현되어 있다면—특히 NVIDIA에서 제공하는 경우—이를 사용하는 것이 알고리즘을 처음부터 다시 구현하는 것보다 대개 생산성과 성능 면에서 더 유리합니다. cuBLAS, cuFFT, cuDNN, CUTLASS 같은 라이브러리는 개발자가 이미 잘 확립된 알고리즘을 다시 구현하는 일을 피하도록 돕는 라이브러리의 몇 가지 예에 불과합니다. 이러한 라이브러리는 각 GPU 아키텍처에 맞게 최적화되어 있어 생산성, 성능, 이식성의 이상적인 조합을 제공한다는 추가 이점도 있습니다.

또한 특히 인공지능에 사용되는 프레임워크 중에는 GPU 가속 빌딩 블록을 제공하는 것들이 있습니다. 이러한 프레임워크 중 다수는 앞서 언급한 GPU 가속 라이브러리를 활용하여 가속을 달성합니다.

추가로, NVIDIA의 Warp나 OpenAI의 Triton과 같은 도메인 특화 언어(DSL)는 CUDA 플랫폼에서 직접 실행되도록 컴파일됩니다. 이는 이 가이드에서 다루는 고수준 언어보다도 더 고수준의 GPU 프로그래밍 방법을 제공합니다.

NVIDIA Accelerated Computing Hub에는 GPU 및 CUDA 컴퓨팅을 학습할 수 있도록 리소스, 예제, 튜토리얼이 포함되어 있습니다.
