5.2. CUDA 환경 변수

다음 섹션에는 CUDA 환경 변수가 나열되어 있습니다. Multi-Process Service(MPS) 관련 항목은 GPU 배포 및 관리 가이드에 문서화되어 있습니다.

5.2.1. 디바이스 열거 및 속성#

5.2.1.1. CUDA_VISIBLE_DEVICES#

이 환경 변수는 CUDA 애플리케이션에서 어떤 GPU 디바이스가 보이는지, 그리고 어떤 순서로 열거되는지를 제어합니다.

  • 변수가 설정되지 않으면 모든 GPU 디바이스가 표시됩니다.

  • 변수가 빈 문자열로 설정되면 어떤 GPU 디바이스도 표시되지 않습니다.

가능한 값: 쉼표로 구분된 GPU 식별자 시퀀스.

GPU 식별자는 다음과 같이 제공됩니다:

  • 정수 인덱스: 이는 nvidia-smi에 의해 결정되는 시스템 내 GPU의 서수 번호에 해당하며, 0부터 시작합니다. 예를 들어, CUDA_VISIBLE_DEVICES=2,1로 설정하면 디바이스 0은 보이지 않게 되고 디바이스 2가 디바이스 1보다 먼저 열거됩니다.

    • 잘못된 인덱스가 발견되면, 목록에서 잘못된 인덱스보다 앞에 나타나는 인덱스를 가진 디바이스만 표시됩니다. 예를 들어, CUDA_VISIBLE_DEVICES=0,2,-1,1로 설정하면 디바이스 0과 2가 표시되며, 디바이스 1은 잘못된 인덱스인 -1 뒤에 나타나므로 표시되지 않습니다.

  • GPU UUID 문자열: nvidia-smi -L에서 제공되는 것과 동일한 형식을 따라야 하며, 예를 들어 GPU-8932f937-d72c-4106-c12f-20bd9faed9f6과 같습니다. 다만 편의를 위해 축약형도 허용됩니다. 대상 시스템에서 해당 GPU를 고유하게 식별할 수 있을 정도로 GPU UUID 시작 부분의 숫자를 충분히 지정하면 됩니다. 예를 들어, 시스템 내 다른 GPU가 이 접두사를 공유하지 않는다는 가정 하에 CUDA_VISIBLE_DEVICES=GPU-8932f937은 위 GPU UUID를 참조하는 유효한 방법일 수 있습니다.

  • Multi-Instance GPU(MIG) 지원: MIG-<GPU-UUID>/<GPU instance ID>/<compute instance ID>. 예: MIG-GPU-8932f937-d72c-4106-c12f-20bd9faed9f6/1/2. 단일 MIG 인스턴스 열거만 지원됩니다.

cudaGetDeviceCount() API가 반환하는 디바이스 개수에는 표시되는 디바이스만 포함되므로, 정수 디바이스 식별자를 사용하는 CUDA API는 [0, 표시 디바이스 개수 - 1] 범위의 서수만 지원합니다. GPU 디바이스의 열거 순서가 서수 값을 결정합니다. 예를 들어, CUDA_VISIBLE_DEVICES=2,1인 경우, cudaSetDevice(0)를 호출하면 디바이스 2가 먼저 열거되어 서수 0이 할당되므로 디바이스 2가 현재 디바이스로 설정됩니다. 그 후 cudaGetDevice(&device_ordinal)을 호출하면 device_ordinal도 0으로 설정되며, 이는 디바이스 2에 해당합니다.

예:

nvidia-smi -L # Get list of GPU UUIDs
CUDA_VISIBLE_DEVICES=0,1
CUDA_VISIBLE_DEVICES=GPU-8932f937-d72c-4106-c12f-20bd9faed9f6
CUDA_VISIBLE_DEVICES=MIG-GPU-8932f937-d72c-4106-c12f-20bd9faed9f6/1/2

5.2.1.2. CUDA_DEVICE_ORDER#

이 환경 변수는 CUDA가 사용 가능한 디바이스를 열거하는 순서를 제어합니다.

가능한 값:

  • FASTEST_FIRST: 간단한 휴리스틱을 사용하여 가장 빠른 디바이스에서 가장 느린 디바이스 순으로 사용 가능한 디바이스가 열거됩니다(기본값).

  • PCI_BUS_ID: 사용 가능한 디바이스가 PCI 버스 ID 오름차순으로 열거됩니다. PCI 버스 ID는 nvidia-smi --query-gpu=name,pci.bus_id로 얻을 수 있습니다.

예:

CUDA_DEVICE_ORDER=FASTEST_FIRST
CUDA_DEVICE_ORDER=PCI_BUS_ID
nvidia-smi --query-gpu=name,pci.bus_id # Get list of PCI bus IDs

5.2.1.3. CUDA_MANAGED_FORCE_DEVICE_ALLOC#

이 환경 변수는 멀티 GPU 시스템에서 통합 메모리가 물리적으로 저장되는 방식을 변경합니다.

가능한 값: 0 또는 0이 아닌 숫자 값.

  • 0이 아닌 값: 드라이버가 물리 저장소로 디바이스 메모리를 사용하도록 강제합니다. 프로세스에서 사용되는 모든 디바이스 중 관리형 메모리를 지원하는 디바이스는 피어 투 피어(peer-to-peer) 호환이어야 합니다. 그렇지 않으면 cudaErrorInvalidDevice이 반환됩니다.

  • 0: 기본 동작.

예:

CUDA_MANAGED_FORCE_DEVICE_ALLOC=0
CUDA_MANAGED_FORCE_DEVICE_ALLOC=1 # force device memory

5.2.2. JIT 컴파일#

5.2.2.1. CUDA_CACHE_DISABLE#

이 환경 변수는 디스크 상 Just-In-Time(JIT) 컴파일 캐시의 동작을 제어합니다. JIT 캐시를 비활성화하면, 실행 중인 아키텍처에 대한 CUBIN 코드가 바이너리에서 발견되지 않는 한 CUDA 애플리케이션이 실행될 때마다 PTX에서 CUBIN으로의 컴파일이 강제됩니다.

JIT 캐시를 비활성화하면 초기 실행 시 애플리케이션의 로드 시간이 증가합니다. 하지만 애플리케이션의 디스크 공간을 줄이거나 드라이버 버전 또는 빌드 플래그에 따른 차이를 진단하는 데 유용할 수 있습니다.

가능한 값:

  • 1: PTX JIT 캐싱을 비활성화합니다.

  • 0: PTX JIT 캐싱을 활성화합니다(기본값).

예:

CUDA_CACHE_DISABLE=1 # disables caching
CUDA_CACHE_DISABLE=0 # enables caching

5.2.2.2. CUDA_CACHE_PATH#

이 환경 변수는 Just-In-Time(JIT) 컴파일 캐시를 위한 디렉터리 경로를 지정합니다.

가능한 값: 캐시 디렉터리의 절대 경로(적절한 접근 권한 포함). 기본값은 다음과 같습니다:

  • Windows: %APPDATA%\NVIDIA\ComputeCache

  • Linux: ~/.nv/ComputeCache

예:

CUDA_CACHE_PATH=~/tmp

5.2.2.3. CUDA_CACHE_MAXSIZE#

이 환경 변수는 Just-In-Time(JIT) 컴파일 캐시 크기를 바이트 단위로 지정합니다. 이 크기를 초과하는 바이너리는 캐시되지 않습니다. 필요 시 더 새로운 바이너리를 위한 공간을 확보하기 위해 오래된 바이너리가 캐시에서 제거됩니다.

가능한 값: 바이트 수. 기본값은 다음과 같습니다:

  • 데스크톱/서버 플랫폼: 1073741824 (1 GiB)

  • 임베디드 플랫폼: 268435456 (256 MiB)

4294967296 (4 GiB)이 최대 크기입니다.

예:

CUDA_CACHE_MAXSIZE=268435456 # 256 MiB

5.2.2.4. CUDA_FORCE_PTX_JIT and CUDA_FORCE_JIT#

이 환경 변수는 CUDA 드라이버가 애플리케이션에 내장된 모든 CUBIN을 무시하고, 대신 내장된 PTX 코드에 대해 Just-In-Time(JIT) 컴파일을 수행하도록 지시합니다.

JIT 컴파일을 강제하면 초기 실행 시 애플리케이션의 로드 시간이 증가합니다. 하지만 애플리케이션에 PTX 코드가 내장되어 있는지, 그리고 해당 Just-In-Time 컴파일이 정상적으로 동작하는지를 검증하는 데 사용할 수 있습니다. 이는 향후 아키텍처에 대한 전방 호환성을 보장합니다.

CUDA_FORCE_PTX_JIT는 CUDA_FORCE_JIT를 재정의합니다.

가능한 값:

  • 1: PTX JIT 컴파일을 강제합니다.

  • 0: 기본 동작.

예:

CUDA_FORCE_PTX_JIT=1

5.2.2.5. CUDA_DISABLE_PTX_JIT and CUDA_DISABLE_JIT#

이 환경 변수는 내장된 PTX 코드의 Just-In-Time(JIT) 컴파일을 비활성화하고, 애플리케이션에 내장된 호환 CUBIN을 사용합니다.

커널에 내장 바이너리 코드가 없거나 내장된 바이너리가 호환되지 않는 아키텍처용으로 컴파일된 경우, 커널 로드에 실패합니다. 이 환경 변수는 애플리케이션이 각 커널에 대해 호환 CUBIN 코드를 생성했는지 검증하는 데 사용할 수 있습니다. 자세한 내용은 바이너리 호환성 섹션을 참조하십시오.

CUDA_DISABLE_PTX_JIT는 CUDA_DISABLE_JIT를 재정의합니다.

가능한 값:

  • 1: PTX JIT 컴파일을 비활성화합니다.

  • 0: 기본 동작.

예:

CUDA_DISABLE_PTX_JIT=1

5.2.2.6. CUDA_FORCE_PRELOAD_LIBRARIES#

이 환경 변수는 NVVM 및 Just-In-Time (JIT) 컴파일에 필요한 라이브러리의 사전 로딩에 영향을 줍니다.

가능한 값:

  • 1: 이는 초기화 중에 NVVM 및 Just-In-Time (JIT) 컴파일에 필요한 라이브러리를 드라이버가 사전 로딩하도록 강제합니다. 이는 메모리 사용량과 CUDA 드라이버 초기화에 필요한 시간을 증가시킵니다. 이 환경 변수를 설정하는 것은 여러 스레드가 관련된 특정 데드락 상황을 피하기 위해 필요합니다.

  • 0: 기본 동작.

예:

CUDA_FORCE_PRELOAD_LIBRARIES=1

5.2.3. 실행#

5.2.3.1. CUDA_LAUNCH_BLOCKING#

이 환경 변수는 비동기 커널 실행을 비활성화할지 또는 활성화할지를 지정합니다.

비동기 실행을 비활성화하면 실행은 더 느려지지만 디버깅에 유용합니다. 이는 CPU의 관점에서 GPU 작업이 동기적으로 실행되도록 강제합니다. 이를 통해 CUDA API 오류를 실행의 나중 시점이 아니라, 이를 유발한 정확한 API 호출에서 관찰할 수 있습니다. 동기 실행은 디버깅 목적에 유용합니다.

가능한 값:

  • 1: 비동기 실행을 비활성화합니다.

  • 0: 비동기 실행(기본값).

예:

CUDA_LAUNCH_BLOCKING=1

5.2.3.2. CUDA_DEVICE_MAX_CONNECTIONS#

이 환경 변수는 동시 컴퓨트 및 복사 엔진 연결(작업 큐)의 수를 제어하며, 둘 다 지정된 값으로 설정합니다. 서로 독립적인 GPU 작업, 즉 서로 다른 CUDA 스트림에서 실행된 커널 또는 복사 작업이 동일한 작업 큐에 매핑되면 동일한 기본 리소스가 사용되므로 잘못된 종속성이 생성될 수 있으며, 이로 인해 GPU 작업이 직렬화될 수 있습니다. 이러한 잘못된 종속성의 발생 확률을 줄이기 위해, 이 환경 변수가 제어하는 작업 큐 개수는 컨텍스트당 활성 CUDA 스트림 수보다 크거나 같도록 하는 것이 권장됩니다.

이 환경 변수를 설정하면 CUDA_DEVICE_MAX_COPY_CONNECTIONS 환경 변수를 통해 명시적으로 설정되지 않는 한, 복사 연결의 수도 수정됩니다.

가능한 값: 1에서 32개 연결, 기본값은 8입니다(MPS 없음 가정).

예:

CUDA_DEVICE_MAX_CONNECTIONS=16

5.2.3.3. CUDA_DEVICE_MAX_COPY_CONNECTIONS#

이 환경 변수는 복사 작업에 관련된 동시 복사 연결(작업 큐)의 수를 제어합니다. 이는 컴퓨트 성능 8.0 이상인 디바이스에만 영향을 미칩니다.

CUDA_DEVICE_MAX_COPY_CONNECTIONS는 둘 다 설정된 경우, CUDA_DEVICE_MAX_CONNECTIONS를 통해 설정된 복사 연결 값보다 우선합니다.

가능한 값: 1부터 32개 연결까지이며, 기본값은 8입니다(Multi-Process Service(MPS)가 없다고 가정).

예:

CUDA_DEVICE_MAX_COPY_CONNECTIONS=16

5.2.3.4. CUDA_SCALE_LAUNCH_QUEUES#

이 환경 변수는 작업(명령 버퍼)을 실행하기 위해 사용할 수 있는 큐의 크기에 대한 스케일링 계수, 즉 디바이스에서 엔큐할 수 있는 대기 중인 커널 또는 호스트/디바이스 복사 작업의 총 수를 지정합니다.

가능한 값: 0.25x, 0.5x, 2x, 4x

  • 0.25x, 0.5x, 2x 또는 4x 이외의 모든 값은 1x로 해석됩니다.

예:

CUDA_SCALE_LAUNCH_QUEUES=2x

5.2.3.5. CUDA_GRAPHS_USE_NODE_PRIORITY#

이 환경 변수는 그래프가 실행되는 스트림으로부터 상속받는 스트림 우선순위에 상대적인 CUDA 그래프의 실행 우선순위를 제어합니다.

CUDA_GRAPHS_USE_NODE_PRIORITY는 그래프 인스턴스화 시 cudaGraphInstantiateFlagUseNodePriority 플래그를 재정의합니다.

가능한 값:

  • 0: 그래프가 실행되는 스트림의 우선순위를 상속합니다(기본값).

  • 1: 노드별 실행 우선순위를 준수합니다. CUDA 런타임은 노드 수준 우선순위를 실행 준비가 된 그래프 노드에 대한 스케줄링 힌트로 취급합니다.

예:

CUDA_GRAPHS_USE_NODE_PRIORITY=1

5.2.3.6. CUDA_DEVICE_WAITS_ON_EXCEPTION#

이 환경 변수는 예외(오류)가 발생했을 때 CUDA 애플리케이션의 동작을 제어합니다.

활성화되면, 디바이스 측 예외가 발생했을 때 CUDA 애플리케이션이 중단하고 대기하여, 프로세스가 종료되거나 계속되기 전에 cuda-gdb와 같은 디버거를 연결해 라이브 GPU 상태를 검사할 수 있습니다.

가능한 값:

  • 0: 기본 동작.

  • 1: 디바이스 예외가 발생하면 중단합니다.

예:

CUDA_DEVICE_WAITS_ON_EXCEPTION=1

5.2.3.7. CUDA_DEVICE_DEFAULT_PERSISTING_L2_CACHE_PERCENTAGE_LIMIT#

이 환경 변수는 지속 접근을 위해 예약되는 GPU의 L2 캐시 기본 “할당” 부분을 L2 크기의 백분율로 표현하여 제어합니다.

이는 지속 L2 캐시를 지원하는 GPU, 특히 컴퓨트 성능 8.0 이상인 디바이스에서 CUDA Multi-Process Service (MPS)를 사용할 때 관련이 있습니다. 이 환경 변수는 CUDA MPS Control Daemon을 시작하기 전에, 즉 nvidia-cuda-mps-control -d 명령을 실행하기 전에 설정해야 합니다.

가능한 값: 0에서 100 사이의 백분율 값이며, 기본값은 0입니다.

예:

CUDA_DEVICE_DEFAULT_PERSISTING_L2_CACHE_PERCENTAGE_LIMIT=25 # 25%

5.2.3.8. CUDA_DISABLE_PERF_BOOST#

Linux 호스트에서 이 환경 변수를 1로 설정하면 디바이스 성능 상태의 부스팅을 방지하며, 대신 다양한 휴리스틱에 따라 pstate가 암묵적으로 선택될 수 있습니다. 이 옵션은 전력 소비를 줄이는 데 잠재적으로 사용될 수 있지만, 동적 성능 상태 선택으로 인해 특정 시나리오에서는 지연 시간이 더 길어질 수 있습니다.

예:

CUDA_DISABLE_PERF_BOOST=1 # perf boost disabled, Linux only.
CUDA_DISABLE_PERF_BOOST=0 # default behavior

5.2.3.9. CUDA_AUTO_BOOST [[deprecated]]#

이 환경 변수는 GPU 클록 “자동 부스트(auto boost)” 동작, 즉 동적 클록 부스팅에 영향을 줍니다. 이는 nvidia-smi 도구의 “자동 부스트(auto boost)” 옵션, 즉 nvidia-smi --auto-boost-default=0를 재정의합니다.

참고

이 환경 변수는 사용이 중단(deprecated)되었습니다. 다음을 사용할 것을 강력히 권장합니다 nvidia-smi --applications-clocks=<memory,graphics> 또는 NVML API 대신 CUDA_AUTO_BOOST 환경 변수.

5.2.4. 모듈 로딩#

5.2.4.1. CUDA_MODULE_LOADING#

이 환경 변수는 CUDA 런타임이 모듈을 로드하는 방식, 특히 디바이스 코드를 초기화하는 방식에 영향을 줍니다.

가능한 값:

  • DEFAULT: 기본 동작이며, LAZY와 동일합니다.

  • LAZY: 특정 커널의 로딩은 CUDA 함수 핸들인 CUfunc이(가) cuModuleGetFunction() 또는 cuKernelGetFunction() API 호출을 사용해 추출될 때까지 지연됩니다. 이 경우 CUBIN의 데이터는 CUBIN의 첫 번째 커널이 로드될 때 또는 CUBIN의 첫 번째 변수가 액세스될 때 로드됩니다.

    • 드라이버는 커널에 대한 첫 호출에서 필요한 코드를 로드하며, 이후 호출에는 추가 오버헤드가 발생하지 않습니다. 이는 시작 시간을 줄이고 GPU 메모리 점유량을 줄입니다.

  • EAGER: 프로그램 초기화 시 CUDA 모듈과 커널을 완전히 로드합니다. CUBIN, FATBIN 또는 PTX 파일의 모든 커널과 데이터는 해당 cuModuleLoad* 및 cuLibraryLoad* 드라이버 API 호출 시 완전히 로드됩니다.

    • 시작 시간과 GPU 메모리 점유량이 더 큽니다. 커널 실행 오버헤드는 예측 가능합니다.

예:

CUDA_MODULE_LOADING=EAGER
CUDA_MODULE_LOADING=LAZY

5.2.4.2. CUDA_MODULE_DATA_LOADING#

이 환경 변수는 CUDA 런타임이 모듈에 연결된 데이터를 로드하는 방식에 영향을 줍니다.

이는 CUDA_MODULE_LOADING의 커널 중심 설정을 보완하는 설정입니다. 이 환경 변수는 커널의 LAZY 또는 EAGER 로딩에 영향을 주지 않습니다. 이 환경 변수가 설정되지 않은 경우 데이터 로딩 동작은 CUDA_MODULE_LOADING에서 상속됩니다.

가능한 값:

  • DEFAULT: 기본 동작으로, LAZY와 동일합니다.

  • LAZY: 모듈 데이터의 로딩은 CUDA 함수 핸들인 CUfunc가 필요해질 때까지 지연됩니다. 이 경우 CUBIN의 데이터는 CUBIN에서 첫 번째 커널이 로드될 때 또는 CUBIN에서 첫 번째 변수에 접근할 때 로드됩니다.

    • 지연 데이터 로드는 컨텍스트 동기화가 필요할 수 있으며, 이는 동시 실행을 느리게 할 수 있습니다.

  • EAGER: CUBIN, FATBIN 또는 PTX 파일의 모든 데이터가 해당 cuModuleLoad* 및 cuLibraryLoad* API 호출 시 완전히 로드됩니다.

예:

CUDA_MODULE_DATA_LOADING=EAGER

5.2.4.3. CUDA_BINARY_LOADER_THREAD_COUNT#

디바이스 바이너리를 로드할 때 사용할 CPU 스레드 수를 설정합니다. 0으로 설정하면 사용되는 CPU 스레드 수는 기본값인 1로 설정됩니다.

가능한 값:

  • 사용할 스레드의 정수 개수. 기본값은 0이며, 이 경우 1개 스레드를 사용합니다.

예:

CUDA_BINARY_LOADER_THREAD_COUNT=4

5.2.5. CUDA 오류 로그 관리#

5.2.5.1. CUDA_LOG_FILE#

이 환경 변수는 오류를 반환한 지원되는 CUDA API 호출에 대해, 설명적인 오류 로그 메시지가 발생하는 즉시 출력될 위치를 지정합니다.

예를 들어, kernel<<<1, dim3(1,1,128)>>>(...)과 같은 잘못된 그리드 구성으로 커널을 실행하려고 하면, 해당 커널은 실행에 실패하고 cudaGetLastError()는 일반적인 invalid configuration argument 오류를 반환합니다.
CUDA_LOG_FILE 환경 변수가 설정되어 있으면, 사용자는 로그에서 다음과 같은 설명적인 오류 메시지인 [CUDA][E] Block Dimensions (1,1,128) include one or more values that exceed the device limit of (1024,1024,64)를 확인할 수 있으며, 지정된 블록의 z-차원이 잘못되었음을 쉽게 판단할 수 있습니다. 자세한 내용은 오류 로그 관리를 참조하십시오.

가능한 값: stdout, stderr, 또는 유효한 파일 경로(적절한 접근 권한 포함)

예:

CUDA_LOG_FILE=stdout
CUDA_LOG_FILE=/tmp/dbg_cuda_log
