2.5. NVCC: NVIDIA CUDA 컴파일러

NVIDIA CUDA 컴파일러 nvcc는 CUDA C/C++뿐만 아니라 PTX 코드도 컴파일하기 위한 NVIDIA의 도구체인입니다. 이 도구체인은 CUDA Toolkit의 일부이며, 컴파일러, 링커, 그리고 PTX 및 Cubin 어셈블러를 포함한 여러 도구로 구성됩니다. 최상위 nvcc 도구는 컴파일 프로세스를 조정하여, 컴파일의 각 단계에 대해 적절한 도구를 호출합니다.

nvcc는 CUDA 런타임 컴파일러 nvrtc에 의해 구동되는 온라인 또는 Just-in-Time(JIT) 컴파일과 대조적으로, CUDA 코드의 오프라인 컴파일을 구동합니다.

이 장에서는 애플리케이션 빌드에 필요한 nvcc의 가장 일반적인 사용법과 세부 사항을 다룹니다. nvcc에 대한 전체 내용은 nvcc 문서에서 확인할 수 있습니다.

2.5.1. CUDA 소스 파일 및 헤더#

로 컴파일된 소스 파일 nvcc 에는 CPU에서 실행되는 호스트 코드와 GPU에서 실행되는 디바이스 코드가 결합되어 있을 수 있습니다. nvcc 일반적인 C/C++ 소스 파일 확장자를 허용합니다 .c, .cpp, .cc, .cxx 호스트 전용 코드 및 .cu 디바이스 코드를 포함하거나 호스트 및 디바이스 코드가 혼합된 코드를 포함하는 파일에 사용합니다. 디바이스 코드를 포함하는 헤더는 일반적으로 .cuh 호스트 전용 코드 헤더와 구별하기 위한 확장자 .h, .hpp, .hh, .hxx, 등.

2.5.2. NVCC 컴파일 워크플로#

초기 단계에서, nvcc는 디바이스 코드를 호스트 코드에서 분리하고, 각각의 컴파일을 GPU 컴파일러와 호스트 컴파일러로 디스패치합니다.

호스트 코드를 컴파일하려면, CUDA 컴파일러 nvcc에는 호환되는 호스트 컴파일러를 사용할 수 있어야 합니다. CUDA Toolkit은 Linux 및 Windows 플랫폼에 대한 호스트 컴파일러 지원 정책을 정의합니다.
호스트 코드만 포함하는 파일은 nvcc 또는 호스트 컴파일러를 직접 사용하여 빌드할 수 있습니다. 결과 오브젝트 파일은 링크 시점에 GPU 코드를 포함하는 nvcc의 오브젝트 파일과 결합할 수 있습니다.
GPU 컴파일러는 C/C++ 디바이스 코드를 PTX 어셈블리 코드로 컴파일합니다. GPU 컴파일러는 컴파일 명령줄에 지정된 각 가상 머신 명령어 집합 아키텍처(예: compute_90)에 대해 실행됩니다.
그런 다음 개별 PTX 코드는 ptxas 도구로 전달되며, 이 도구는 대상 하드웨어 ISA에 대한 Cubin을 생성합니다. 하드웨어 ISA는 해당 SM version으로 식별됩니다.
단일 바이너리가 여러 가상 ISA와 대상 하드웨어 ISA를 지원할 수 있도록, 애플리케이션 또는 라이브러리 내에서 단일 바이너리 Fatbin 컨테이너에 여러 PTX 및 Cubin 대상을 임베드할 수 있습니다.

위에서 설명한 도구들의 호출과 조정은 nvcc에 의해 자동으로 수행됩니다. -v 옵션을 사용하면 전체 컴파일 워크플로와 도구 호출을 표시할 수 있습니다. -keep 옵션을 사용하면 컴파일 중 생성되는 중간 파일을 현재 디렉터리에 저장하거나, 대신 --keep-dir로 지정한 디렉터리에 저장할 수 있습니다.

다음 예는 CUDA 소스 파일 example.cu에 대한 컴파일 워크플로를 보여줍니다:

// ----- example.cu -----
#include <stdio.h>
__global__ void kernel() {
    printf("Hello from kernel\n");
}

void kernel_launcher() {
    kernel<<<1, 1>>>();
    cudaDeviceSynchronize();
}

int main() {
    kernel_launcher();
    return 0;
}

2.5.3. NVCC 기본 사용법#

nvcc로 CUDA 소스 파일을 컴파일하는 기본 명령은 다음과 같습니다:

nvcc <source_file>.cu -o <output_file>

nvcc는 인클루드 디렉터리 -I <path> 및 라이브러리 경로 -L <path> 지정, 다른 라이브러리와의 링크 -l<library>, 매크로 정의 -D<macro>=<value>에 사용되는 일반적인 컴파일러 플래그를 허용합니다.

nvcc example.cu -I path_to_include/ -L path_to_library/ -lcublas -o <output_file>

2.5.3.1. NVCC PTX 및 Cubin 생성#

기본적으로, nvcc는 호환성을 극대화하기 위해 CUDA Toolkit에서 지원하는 가장 이른 GPU 아키텍처(가장 낮은 compute_XY 및 sm_XY 버전)에 대해 PTX와 Cubin을 생성합니다.

  • -arch 옵션은 특정 GPU 아키텍처에 대해 PTX 및 Cubin을 생성하는 데 사용할 수 있습니다.

  • -gencode 옵션은 여러 GPU 아키텍처에 대해 PTX 및 Cubin을 생성하는 데 사용할 수 있습니다.

지원되는 가상 및 실제 GPU 아키텍처의 전체 목록은 다음을 전달하여 얻을 수 있습니다. --list-gpu-code 및 --list-gpu-arch 각각의 플래그를 사용하거나, 다음을 참조하여 가상 아키텍처 목록 및 GPU 아키텍처 목록 내의 섹션 nvcc 문서.

nvcc --list-gpu-code # list all supported real GPU architectures
nvcc --list-gpu-arch # list all supported virtual GPU architectures

nvcc example.cu -arch=compute_<XY> # e.g. -arch=compute_80 for NVIDIA Ampere GPUs and later
                                   # PTX-only, GPU forward compatible

nvcc example.cu -arch=sm_<XY>      # e.g. -arch=sm_80 for NVIDIA Ampere GPUs and later
                                   # PTX and Cubin, GPU forward compatible

nvcc example.cu -arch=native       # automatically detects and generates Cubin for the current GPU
                                   # no PTX, no GPU forward compatibility

nvcc example.cu -arch=all          # generate Cubin for all supported GPU architectures
                                   # also includes the latest PTX for GPU forward compatibility

nvcc example.cu -arch=all-major    # generate Cubin for all major supported GPU architectures, e.g. sm_80, sm_90,
                                   # also includes the latest PTX for GPU forward compatibility

더 고급 사용법에서는 PTX 및 Cubin 대상을 개별적으로 지정할 수 있습니다:

# generate PTX for virtual architecture compute_80 and compile it to Cubin for real architecture sm_86, keep compute_80 PTX
nvcc example.cu -arch=compute_80 -gpu-code=sm_86,compute_80 # (PTX and Cubin)

# generate PTX for virtual architecture compute_80 and compile it to Cubin for real architecture sm_86, sm_89
nvcc example.cu -arch=compute_80 -gpu-code=sm_86,sm_89    # (no PTX)
nvcc example.cu -gencode=arch=compute_80,code=sm_86,sm_89 # same as above

# (1) generate PTX for virtual architecture compute_80 and compile it to Cubin for real architecture sm_86, sm_89
# (2) generate PTX for virtual architecture compute_90 and compile it to Cubin for real architecture sm_90
nvcc example.cu -gencode=arch=compute_80,code=sm_86,sm_89 -gencode=arch=compute_90,code=sm_90

GPU 코드 생성을 제어하기 위한 nvcc 명령줄 옵션의 전체 참조는 nvcc 문서에서 확인할 수 있습니다.

2.5.3.2. 호스트 코드 컴파일 참고 사항#

디바이스 코드나 심볼을 포함하지 않는 컴파일 단위(즉, 소스 파일과 그 헤더)는 호스트 컴파일러로 직접 컴파일할 수 있습니다. 어떤 컴파일 단위든 CUDA 런타임 API 함수를 사용한다면, 애플리케이션은 CUDA 런타임 라이브러리와 링크되어야 합니다. CUDA 런타임은 정적 라이브러리와 공유 라이브러리 형태로 모두 제공되며, libcudart_static 그리고 libcudart, 각각. 기본적으로, nvcc 정적 CUDA 런타임 라이브러리와 링크합니다. CUDA 런타임의 공유 라이브러리 버전을 사용하려면 다음 플래그를 전달하십시오 --cudart=shared 로 nvcc 컴파일 또는 링크 명령에서.

nvcc 호스트 함수에 사용되는 호스트 컴파일러를 다음을 통해 지정할 수 있습니다 -ccbin <compiler> 인수. 환경 변수 NVCC_CCBIN 도 정의하여 다음에서 사용하는 호스트 컴파일러를 지정할 수 있습니다 nvcc. -Xcompiler 에 대한 인수 nvcc 호스트 컴파일러에 인수를 그대로 전달합니다. 예를 들어, 아래 예에서는, -O3 인수가 다음에 의해 호스트 컴파일러에 전달됩니다 nvcc.

nvcc example.cu -ccbin=clang++

export NVCC_CCBIN='gcc'
nvcc example.cu -Xcompiler=-O3

2.5.3.3. GPU 코드의 분리 컴파일#

nvcc의 기본값은 전체 프로그램 컴파일이며, 이는 GPU 코드와 심볼이 이를 사용하는 컴파일 단위에 모두 존재할 것으로 예상합니다. CUDA 디바이스 함수는 다른 컴파일 단위에 정의된 디바이스 함수를 호출하거나 디바이스 변수에 액세스할 수 있지만, 서로 다른 컴파일 단위의 디바이스 코드를 링크할 수 있도록 하려면 -rdc=true 또는 그 별칭인 -dc 플래그를 nvcc 명령줄에 지정해야 합니다. 서로 다른 컴파일 단위의 디바이스 코드와 심볼을 링크하는 기능을 분리 컴파일이라고 합니다.

분리 컴파일은 더 유연한 코드 구성을 가능하게 하고, 컴파일 시간을 개선할 수 있으며, 더 작은 바이너리로 이어질 수 있습니다. 분리 컴파일은 전체 프로그램 컴파일에 비해 빌드 시점의 복잡성을 어느 정도 수반할 수 있습니다. 성능은 디바이스 코드 링크 사용에 의해 영향을 받을 수 있으며, 이것이 기본적으로 사용되지 않는 이유입니다. 링크 타임 최적화(LTO)는 분리 컴파일의 성능 오버헤드를 줄이는 데 도움이 될 수 있습니다.

분리 컴파일에는 다음 조건이 필요합니다:

  • 한 컴파일 단위에 정의된 비-const 디바이스 변수는 다른 컴파일 단위에서 extern 키워드로 참조되어야 합니다.

  • 모든 const 디바이스 변수는 extern 키워드로 정의되고 참조되어야 합니다.

  • 모든 CUDA 소스 파일 .cu은 -dc 또는 -rdc=true 플래그로 컴파일되어야 합니다.

호스트 및 디바이스 함수는 기본적으로 외부 링키지를 가지며 extern 키워드가 필요하지 않습니다. CUDA 13부터 __global__ 함수와 __managed__/__device__/__constant__ 변수는 기본적으로 내부 링키지를 가진다는 점에 유의하십시오.

다음 예제에서 definition.cu는 변수와 함수를 정의하고, example.cu는 이를 참조합니다. 두 파일은 각각 별도로 컴파일된 다음 최종 바이너리에 링크됩니다.

// ----- definition.cu -----
extern __device__ int device_variable = 5;
__device__        int device_function() { return 10; }

// ----- example.cu -----
extern __device__ int  device_variable;
__device__        int device_function();

__global__ void kernel(int* ptr) {
    device_variable = 0;
    *ptr            = device_function();
}

nvcc -dc definition.cu -o definition.o
nvcc -dc example.cu    -o example.o
nvcc definition.o example.o -o program

2.5.4. 일반적인 컴파일러 옵션#

이 섹션에서는 언어 기능, 최적화, 디버깅, 프로파일링 및 빌드 측면을 다루면서, nvcc와 함께 사용할 수 있는 가장 관련성 높은 컴파일러 옵션을 소개합니다. 모든 옵션에 대한 전체 설명은 nvcc 문서에서 확인할 수 있습니다.

2.5.4.1. 언어 기능#

nvcc는 C++03부터 C++20까지의 C++ 핵심 언어 기능을 지원합니다. -std 플래그를 사용하여 사용할 언어 표준을 지정할 수 있습니다:

  • --std={c++03|c++11|c++14|c++17|c++20}

또한, nvcc는 다음 언어 확장을 지원합니다:

  • -restrict: 모든 커널 포인터 매개변수가 restrict 포인터임을 단언합니다.

  • -extended-lambda: 람다 선언에서 __host__, __device__ 애너테이션을 허용합니다.

  • -expt-relaxed-constexpr: (실험적 플래그) 호스트 코드가 __device__ constexpr 함수를 호출하고, 디바이스 코드가 __host__ constexpr 함수를 호출할 수 있도록 허용합니다.

이러한 기능에 대한 자세한 내용은 extended lambda 및 constexpr 섹션에서 확인할 수 있습니다.

2.5.4.2. 디버깅 옵션#

nvcc는 디버그 정보를 생성하기 위해 다음 옵션을 지원합니다:

  • -g: 호스트 코드에 대한 디버그 정보를 생성합니다. gdb/lldb 및 유사한 도구는 호스트 코드 디버깅을 위해 이러한 정보에 의존합니다.

  • -G: 디바이스 코드에 대한 디버그 정보를 생성합니다. cuda-gdb는 디바이스 코드 디버깅을 위해 이러한 정보에 의존합니다. 또한 이 플래그는 __CUDACC_DEBUG__ 매크로를 정의합니다.

  • -lineinfo: 디바이스 코드에 대한 줄 번호 정보를 생성합니다. 이 옵션은 실행 성능에 영향을 주지 않으며, 커널 실행을 추적하기 위해 compute-sanitizer 도구와 함께 사용할 때 유용합니다.

nvcc는 기본적으로 GPU 코드에 대해 가장 높은 최적화 수준인 -O3을 사용합니다. 디버그 플래그인 -G는 일부 컴파일러 최적화를 방지하므로, 디버그 코드는 비디버그 코드보다 성능이 낮을 것으로 예상됩니다. 또한 런타임 단언을 비활성화하기 위해 -DNDEBUG 플래그를 정의할 수 있는데, 이러한 단언 역시 실행을 느리게 만들 수 있기 때문입니다.

2.5.4.3. 최적화 옵션#

nvcc는 성능 최적화를 위한 많은 옵션을 제공합니다. 이 섹션은 개발자가 유용하다고 생각할 수 있는 사용 가능한 일부 옵션에 대한 간단한 개요를 제공하고, 추가 정보에 대한 링크도 제공하는 것을 목표로 합니다. 전체 내용은 nvcc 문서에서 확인할 수 있습니다.

  • -Xptxas PTX 어셈블러 도구에 인수를 전달합니다 ptxas. The nvcc 문서는 유용한 인수 목록 에 대한 ptxas. 예를 들어, -Xptxas=-maxrregcount=N 스레드당 사용할 최대 레지스터 수를 지정합니다.

  • -extra-device-vectorization: 더 공격적인 디바이스 코드 벡터화를 활성화합니다.

  • 부동소수점 동작을 세밀하게 제어할 수 있게 해주는 추가 플래그는 부동소수점 연산 섹션과 nvcc 문서에서 다룹니다.

다음 플래그는 더 고급 코드 최적화에서 유용할 수 있는 컴파일러의 출력 정보를 가져옵니다:

  • -res-usage: 컴파일 후 리소스 사용량 보고서를 출력합니다. 여기에는 각 커널 함수에 대해 할당된 레지스터, 공유 메모리, 상수 메모리, 로컬 메모리의 개수가 포함됩니다.

  • -opt-info=inline: 인라인된 함수에 대한 정보를 출력합니다.

  • -Xptxas=-warn-lmem-usage: 로컬 메모리가 사용되는 경우 경고합니다.

  • -Xptxas=-warn-spills: 레지스터가 로컬 메모리로 스필(spill)되는 경우 경고합니다.

2.5.4.4. 링크 타임 최적화(LTO)#

분리 컴파일은 파일 간 최적화 기회가 제한되기 때문에 전체 프로그램 컴파일보다 성능이 낮을 수 있습니다. 링크 타임 최적화(LTO)는 컴파일 시간이 증가하는 비용을 치르지만, 링크 시점에 각각 별도로 컴파일된 파일 전반에 걸쳐 최적화를 수행함으로써 이를 해결합니다. LTO는 분리 컴파일의 유연성을 유지하면서도 전체 프로그램 컴파일의 성능을 상당 부분 회복할 수 있습니다.

nvcc를 사용하려면 LTO를 활성화하기 위해 -dlto 플래그 또는 lto_<SM version> 링크 타임 최적화 대상이 필요합니다:

nvcc -dc -dlto -arch=sm_100 definition.cu -o definition.o
nvcc -dc -dlto -arch=sm_100 example.cu    -o example.o
nvcc -dlto definition.o example.o -o program

nvcc -dc -arch=lto_100 definition.cu -o definition.o
nvcc -dc -arch=lto_100 example.cu    -o example.o
nvcc -dlto definition.o example.o -o program

2.5.4.5. 프로파일링 옵션#

컴파일 과정에서 추가 플래그가 필요 없이 Nsight Compute 및 Nsight Systems 도구를 사용하여 CUDA 애플리케이션을 직접 프로파일링할 수 있습니다. 그러나 nvcc로 생성할 수 있는 추가 정보는 소스 파일을 생성된 코드와 연관 지어 프로파일링을 돕는 데 유용할 수 있습니다:

  • -lineinfo: 디바이스 코드에 대한 라인 번호 정보를 생성합니다. 이를 통해 프로파일링 도구에서 소스 코드를 볼 수 있습니다. 프로파일링 도구는 코드가 컴파일된 동일한 위치에서 원본 소스 코드를 사용할 수 있어야 합니다.

  • -src-in-ptx: PTX에 원본 소스 코드를 유지하여, 위에서 언급한 -lineinfo의 제한을 피합니다. -lineinfo이 필요합니다.

2.5.4.6. Fatbin 압축#

nvcc는 기본적으로 애플리케이션 또는 라이브러리 바이너리에 저장된 fatbins를 압축합니다. Fatbin 압축은 다음 옵션을 사용하여 제어할 수 있습니다:

  • -no-compress: fatbin 압축을 비활성화합니다.

  • --compress-mode={default|size|speed|balance|none}: 압축 모드를 설정합니다. speed는 빠른 압축 해제 시간에 중점을 두는 반면, size는 fatbin 크기를 줄이는 것을 목표로 합니다. balance는 속도와 크기 사이의 절충안을 제공합니다. 기본 모드는 speed입니다. none는 압축을 비활성화합니다.

2.5.4.7. 컴파일러 성능 제어#

nvcc는 컴파일 프로세스 자체를 분석하고 가속하기 위한 옵션을 제공합니다:

  • -t <N>: 여러 GPU 아키텍처에 대해 단일 컴파일 단위의 컴파일을 병렬화하는 데 사용되는 CPU 스레드 수.

  • -split-compile <N>: 최적화 단계를 병렬화하는 데 사용되는 CPU 스레드 수.

  • -split-compile-extended <N>: 분할 컴파일의 더 공격적인 형태입니다. 링크 타임 최적화가 필요합니다.

  • -Ofc <N>: 디바이스 코드 컴파일 속도 수준.

  • -time <filename>: 각 컴파일 단계에 소요된 시간을 포함한 쉼표로 구분된 값(CSV) 표를 생성합니다.

  • -fdevice-time-trace: 디바이스 코드 컴파일을 위한 시간 트레이스를 생성합니다.
